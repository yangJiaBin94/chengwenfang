# 工作流管理模块设计与版本迭代方案

> 文档版本：1.0  
> 编制日期：2026-08-04  
> 适用项目：AI 内容生产成文坊  
> 基线代码：`ee7a2c1 feat: complete course generation Chengwenfang workflow`
>
> **现行产品变更（2026-10）**：已移除工作流「测试运行」Tab、干运行（`dry-runs`）、沙箱运行（`sandbox-runs`）及 `run_mode` / `is_test` 列。验证依赖正式生成与自动化 IT；下文凡涉及沙箱/干运行的规划条目视为历史方案，不再作为产品能力。

## 1. 文档目的

本文定义工作流管理模块的产品边界、信息架构、领域模型、运行机制、接口、数据迁移、风险控制和分阶段交付计划。目标不是建设一个可以执行任意代码的通用低代码平台，而是把当前已经验证的课程生成工作流变成**可查看、可配置、可验证、可发布、可追溯、可恢复**的受控业务能力。

本文是后续需求评审、交互设计、数据库迁移、接口开发、前端开发、测试和验收的共同依据。

## 2. 建设目标与非目标

### 2.1 建设目标

1. 将当前散落在代码、数据库 Skill 配置和执行轨迹中的流程信息统一管理。
2. 明确区分流程定义、编辑草稿、已发布版本和实际运行记录。
3. 让每次生成都绑定唯一且不可变的工作流版本、节点配置和 Skill 快照。
4. 支持在不修改代码的情况下调整受控参数，包括节点启停、超时、重试、失败策略及 Skill 绑定顺序。
5. 在发布前完成结构、数据契约、Skill、资源和安全校验。
6. （已取消）隔离测试运行 / 沙箱；改由正式生成与自动化测试验证，避免双路径维护成本。
7. 让失败能够定位到具体节点、具体尝试和具体上游调用，并支持从安全检查点恢复。
8. 建立可量化的成功率、耗时、重试率、模型消耗和版本质量指标。

### 2.2 非目标

1. 首期不支持用户在页面中编写或执行 Python、JavaScript、Shell 等任意代码。
2. 不建设面向所有业务的通用 BPM、审批流或组织权限平台。
3. 不允许直接修改已经发布的工作流版本。
4. 不允许运行中的任务自动切换到新发布版本。
5. 不用工作流配置替代节点内部的专业业务代码、知识准确性规则或事务一致性控制。
6. 首期不支持多人实时协同编辑，也不引入复杂角色审批。

## 3. 当前系统基线

### 3.1 已具备能力

- 课程内容生成由固定代码流程编排。
- 工作流节点能够记录状态、顺序、尝试次数、输入输出摘要和错误信息。
- 节点中间产物以不可变 Artifact 保存，可用于恢复和审计。
- 支持识别异常中断的运行节点，并从已成功节点继续。
- 课程原稿和公众号版本可关联生成运行记录。
- Skill 分为系统级和业务场景级；系统级可查看不可编辑。
- 场景级 Skill 可以绑定到具体工作流节点，并按顺序注入 AI 上下文。
- 执行轨迹能够展示父步骤、子步骤、完成状态、失败原因及使用的 Skill。
- 文件投影采用可重试 Outbox，避免数据库提交和 Markdown 写入互相破坏一致性。

### 3.2 当前缺口

| 领域 | 当前情况 | 主要问题 |
|---|---|---|
| 流程定义 | 节点顺序主要由代码确定 | 无独立的可管理流程定义 |
| 配置变更 | Skill 可配置，节点参数不完整 | 变更入口分散，无法整体校验 |
| 版本管理 | 有文章版本与运行关联 | 无工作流草稿、发布版本和差异对比 |
| 发布治理 | 修改代码后部署生效 | 无发布说明、发布校验和回滚机制 |
| 流程测试 | 正式生成 + 自动化 IT | （产品侧不再提供隔离沙箱） |
| 可观测性 | 可查看单次执行轨迹 | 缺少跨运行指标、趋势和失败聚合 |
| 数据契约 | 由代码隐式保证 | 设计器无法展示节点输入输出关系 |

## 4. 总体设计原则

### 4.1 推荐架构

采用三层模型：

1. **节点执行器层**：由代码实现并注册，负责实际业务行为、输入输出校验、幂等和事务边界。
2. **流程定义层**：数据库保存节点实例、连接、参数、Skill 绑定和发布版本。
3. **运行实例层**：每次执行复制已发布版本的完整快照，产生节点运行、模型调用、Artifact 和文章版本关联。

### 4.2 核心约束

- 页面只能选择系统注册的节点类型，不能提交可执行代码。
- 已发布版本不可修改；所谓回滚，是以历史版本为来源创建并发布一个新版本。
- 正式运行只能使用已发布版本；草稿用于编辑与发布前校验。
- 运行开始后锁定版本、节点配置和 Skill 快照，后续配置变化不影响该次运行。
- 节点输出必须符合声明的数据契约，才允许交给下游。
- 跳过、重试和从节点恢复必须经过依赖、幂等与产物有效性检查。
- 对外展示中文业务文案，内部保留稳定的英文 key 作为协议标识。

## 5. 领域模型

### 5.1 工作流定义 Workflow Definition

表示一个长期存在的业务流程，例如“生成课程内容”。保存稳定标识、名称、简介、业务场景、负责人、状态、当前发布版本和默认触发入口。

### 5.2 工作流草稿 Workflow Draft

表示尚未发布的可编辑配置。同一工作流只保留一个活动草稿；每次保存更新草稿修订号，但不产生正式版本。草稿记录基于哪个发布版本创建，以支持三方差异判断。

### 5.3 已发布版本 Published Workflow Version

工作流在某一时刻的完整不可变快照，包括节点、连接、参数、Skill 绑定、数据契约版本、发布说明、发布人和校验报告。正式运行必须绑定该实体。

### 5.4 节点类型 Node Type

由代码注册的执行能力，例如读取课程路线、生成课程原稿、审校、生成公众号版本和生成图片。定义配置 JSON Schema、输入输出契约、是否可禁用、是否支持重试、幂等等级和执行器版本。

### 5.5 节点实例 Workflow Node

节点类型在某个流程版本中的一次配置实例。包含稳定 node key、展示名称、阶段、坐标、超时、重试次数、失败策略、启用状态、配置参数和执行器版本约束。

### 5.6 节点连接 Node Connection

描述上游输出端口与下游输入端口的有向依赖。首期只读现有顺序；可视化设计器阶段才允许受控编辑。连接不只是视觉线条，还承担数据契约匹配和调度依赖。

### 5.7 工作流运行 Workflow Run

一次真实或测试执行。记录工作流版本、触发来源、业务对象、运行模式、状态、当前节点、开始结束时间、快照、费用摘要和最终错误。

### 5.8 节点运行 Node Run

节点的一次尝试。现有 `workflow_node_runs` 继续作为基础，并补充节点实例 ID、配置快照、执行器版本、父节点、重试来源、心跳时间和耗时。

### 5.9 产物 Artifact

节点产生的不可变中间结果，包括定位报告、相邻课程上下文、课程边界、课程原稿、公众号保留清单、审校报告、图片计划、图片文件和正式保存结果。产物通过哈希防止错误复用。

### 5.10 Skill 绑定与快照

- 系统级 Skill：由系统自行判断是否使用，只读、无业务顺序。
- 节点级 Skill：绑定工作流节点，可启停并排序，只在该节点构建 AI 请求时注入。
- 发布时保存 Skill 版本引用；运行时再固化 Skill 内容快照，保证历史可解释。
- Skill 被修改或删除后，不影响历史发布版本和历史运行。

## 6. 信息架构与导航

左侧一级菜单调整为：

1. 总览
2. 课程路线
3. 工作流
4. 设置

“执行轨迹”不作为一级菜单。它仍然从课程生成、文章版本、工作流运行历史等上下文入口进入。

工作流模块内部采用二级页签：

- 工作流概览
- 流程设计
- 版本发布
- 运行记录
- 运行分析

（「测试运行」页签已从产品中移除。）未开放的页签按版本隐藏，不展示不可用空入口。

## 7. 页面与交互设计

### 7.1 工作流列表页

展示名称、简介、场景、当前发布版本、草稿状态、近 7 日成功率、最后发布时间和状态。支持名称搜索、场景筛选和状态筛选。

主要操作：

- 查看工作流
- 编辑草稿
- 查看运行记录
- 克隆为新工作流（后期）

列表不直接放置删除按钮。已有运行记录的工作流只能停用或归档，不能物理删除。

### 7.2 工作流概览页

展示工作流基本信息、当前发布版本、草稿变更提醒、流程缩略图、节点数量、绑定 Skill 数量、最近运行、成功率和常见失败节点。

首屏主要动作只有“查看流程”和“编辑草稿”。发布、回滚等高风险动作放入版本发布页。

### 7.3 工作流设计器

布局采用三栏：

- 左侧：受控节点库和阶段分类。
- 中间：流程画布或首期只读拓扑图。
- 右侧：选中节点的配置面板。

画布能力分阶段开放：缩放、平移、适配视图、节点定位、问题高亮、受控拖拽、受控连线。节点卡片展示名称、类型、Skill 数量和校验状态，不在卡片堆叠全部参数。

### 7.4 节点配置面板

配置分组：

1. 基本信息：展示名称、说明、阶段。
2. 执行策略：超时、最大重试、退避方式、失败策略。
3. 业务参数：根据节点类型 JSON Schema 渲染。
4. Skill：节点级 Skill 选择、启停、排序和内容预览。
5. 输入输出：端口、字段、必填性、来源和契约版本。
6. 高级信息：执行器 key、版本、幂等等级，只读展示。

参数变更只更新草稿。离开未保存页面时使用项目自研确认弹窗，不使用浏览器原生弹窗。

### 7.5 版本与发布页

版本列表展示版本号、状态、基线版本、发布说明、发布人、发布时间、节点数量和关联运行数。

提供：

- 草稿与当前发布版差异
- 任意两个已发布版本差异
- 发布前校验报告
- 发布草稿
- 基于历史版本创建草稿
- 将历史配置重新发布为新版本

差异维度包括节点增删、连接、顺序、配置、Skill 绑定、重试策略和执行器版本。

### 7.6 校验报告页/抽屉

校验结果按“阻断错误、风险警告、建议”分组，每条包含对象、原因、影响和定位按钮。阻断错误存在时禁止发布；警告可以发布，但必须在发布记录中留痕。

### 7.7 测试运行页（已移除）

产品侧不再提供干运行 / 沙箱测试运行页。流程验证通过正式课程/热点生成与自动化 IT 完成。

### 7.8 运行记录页

支持按状态、工作流版本、课程、时间和失败节点筛选。列表展示运行编号、对象、版本、触发来源、状态、当前步骤、耗时、费用、开始时间和发起人。

点击后进入现有执行轨迹页面的增强版。文章版本存在关联时显示“查看版本内容”。

### 7.9 运行分析页

展示成功率、平均耗时、P95 耗时、重试率、重试成功率、平均 Token、平均图片数、失败节点排行和版本对比。指标必须可以下钻到具体运行，避免只有汇总数字无法定位。

## 8. 受控节点类型设计

### 8.1 首批节点分类

| 分类 | 节点示例 | 是否调用 AI | 核心产物 |
|---|---|---:|---|
| 定位 | 解析课程位置、读取路线 | 否 | course_context |
| 上下文 | 读取相邻课程、规则与参考课 | 否 | source_bundle |
| 规划 | 课程边界、结构提纲、保留清单 | 是 | boundary_plan、outline |
| 写作 | 生成课程原稿 | 是 | course_draft |
| 审校 | 知识检查、零基础检查、规范修复 | 规则 + AI | review_report、revised_draft |
| 转换 | 生成公众号版本 | 是 | wechat_draft |
| 视觉 | 图片计划、图片生成、尺寸校验 | AI + 图片服务 | image_assets |
| 一致性 | 图片引用、禁用符号、上下节衔接 | 否/AI | validation_report |
| 保存 | 数据库提交、版本关联、文件投影 | 否 | committed_version |

### 8.2 节点可配置性等级

- A 级：只读系统节点，不可禁用，如正式版本提交。
- B 级：可调整超时、重试和 Skill，不可改变关键业务顺序，如课程原稿生成。
- C 级：可启停、排序和配置，如某些补充审校节点。
- D 级：未来可新增的受控扩展节点，必须来自系统节点注册表。

### 8.3 执行器注册要求

每个执行器必须声明：唯一 key、中文名称、版本、配置 Schema、输入输出 Schema、超时上限、重试能力、幂等策略、是否产生外部副作用、允许的前后置节点和测试替身。

## 9. 节点配置 Schema

后端以版本化 JSON Schema 描述配置，前端按 Schema 渲染表单，但关键节点可以提供专用编辑组件。配置示例字段：

```json
{
  "timeout_seconds": 180,
  "max_attempts": 3,
  "retry_backoff": "exponential",
  "failure_policy": "stop",
  "model_profile": "text_default",
  "temperature": 0.4,
  "output_contract_version": "course-draft-v2"
}
```

敏感字段只保存配置引用，例如 `model_profile`、`credential_id`，不把 API Key 放入工作流 JSON、版本差异或运行快照。

## 10. Skill 与工作流节点集成

### 10.1 使用规则

1. AI 节点执行前，根据发布版本取得绑定的节点级 Skill。
2. 按节点绑定顺序拼装，并记录 Skill ID、版本、内容哈希和最终顺序。
3. 系统级 Skill 进入可用能力清单，由 AI 调用策略自行判断，不参与节点顺序配置。
4. 非 AI 节点默认禁止绑定提示词 Skill；如确有规则型 Skill，必须提供独立执行器。
5. 同一 Skill 可绑定多个节点，但每个节点的顺序独立。
6. 发布校验必须检查 Skill 是否存在、是否启用、内容是否为空、版本是否可用及冲突情况。

### 10.2 Prompt 组装顺序

建议固定为：系统安全规则 → 项目全局规则 → 节点任务指令 → 节点级 Skill（按顺序）→ 本次课程上下文 → 输出契约。

最终 Prompt 不在普通页面完整暴露密钥或敏感配置，但具备权限的调试视图可以查看脱敏快照和各片段来源。

## 11. 草稿、发布、回滚与兼容

### 11.1 状态流转

`未启用 → 草稿 → 已发布 → 已停用/已归档`

工作流定义状态和版本状态分别管理。一个工作流可有多个历史发布版本，但同一时间仅有一个当前发布版本。

### 11.2 版本号

- 小版本：仅展示文案、非语义配置或安全的重试参数变化，如 `1.1`。
- 大版本：节点、依赖、输入输出契约或关键 Skill 发生变化，如 `2.0`。
- 版本号由系统建议、发布人确认；数据库另用单调递增 revision 保证排序。

### 11.3 发布事务

发布操作必须在单一事务中：锁定草稿 → 重新校验 → 创建不可变版本快照 → 更新当前发布版本 → 写审计日志。任何一步失败都不得让半成品版本生效。

### 11.4 回滚语义

不直接把指针静默指回历史版本。用户选择历史版本后，系统复制为新草稿，完成当前环境兼容校验，再发布为新的版本号。这样保留完整时间线，也能发现旧执行器或旧 Skill 已不可用的问题。

### 11.5 运行兼容

- 已开始运行继续使用启动时的版本快照。
- 新发布只影响发布后的新运行。
- 停用工作流后禁止新运行，已运行任务可以完成或由管理员终止。
- 执行器升级必须声明兼容范围；删除执行器前检查所有可运行版本引用。

## 12. 运行、失败和恢复机制

### 12.1 调度流程

1. 接收业务触发请求并检查幂等键。
2. 读取当前发布版本并复制运行快照。
3. 校验业务输入和运行前置条件。
4. 根据依赖选择可运行节点。
5. 节点开始前写 Node Run 和心跳。
6. 执行节点并校验输出契约。
7. 保存不可变 Artifact 和输出哈希。
8. 标记节点完成，继续调度下游。
9. 全部通过后统一提交正式文章版本与关联记录。
10. 文件投影通过 Outbox 异步完成并可独立重试。

### 12.2 失败策略

- `stop`：立即停止流程，默认用于内容生成和校验节点。
- `retry_then_stop`：按退避策略自动重试，耗尽后停止。
- `continue_with_warning`：仅允许明确标记为非关键的节点。
- `fallback`：调用代码中预注册的备用执行器，不允许在页面填写任意地址。

### 12.3 恢复条件

重新执行失败节点前检查：工作流版本未变、上游 Artifact 哈希有效、节点支持幂等、外部副作用可重放。任一条件不满足时，从最近安全检查点创建一次新的恢复运行，而不是覆盖历史尝试。

### 12.4 状态语义

统一使用：等待执行、执行中、已完成、重试中、已失败、已跳过、已取消。父步骤状态由子节点聚合，不允许父步骤和子步骤同时出现互相矛盾的“执行中”。

## 15. 前端状态与交互规范

- 服务端状态使用统一请求缓存层；草稿编辑状态与已发布数据分离。
- 草稿采用显式“保存草稿”，不自动发布。
- 可在本地暂存表单输入，但页面刷新后恢复时必须提示，不直接覆盖服务端草稿。
- 所有删除、重置、发布、取消运行使用项目自研对话框。
- 节点保存失败时保留用户输入，并将错误定位到字段或节点。
- 运行状态使用轮询或 SSE；网络断开不把任务误判为失败，恢复连接后按服务端状态对齐。
- 按钮、表单、表格、Toggle、标签和弹窗沿用现有设计系统及 Lucide 图标。
- 画布在窄屏下切换为节点列表与配置抽屉，不强制压缩成不可操作的小图。

## 16. 发布校验规则

### 16.1 阻断规则

- 没有开始节点或结束节点。
- 出现环路、孤立节点或不可达必需节点。
- 必填节点被禁用。
- 连接端口或数据契约不兼容。
- 节点配置不符合 Schema 或超出系统安全上限。
- AI 节点缺少必需 Skill、模型配置或输出契约。
- 引用的 Skill、节点执行器或凭据配置不存在。
- 正式保存节点不是唯一终点，或存在绕过最终校验的路径。

### 16.2 警告规则

- 重试次数可能造成较高费用。
- 节点没有绑定建议 Skill。
- 草稿执行器版本落后于当前推荐版本。
- 非关键审校节点被禁用。
- 超时设置明显低于近期 P95。

## 17. 安全与审计

1. API Key 仅由现有 AI 配置管理，工作流只引用配置 ID。
2. 工作流定义禁止任意代码、任意 SQL 和未经白名单的外部 URL。
3. Prompt、Skill 和模型响应在日志中按规则脱敏。
4. 发布、停用、归档、测试真实上游、取消运行均写审计日志。
5. 运行详情默认不展示 Authorization、API Key、完整请求头和数据库连接信息。
6. 测试产物和正式产物使用独立命名空间与写入路径。
7. 对工作流修改、发布和运行 API 实施幂等键、速率限制和请求大小限制。

## 18. 从当前硬编码流程迁移

### 18.1 迁移策略

采用“镜像、校验、切换”三步，不一次性替换现有执行链：

1. 将当前节点注册为受控 Node Type。
2. 由迁移脚本生成“生成课程内容”工作流定义和 V1.0 发布快照。
3. 旧执行器继续负责调度，管理模块先只读展示同一份节点元数据。
4. 对比代码顺序与数据库定义，建立一致性测试。
5. 开放配置后，仅让白名单参数从发布版本读取。
6. 沙箱验证通过后，正式运行绑定工作流版本。
7. 稳定观察至少一个发布周期，再移除重复的硬编码展示配置；核心执行器代码保留。

### 18.2 兼容历史数据

- 历史运行无法确定版本时标记为“旧版内置流程”，不伪造版本号。
- 可确定节点集合的历史运行关联只读的 `legacy-v1` 快照。
- 历史文章版本继续通过 workflow_run_id 查看轨迹。
- 手动修改并保存的文章版本不关联 AI 轨迹，符合现有规则。

## 19. 可观测性与指标

### 19.1 业务指标

- 课程生成成功率
- 一次通过率
- 人工修改前后的差异量
- 原稿与公众号知识点保留率
- 图片完整率和尺寸通过率

### 19.2 技术指标

- 工作流总耗时与 P95
- 各节点耗时、失败率和重试成功率
- 文本/图片上游错误码分布
- Token、图片数量及估算费用
- 恢复运行成功率
- 文件投影延迟和失败率

### 19.3 告警建议

- 连续 3 次相同节点失败。
- 15 分钟无心跳但状态仍为执行中。
- 某版本成功率较前版本下降 10 个百分点以上。
- 上游无效响应率超过阈值。
- 正式提交成功但文件投影长时间未完成。

## 20. 分阶段版本迭代

## 20.1 V1.0：只读工作流中心

### 产品目标

让用户看清“当前系统到底按什么流程执行”，统一工作流、节点、Skill 和历史运行的入口，不改变实际生成逻辑。

### 功能范围

- 新增一级菜单“工作流”。
- 工作流列表与“生成课程内容”详情。
- 当前内置流程的只读拓扑图/节点列表。
- 节点详情只读展示：作用、执行器、输入输出、重试规则、绑定 Skill。
- 当前发布标识采用“内置基线版本”。
- 关联现有执行轨迹和运行记录。
- 中文节点名称、状态和错误文案统一。

### 后端与数据

- 建立 workflow_definitions、workflow_node_types 和只读基线版本表。
- 迁移脚本根据当前代码节点生成基线定义。
- 增加查询 API，不改变调度入口。

### 兼容与迁移

生成按钮、课程页面、版本关联和失败重试行为保持不变。历史运行显示为旧版或可识别的基线版本。

### 验收标准

1. 页面展示节点与代码实际执行顺序 100% 一致。
2. 每个 AI 节点可看到实际绑定的 Skill 和顺序。
3. 从工作流运行记录可以进入现有执行轨迹。
4. 不允许在 V1.0 页面修改任何运行配置。
5. 现有生成回归测试全部通过。

### 明确不包含

编辑、发布、回滚、沙箱、拖拽和指标分析。

## 20.2 V1.1：受控节点配置

### 产品目标

允许在安全边界内调整节点参数和节点级 Skill，同时保持核心流程结构不被破坏。

### 功能范围

- 工作流活动草稿。
- 编辑节点展示名称、说明、超时、重试和失败策略。
- 对 C 级节点进行启停和受控排序。
- 节点级 Skill 绑定、启停、顺序和预览。
- 草稿保存、乐观锁和未保存提醒。
- 结构、配置、Skill 与契约校验。

### 后端与数据

- 新增 workflow_drafts。
- 节点类型注册配置 Schema。
- 增加草稿保存、校验、重置和差异 API。
- 运行仍使用内置发布版，不直接读取未发布草稿。

### 兼容与迁移

现有 Skill 节点绑定迁移到草稿和基线版本。Skill 管理页继续管理 Skill 内容，工作流页只管理“在哪个节点、按什么顺序使用”。

### 验收标准

1. 非法超时、空 Skill 和必需节点禁用会被阻断。
2. 两个浏览器编辑同一草稿时能发现 revision 冲突。
3. 系统级 Skill 始终只读且无顺序字段。
4. 保存草稿不会影响正式课程生成。
5. 草稿与当前运行配置差异可以准确展示。

### 明确不包含

正式发布、历史回滚、真实沙箱和任意连线。

## 20.3 V1.2：版本与发布治理

### 产品目标

让配置变更以可审计、不可变、可回退的版本方式进入正式生产。

### 功能范围

- 草稿与发布版本分离。
- 发布前完整校验和确认弹窗。
- 发布说明、版本号建议和版本列表。
- 草稿与发布版、两个历史版本差异对比。
- 基于历史版本创建草稿并重新发布。
- 正式运行锁定工作流版本和 Skill 快照。

### 后端与数据

- 完成 workflow_versions、version_nodes、version_edges、version_skill_bindings 和 audit_logs。
- 发布事务和版本快照签名。
- workflow_runs 增加版本外键和运行快照。

### 兼容与迁移

首次上线把内置基线转为正式 V1.0。未发布草稿不影响生产；已有运行继续使用原快照。

### 验收标准

1. 已发布版本通过所有接口均不可修改。
2. 发布后新运行使用新版本，旧运行不漂移。
3. 任意运行能还原节点配置和 Skill 内容哈希。
4. 回滚生成新版本，不覆盖历史版本。
5. 发布失败不会出现半生效状态。

### 明确不包含

从任意节点调试、可编辑拓扑和复杂运营指标。

## 20.4 V1.3：测试、调试与恢复（部分已调整）

### 产品目标

缩短上游失败、Prompt 异常和节点配置问题的定位时间。干运行 / 沙箱隔离路径已取消；验证走正式生成与自动化 IT。

### 功能范围（现行）

- 查看脱敏 Prompt/Skill 快照、模型调用和节点输入输出摘要（运行记录）。
- 失败节点重试、从安全检查点创建恢复运行。
- Token、耗时、图片数和费用诊断。

### 后端与数据

- 建立运行心跳、取消和超时回收机制。
- （已取消）`run_mode` / 测试 Artifact 隔离列；见 Flyway V19。

### 验收标准

1. 失败详情能定位课程原稿、公众号、图片或保存环节。
2. 重试时旧错误文案被新尝试状态正确替代，同时保留历史尝试。
3. 工作进程异常退出后能够识别中断并安全恢复。

### 明确不包含

干运行、沙箱运行、任意节点连线、循环编排和工作流模板市场。

## 20.5 V2.0：受控可视化设计器

### 产品目标

在执行器和数据契约约束下调整流程结构，支持有限分支与返工闭环。

### 功能范围

- 受控节点库、拖放、排序和连线。
- 条件节点，例如审校不通过进入修复节点。
- 有上限的循环/返工节点，必须设置最大次数和终止条件。
- 输入输出端口与数据流可视化。
- 环路、孤立节点、不可达节点和契约冲突实时提示。
- 画布撤销、重做、适配视图和键盘可访问操作。

### 后端与数据

- 调度器从版本边关系计算可执行节点。
- 条件表达式使用受限 DSL，不执行代码。
- 循环执行记录包含迭代号和硬性上限。

### 兼容与迁移

现有线性流程自动映射成 DAG。关键保存和一致性节点设置系统结构约束，不能被绕过。

### 验收标准

1. 无法发布存在非法环路或绕过最终校验的流程。
2. 连线时即时检查端口契约。
3. 循环达到上限后明确失败，不能无限消耗上游资源。
4. 同一发布版本在相同输入下调度路径可解释、可重放。
5. 移动端可通过列表模式完成查看和基本配置。

### 明确不包含

任意代码节点、任意外部 Webhook 和无限循环。

## 20.6 V2.1：模板与运营分析

### 产品目标

提高新场景复用效率，并用数据判断流程版本是否真正改善质量、稳定性和成本。

### 功能范围

- 官方工作流模板。
- 克隆工作流并保留来源关系。
- 成功率、耗时、失败节点、重试成功率和费用趋势。
- 工作流版本横向对比。
- 指标下钻到运行和节点。
- 异常阈值与站内告警。

### 后端与数据

- 聚合指标表或定时聚合任务。
- 模板元数据、适用场景和兼容执行器范围。
- 版本指标对比 API。

### 兼容与迁移

指标从 V1.2 后有可靠版本关联的运行开始统计；旧数据单独标识，不与新版本强行合并。

### 验收标准

1. 汇总指标与抽样运行明细一致。
2. 每个指标可查看口径、时间范围和样本量。
3. 克隆模板不会复制凭据、正式业务对象或历史运行。
4. 版本对比至少覆盖成功率、P95、重试率、Token 和费用。
5. 告警可追溯到触发指标及关联运行。

### 明确不包含

公共模板市场、跨租户共享和自动发布优化方案。

## 23. 风险与应对

| 风险 | 影响 | 应对措施 |

| 配置能力过强导致质量下降 | 正式文章不稳定 | 分级可配置、阻断校验、发布版本、正式生成验收 |
| Skill 与节点指令重复冲突 | Prompt 变长且结果漂移 | 明确组装顺序、冲突扫描、运行快照 |
| 已发布版本引用旧执行器 | 无法重放 | 执行器兼容声明、下线前引用检查 |
| 重试产生重复外部副作用 | 重复图片或版本 | 节点幂等键、Artifact 哈希、安全检查点 |
| 可视化流程与真实执行不一致 | 用户误判 | 定义成为调度来源、一致性契约测试 |
| Prompt/日志泄露敏感信息 | 安全事故 | 引用凭据、脱敏、保留期与审计 |
| 指标口径不一致 | 错误决策 | 指标字典、样本量和明细下钻 |

## 24. 各阶段统一完成定义

每个版本只有同时满足以下条件才算完成：

1. 产品需求、交互稿、接口和数据迁移已经评审。
2. 功能代码、必要注释和迁移脚本完整。
3. 单元、集成、端到端和既有回归测试通过。
4. 数据迁移可前滚，必要时具备可验证的恢复方案。
5. 桌面和移动端完成视觉验收，不使用浏览器原生弹窗。
6. 权限、安全、脱敏和审计检查通过。
7. 使用固定课程案例完成正式生成验收。
8. 用户文案、错误信息、状态名称均为准确中文。
9. 发布说明记录已知限制和监控指标。
10. 代码、数据库、页面所展示的节点和 Skill 保持一致。

## 25. 最终建议

优先实施 V1.0 至 V1.3，先解决流程不可见、配置不可控、变更不可追溯的问题。V2.0 的可视化编排价值较高，但复杂度和风险也显著增加，应在版本治理与运行可观测成熟后再建设。

该模块最重要的质量标准不是“画布看起来像低代码平台”，而是每次课程生成都能够明确回答：**使用了哪个工作流版本、执行了哪些节点、每个节点用了哪些 Skill、产生了什么产物、失败在哪里、为何能重试，以及最终文章版本如何形成。**
