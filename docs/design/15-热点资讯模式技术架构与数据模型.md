# 热点资讯模式技术架构与数据模型

## 1. 技术目标

在现有 `ContentMode`、`ContentTheme`、工作流、任务、通知和文章版本模型上扩展热点资讯模式，不破坏课程体系教学模式的历史数据。

热点模式需要重点解决：

- 多来源协议不同。
- 同一事件重复出现。
- 来源内容会更新或失效。
- 采集任务必须可恢复、可诊断。
- AI 判断必须保留依据。
- 文章必须关联来源和事实证据。
- 采集来源的凭据不能进入日志和文章。

## 2. 模式与主题

新增固定数据：

```text
模式名称：热点资讯模式
模式编码：hot-news
主题名称：AI 热点前沿
主题编码：ai-frontier
```

课程模式现有数据不迁移、不改主键。热点文章、热点任务和来源数据通过 `theme_id` 归属到新主题。

## 3. 分层架构

```text
来源适配层
  RSS / 网页 / GitHub / 论文 / 社区 / 搜索 API
        ↓
采集编排层
  手动任务、分来源执行、超时、重试、终态
        ↓
标准化层
  标题、正文摘要、作者、时间、URL、来源类型、Hash
        ↓
事件聚合层
  相似事件聚类、来源关系、事件时间线
        ↓
分析层
  热度评分、写作价值评分、事实状态、重复检测
        ↓
人工决策层
  选题确认、角度确认、观点确认
        ↓
内容生成层
  简报、原稿、公众号转换、配图、审核、版本
```

## 4. 来源适配器

所有来源实现统一接口：

```text
validate_config()
fetch(cursor, time_range)
normalize(raw_item)
get_detail(item)
health_check()
```

适配器不得直接写业务文章，只负责返回标准化来源条目。

建议首批适配器：

1. RSS/Atom：低成本、稳定、适合官方博客和媒体。
2. 普通网页：读取公开页面并保存摘要和正文快照。
3. GitHub：仓库搜索、Release、Star 增量和 README 摘要。
4. 论文元数据：标题、作者、摘要、分类、发布时间和论文链接。
5. 可选平台搜索：通过用户配置的 API 或 Cookie 访问，不作为唯一事实来源。

每个适配器都有来源级超时、速率限制、重试次数和最大条目数。

## 5. 数据模型

### 5.1 `source_channels`

来源渠道定义。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| theme_id | 所属主题 |
| name | 来源名称 |
| type | rss、web、github、paper、social、search |
| base_url | 来源地址 |
| trust_level | official、primary、secondary、community |
| enabled | 是否启用 |
| fetch_policy | 抓取策略 JSON |
| created_at / updated_at | 时间 |

### 5.2 `source_credentials`

来源凭据独立保存。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| channel_id | 来源渠道 |
| credential_type | token、cookie、api_key |
| encrypted_value | 加密值 |
| redacted_hint | 脱敏展示 |
| expires_at | 过期时间 |
| updated_at | 更新时间 |

凭据不能写入日志、任务输出、AI 提示词或文章内容。

### 5.3 `source_fetch_runs`

一次手动采集任务。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| theme_id | 主题 |
| status | pending、running、succeeded、partial、failed、cancelled |
| trigger | manual |
| requested_channels | 选择的来源 |
| started_at / finished_at | 时间 |
| total_items | 条目数 |
| error_summary | 脱敏错误摘要 |

### 5.4 `source_items`

标准化后的原始条目。

保存：

- 来源渠道和来源类型
- 原始 URL、规范化 URL
- 标题、作者、发布时间、采集时间
- 摘要和正文快照路径
- 内容 Hash
- 官方来源标记
- 可信等级
- 是否已删除或失效
- 原始响应状态

### 5.5 `topic_clusters`

聚合后的热点事件。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| theme_id | 主题 |
| title | 规范化标题 |
| summary | 事件摘要 |
| status | discovered、candidate、confirmed、writing、ignored、expired |
| heat_score | 热度分 |
| writing_score | 写作价值分 |
| confidence_score | 可信度 |
| score_reason | 评分理由 |
| first_seen_at / last_seen_at | 时间 |
| expires_at | 预计过期时间 |

### 5.6 `topic_sources`

热点与原始条目的多对多关系。

额外保存：

- 来源在事件中的角色：official、evidence、commentary、contradiction
- 来源排序
- 是否已人工确认

### 5.7 `topic_evidence`

事实核验记录。

| 字段 | 说明 |
|---|---|
| topic_id | 热点 |
| statement | 待核验陈述 |
| evidence_type | fact、claim、opinion、uncertain |
| source_item_id | 支持来源 |
| status | verified、unverified、contradicted |
| reviewer | AI 或人工 |
| note | 说明 |

### 5.8 `topic_briefs`

选题简报版本。

保存：

- 事件概览
- 已确认事实
- 未确认信息
- 影响分析
- 推荐角度
- 作者观点草案
- 推荐文章类型、字数和配图
- 使用的来源快照
- 人工确认状态和意见

### 5.9 来源与文章关联

新增 `article_source_links`，记录文章引用或参考过的来源、证据和段落位置。

文章版本一旦生成，必须保存来源快照版本，不能只依赖当前网页内容。

## 6. 任务与并发

一次采集任务拆成：

```text
采集任务
  ├─ 来源 A 子任务
  ├─ 来源 B 子任务
  ├─ GitHub 子任务
  └─ 论文子任务
```

单个来源失败只影响该来源，不阻塞其他来源。任务最终状态：

- `succeeded`：全部启用来源成功。
- `partial`：至少一个来源成功，至少一个来源失败。
- `failed`：所有来源失败。
- `cancelled`：用户主动取消。

所有来源子任务必须有超时、心跳、错误码和结束时间。

## 7. API 边界

建议新增：

```text
GET  /api/modes
GET  /api/themes/{theme_id}/topics
POST /api/themes/{theme_id}/fetch-runs
GET  /api/fetch-runs/{run_id}
GET  /api/fetch-runs/{run_id}/channels
GET  /api/topics/{topic_id}
POST /api/topics/{topic_id}/confirm
POST /api/topics/{topic_id}/ignore
POST /api/topics/{topic_id}/briefs
POST /api/topic-briefs/{brief_id}/confirm
POST /api/topic-briefs/{brief_id}/generate-article
GET  /api/topics/{topic_id}/sources
GET  /api/articles/{article_id}/sources
```

写入动作都应返回任务或版本 ID，不能让前端依赖长时间同步请求。
