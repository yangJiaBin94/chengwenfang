# 知识库一致性生成流程改造方案

## 1. 文档目的

本文档定义工作台“生成课程内容”流程的改造目标、标准流程、数据结构、Skill 执行方式、审校返工机制、图片处理、版本管理和验收标准。

最终目标不是让工作台“也能生成文章”，而是让工作台与知识库项目使用同一套课程生成方法：上下文一致、课程边界一致、Skill 一致、检查标准一致、失败处理一致，并能够对生成结果和执行过程进行逐项复盘。

工作台与知识库可以保留不同的界面和技术实现，但不能各自维护一套互相漂移的生成规则。

## 2. 一致性目标

### 2.1 必须一致的内容

- 学习路线和课程定位
- 前后课程衔接关系
- 必须覆盖的知识点
- 禁止提前展开的内容
- 公式、数值和案例推理
- 课程原稿结构
- 公众号版本的知识点保留范围
- 图片数量、用途、风格和尺寸
- 审校规则和返工条件
- Skill 内容、版本和执行顺序
- 版本保存条件
- 执行记录和最终报告字段

### 2.2 可以不同的内容

- 前端页面布局
- 执行轨迹的视觉样式
- 后端任务队列实现
- 文件存储路径的具体实现
- AI 上游请求的技术封装

### 2.3 硬性质量指标

| 指标 | 目标 |
| --- | --- |
| 必须知识点覆盖率 | 100% |
| 公式和关键数值一致率 | 100% |
| 禁止内容命中率 | 0% |
| 公众号图片引用对应率 | 100% |
| 小结、预告顺序正确率 | 100% |
| 图片尺寸合规率 | 100% |
| 生成步骤覆盖率 | 100% |
| 执行报告字段完整率 | 100% |

## 3. 知识库标准流程

知识库生成课程的实际流程分为七个阶段。

### 3.1 项目上下文读取

必须读取并记录：

1. 项目级 `AGENTS.md`。
2. 学习路线及当前系列全部课程。
3. 上一课原稿和公众号版本。
4. 当前课程已有内容（如果存在）。
5. 下一课标题和摘要。
6. 课程写作规范。
7. 公众号排版规范。
8. 插图风格指南。
9. 当前任务的 `task_plan.md`、`findings.md`、`progress.md`。
10. 本次生成所需的 Skill 文件。

每个文件都要记录是否存在、读取用途、修改时间和内容哈希。文件不存在时必须记录，不得静默跳过。

### 3.2 Skill 加载与执行

系统级 Skill 只读、不可编辑、没有固定场景顺序，由 AI 根据任务判断是否使用。场景 Skill 仅在对应功能中执行，并按照场景配置顺序执行。

“生成课程内容”场景的标准顺序为：

1. 课程策划与边界设计。
2. 课程原稿生成。
3. 公众号等量转换。
4. 插图规划与生成。
5. 完稿审校与返工。

本次执行必须记录 Skill 名称、类型、版本、内容哈希、执行顺序、是否实际调用以及输出摘要。

### 3.3 课程定位与边界设计

生成正文前必须明确：

- 本课最终学习目标。
- 必须覆盖的知识点。
- 必须出现的公式和数值案例。
- 必须解释的专业术语。
- 不得提前展开的内容。
- 上一课的承接点。
- 下一课的交接点。
- 章节结构和篇幅范围。
- 插图数量及每张图的主要结论。

该阶段的结果必须保存为结构化课程计划，并先通过检查，再进入正文生成。

### 3.4 课程原稿生成与审校

课程原稿必须包含：

- 从具体问题或生活场景开始的开场。
- 本课目标。
- 分层解释和首次术语说明。
- 公式前后的问题解释。
- 具体数值案例和推理过程。
- 插图位置和独立插图提示词。
- 本课小结。
- 下节课预告。

生成后检查：课程边界、知识点、公式、数值、案例、术语、前后衔接、作者声音、禁用符号、图片格式以及小结和预告顺序。

发现问题时优先局部修正，最多进行三轮“修正后再次检查”，不能因为单个格式问题无条件重写全文。

### 3.5 公众号等量转换

公众号版本以已通过审校的课程原稿为唯一事实来源。允许调整标题、段落节奏、移动端排版和表达方式，不允许改变知识点、公式、数值、案例推理、结论和课程边界。

公众号版本必须：

- 保留全部核心知识点。
- 保留公式、案例、图片引用和小结、预告。
- 删除课程编号、插图位置说明和插图提示词。
- 不新增下一课内容。
- 不压缩关键推理。

转换后必须生成内容保留清单，并逐项检查知识点、公式、数值、案例、边界条件和图片引用。检查失败时只修正缺失或错误部分。

### 3.6 图片规划、生成与检查

图片生成前先形成图片计划，显式区分封面和正文图片。每张图片必须有文章位置、用途、主要结论、提示词、目标尺寸和状态。

- 封面尺寸：`2400x1024`。
- 正文插图尺寸：`2048x1152`。
- 使用配置中的 `image2` / `gpt-image-2` 和 `high` 质量。
- 一张图只表达一个主要结论，通常不超过三个信息区。
- 统一使用知识库规定的视觉风格。

生成后检查文件存在性、格式、尺寸、引用、序号、图文位置、公式数字和视觉风格。失败图片单独重试，不重新生成整篇文章。

### 3.7 同步、版本和最终报告

生成完成后只同步上一课的“下节课预告”，不得修改上一课其他正文内容。

课程原稿和公众号版本使用同一个课程版本号。中间草稿和审校过程不产生用户可见版本，只有正式持久化修改才生成新版本。

最终报告必须记录：课程定位、读取文件、使用 Skill、执行步骤、失败和重试、图片结果、文件变化、版本信息、最终统计以及未执行或跳过的步骤。

## 4. 工作台目标工作流

工作台现有流程需要扩展为以下节点：

```text
queued
starting
load_project_rules
load_route_context
load_adjacent_articles
load_skill_context
plan_course
review_course_plan
generate_draft
review_draft
repair_draft
extract_content_manifest
generate_wechat
review_wechat
repair_wechat
plan_images
generate_cover
generate_inline_images
review_images
retry_failed_images
apply_images
sync_previous_preview
final_validation
save_generation_report
completed
```

每个节点必须有开始时间、结束时间、状态、输入摘要、输出摘要、错误信息、重试次数和关联文件。

状态统一使用：

- `pending`：未执行。
- `running`：执行中。
- `completed`：已完成。
- `failed`：执行失败。
- `retrying`：正在重试。
- `partial`：部分完成。

## 6. 审校与返工规则

### 6.1 原稿审校

检查：

- 必须知识点是否全部覆盖。
- 公式和数值是否正确。
- 必须案例是否完整。
- 是否提前讲下一课。
- 是否与上一课衔接。
- 是否首次解释专业术语。
- 是否存在重复、模板化或无效扩写。
- 是否满足课程结构、作者声音和格式要求。

### 6.2 公众号审校

检查：

- 知识点覆盖率为 100%。
- 公式数量、符号和含义一致。
- 数值、案例步骤和结论一致。
- 图片引用数量和位置一致。
- 不残留插图提示词。
- 不新增边界外内容。
- 小结在预告之前。

### 6.3 图片审校

检查：

- 文件存在且可访问。
- 格式和尺寸正确。
- 图片数量与计划一致。
- 文章引用与图片序号一致。
- 图片表达单一主要结论。
- 公式、数字和曲线无明显错误。
- 视觉风格符合知识库指南。

### 6.4 修正原则

- 优先局部修正，避免全文重写。
- 每次修正必须记录问题、位置、修正动作和结果。
- 修正后必须重新执行对应检查。
- 连续三轮仍失败时标记失败，保留失败原因和建议操作。

## 7. 版本与持久化规则

1. 课程原稿和公众号文章共用一个课程版本号。
2. 生成过程中的草稿、计划和审校结果不产生正式版本。
3. 只有用户或生成流程正式持久化修改后才生成新版本。
4. 图片插入导致正文发生持久化变化时，按照统一版本规则处理。
5. 轨迹必须关联具体课程、具体版本和具体文章来源。
6. 手动编辑版本没有 AI 执行轨迹时，不强行关联生成记录。

## 8. 执行报告要求

工作台应生成与知识库报告同等级别的 Markdown 或结构化报告，至少包含：

1. 生成目标和课程定位。
2. 路线定位和前后课程。
3. 实际读取文件清单。
4. 使用的系统级和场景 Skill。
5. Skill 执行顺序和版本。
6. 课程边界和内容清单。
7. 原稿生成过程。
8. 公众号转换过程。
9. 图片规划和生成结果。
10. 审校结果和返工记录。
11. 失败、重试和替代处理。
12. 文件新增、修改和未找到记录。
13. 版本和文章关联信息。
14. 最终字符数、标题数、图片数等统计。
15. 最终摘要和遗留风险。

报告必须区分“实际执行”“跳过”“失败”“推测”，不能把未发生的操作写成已完成。

## 9. 分阶段实施计划

### 阶段一：规则和上下文同步

实现项目规则、路线、相邻文章、Skill 和任务文件的统一读取、哈希记录和快照保存。

验收：能够查看本次实际读取的全部文件，文件缺失能够明确显示。

### 阶段二：课程计划和边界

新增课程定位、必须覆盖清单、禁止越界清单、前后衔接和计划审校。

验收：无有效课程计划不得生成原稿，计划内容可在执行轨迹中查看。

### 阶段三：原稿审校和返工

新增知识点、公式、案例、边界和格式审校，支持局部修正和重新检查。

验收：能够自动补齐缺失内容、删除越界内容并保留修正记录。

### 阶段四：公众号等量转换

取消默认分块二次改写，改为完整原稿转换、内容清单提取、逐项对照和局部修正。分块请求仅作为上游限制时的兜底方案。

验收：知识点、公式、数值和案例全部一致，提示词全部删除，图片引用完整。

### 阶段五：图片规划和检查

新增独立图片规划、封面显式标识、逐图状态、尺寸检查、视觉检查和失败图片单独重试。

验收：图片数量、尺寸、风格、引用和文章位置全部符合计划。

### 阶段六：报告和版本一致性

新增文件级执行记录、Skill 快照、失败记录、最终报告和统一版本关联。

验收：能够从执行轨迹完整复盘一次生成，并准确关联到对应课程版本。

## 10. 对照验收方案

使用同一课程路线、同一课程和同一批 Skill，分别在知识库和工作台生成一次，执行以下对照：

### 内容对照

- 课程目标一致。
- 必须知识点一致。
- 公式和关键数值一致。
- 案例推理一致。
- 禁止越界内容均未出现。
- 前后课程衔接一致。

### 结构对照

- 章节数量处于同一范围。
- 小结和预告顺序一致。
- 插图数量和位置一致。
- 公众号没有遗漏关键推理。

### 规范对照

- 作者声音一致。
- 术语解释方式一致。
- 禁用符号检查一致。
- 公众号排版一致。
- 图片风格、尺寸和用途一致。

### 流程对照

- Skill 执行顺序一致。
- 课程计划阶段存在。
- 审校和返工阶段存在。
- 图片规划和检查阶段存在。
- 执行报告字段完整。

## 11. 实施约束

- 先改后端工作流和数据记录，再改前端展示。
- 不以增加 Prompt 文本代替流程节点。
- 不在未通过审校时保存正式版本。
- 不将失败重试隐藏为一次成功执行。
- 不把推测步骤写入执行报告。
- 不破坏现有统一版本管理和手动编辑逻辑。
- 每个阶段完成后必须运行后端测试、前端构建和一次真实生成验收。

## 12. 完成定义

只有同时满足以下条件，才算本方案完成：

1. 工作台使用知识库规则作为规范源。
2. 生成前存在可查看的课程计划和边界表。
3. 原稿经过内容级审校和返工。
4. 公众号版本经过逐项等量对照。
5. 图片经过规划、生成、尺寸和视觉检查。
6. 失败步骤可以单独重试。
7. 原稿和公众号版本使用统一版本号。
8. 执行轨迹关联具体版本。
9. 生成报告能够记录所有实际操作和文件差异。
10. 同一课程在两边生成的关键内容和结构达到上述一致性指标。
