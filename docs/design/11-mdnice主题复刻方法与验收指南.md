# mdnice 主题复刻方法与验收指南

## 1. 文档目的

本文总结工作台复刻 mdnice 主题时的关键方法、常见误区和验收标准。

复刻目标不是让工作台预览“看起来差不多”，而是让同一份 Markdown 分别经过工作台和 mdnice 复制到微信公众号编辑器后，最终 DOM 结构、计算样式和视觉节奏保持一致。

完整链路如下：

```text
Markdown
  -> Markdown 解析器
  -> 工作台主题渲染器
  -> text/html 剪贴板内容
  -> 微信编辑器粘贴与 DOM 重写
  -> 微信编辑器最终显示
```

任何一层存在差异，最终效果都会不同。

## 2. 本次复刻得到的核心结论

### 2.1 最终微信 DOM 才是事实来源

工作台预览和 mdnice 预览只能用于快速观察，不能作为最终验收依据。微信编辑器会在粘贴时：

- 删除或改写部分标签和属性。
- 把文本包进新的 `span`、`section` 或其他节点。
- 将不符合编辑器模型的结构拆分为多个块。
- 重新计算继承样式。
- 为图片、段落和可编辑节点增加内部结构。

因此，复刻时必须比较两份内容粘贴进微信后的最终 `outerHTML` 和 `getComputedStyle()`。

### 2.2 DOM 结构比 CSS 参数更重要

列表问题是最典型的例子。

工作台原先输出：

```html
<li>
  <strong>输入层</strong>
  接收原始数据
</li>
```

微信粘贴后将裸文本改写为独立块：

```html
<li>
  <strong>输入层</strong>
  <section>接收原始数据</section>
</li>
```

这会导致强制换行。仅调整 `font-size`、`line-height` 或处理 Markdown 软换行都无法解决。

mdnice 在复制前已经输出稳定结构：

```html
<li>
  <section>
    <strong>输入层</strong>
    接收原始数据
  </section>
</li>
```

微信不会再拆分该结构。复刻时必须使用相同的节点层级。

### 2.3 不要把所有样式都绑定到一个主题主色

一个 mdnice 主题可能同时包含：

- 二级标题的黑色背景。
- 三级标题的红色左边线。
- 引用块的紫色边框和浅紫背景。
- 行内代码的紫色文字。
- 普通正文的灰色文字。

这些颜色承担不同语义，不能全部复用 `primaryColor`。主题配置应拆分为独立字段，例如：

```json
{
  "primaryColor": "#9654b5",
  "headingBackground": "#212122",
  "headingTextColor": "#ffffff",
  "subheadingBorderColor": "#f44336",
  "blockquoteBorderColor": "#9654b5",
  "accentColor": "#fbf9fd",
  "inlineCodeColor": "#9654b5"
}
```

### 2.4 背景色必须考虑继承关系

普通正文需要白色背景，但引用块内部段落不能强制白底。

错误做法：

```html
<blockquote style="background:#fbf9fd">
  <p style="background:#ffffff">摘要内容</p>
</blockquote>
```

这会让引用块内部出现白色矩形，只剩外围浅紫背景。

正确做法：

```html
<blockquote style="background:#fbf9fd">
  <p style="background:transparent">摘要内容</p>
</blockquote>
```

规则应按上下文生成：

- 普通段落：白色背景。
- 引用块内段落：透明背景。
- 列表项内部容器：按 mdnice 对应规则设置。

### 2.5 Markdown 语义不能凭经验改写

不要仅凭某一个样例，将独立粗体行统一转换成二级标题。

例如：

```markdown
**输入层 -> 隐藏层 -> 输出层**
```

它可能是强调段落，也可能在某个主题中看起来像标题。是否转换必须依据目标 mdnice 主题的实际解析结果，而不是视觉猜测。

Markdown 结构变化会影响：

- 标签类型。
- 上下间距。
- 标题装饰。
- 微信粘贴后的节点重写。
- 文档目录和可访问性语义。

## 3. 推荐的复刻流程

### 3.1 准备固定基准文章

每个主题至少准备一篇覆盖以下元素的基准 Markdown：

- 一级、二级和三级标题。
- 普通段落。
- 段内加粗、斜体和行内代码。
- 引用块，且包含多个段落。
- 无序列表和有序列表。
- 列表项中的加粗开头和长文本。
- 图片与图注。
- 分隔线。
- 代码块。
- 链接。
- 中英文、数字和标点混排。

不要只用短文章测试。长文章更容易暴露累计间距和继承样式问题。

### 3.2 在 mdnice 和工作台使用完全相同的 Markdown

对比前先校验：

- Markdown 字符串相同。
- 图片引用数量和位置相同。
- 标题级别相同。
- 列表缩进和空行相同。
- 没有一边手工修改正文。

如果输入不同，不能直接比较输出样式。

### 3.3 分别复制到两个微信草稿

建议固定命名：

```text
主题名-mdnice-基准文章
主题名-chengwenfang-基准文章
```

两个草稿应使用同一个微信公众号账号、同一编辑器版本和接近的创建时间。

### 3.4 先比较结构，再比较视觉

结构检查顺序：

1. 统计 `h1/h2/h3/p/blockquote/ul/ol/li/figure/strong/code` 数量。
2. 比较同位置节点的标签类型。
3. 比较节点的子元素层级。
4. 检查微信是否插入额外的 `section`、`p` 或空段落。
5. 检查图片前后是否产生空节点。
6. 检查列表项内容是否仍处于同一容器。

节点数量只能用于发现异常，不能单独作为视觉一致的证明。

### 3.5 提取计算样式

建议对每种元素记录以下属性：

```text
display
position
box-sizing
width / max-width
margin-top / margin-bottom
padding-top / padding-right / padding-bottom / padding-left
color
background-color
font-family
font-size
font-weight
line-height
letter-spacing
text-align
text-indent
border-width
border-color
border-radius
overflow
```

应读取 `getComputedStyle()`，不能只比较 `style` 字符串。不同内联写法可能得到相同的计算结果。

### 3.6 最后比较截图

截图用于检查计算样式无法直接表达的整体问题：

- 页面纵向节奏。
- 标题与正文之间的视觉距离。
- 长列表的密度。
- 多段引用块的背景连续性。
- 中英文基线和字体回退。
- 长标题换行后的形状。
- 图片与图注的整体占位。

截图必须保证：

- 相同浏览器缩放比例。
- 相同编辑器宽度。
- 相同滚动位置。
- 相同内容。
- 相同图片加载状态。

## 4. 元素级复刻要点

### 4.1 根容器

需要确认：

- 内容宽度。
- 左右内边距。
- 根字体和回退字体。
- 基准字号和行高。
- 根背景颜色。

字体名称必须完全匹配，例如：

```css
font-family: Optima, PingFangSC-regular, serif;
```

`PingFangSC-regular`、`"PingFang SC"` 和带有 `Microsoft YaHei` 回退的字体栈可能产生不同字宽和换行位置。

### 4.2 普通段落

本次主题的正文基准为：

```css
font-size: 15px;
line-height: 1.8em;
letter-spacing: 0.02em;
color: #5a5a5a;
padding: 8px 0;
text-align: left;
background-color: #ffffff;
```

段落外边距需要根据上下文决定，不能无条件统一。

### 4.3 二级标题

二级标题由外层块和内部装饰容器共同组成：

```html
<h2>
  <span class="content">01 | 标题</span>
</h2>
```

需要分别复刻：

- `h2` 的上下间距和背景。
- 内层 `span` 的背景色、文字色、圆角、内边距和行高。

### 4.4 三级标题

三级标题不应复用二级标题的黑色胶囊结构。本次主题使用独立左侧色条：

```css
font-size: 16px;
line-height: 1.5em;
border-left: 4px solid #f44336;
padding: 8px 0 8px 12px;
background: #ffffff;
```

### 4.5 引用块

引用块需要同时检查外层和内部段落：

```css
margin: 20px 0;
padding: 10px 10px 10px 20px;
border-left: 3px solid #9654b5;
background: #fbf9fd;
font-size: 16px;
line-height: 1.6;
```

内部段落应使用透明背景，避免覆盖引用块背景。

### 4.6 列表

列表至少包含三层样式责任：

1. `ul/ol`：项目符号、整体缩进和外边距。
2. `li`：列表项结构。
3. `li > section`：文字排版和微信粘贴稳定性。

本次主题的稳定结构为：

```html
<ul>
  <li>
    <section>
      <strong>输入层</strong>接收原始数据
    </section>
  </li>
</ul>
```

不要让 `strong` 后面直接跟随 `li` 的裸文本。微信可能将裸文本包装成新的块级节点，造成换行。

### 4.7 图片和图注

图片段落不要输出非法的 `p > figure` 结构。浏览器或微信会将它拆成：

```html
<p></p>
<figure>...</figure>
<p></p>
```

这会在图片上下产生额外空白。纯图片段落应直接输出 `figure`。

图注需要单独设置字号、行高、颜色、对齐和上边距。

### 4.8 加粗和行内代码

加粗文字通常需要显式设置黑色，避免继承正文灰色：

```css
font-weight: bold;
color: #000000;
```

行内代码需要检查：

- 字体族。
- 字号。
- 行高。
- 背景色。
- 文字色。
- 内边距和圆角。
- 长文本换行方式。

## 5. 常见错误及原因

### 5.1 只凭截图猜 CSS

截图能发现问题，但不能解释问题。相同的换行可能由以下原因造成：

- 容器宽度不同。
- 字体回退不同。
- 字号不同。
- 微信插入块级节点。
- Markdown 被解析成不同标签。

发现问题后应立即读取 DOM 和计算样式。

### 5.2 只比较预览，不比较粘贴结果

预览一致不代表微信粘贴后一致。必须至少进行一次真实复制粘贴回归。

### 5.3 一次修改多个结构规则

同时修改标题转换、列表结构、背景和字号，会让回归来源难以定位。正确方式是：

1. 一次只修复一个确定差异。
2. 增加对应测试。
3. 重启并重新复制。
4. 验证微信最终 DOM。
5. 再处理下一项。

### 5.4 用元素数量证明视觉一致

`h2` 数量一致只说明标签数量一致，不代表：

- 标签内容相同。
- 子节点相同。
- 样式相同。
- 间距相同。
- 微信没有重写节点。

元素数量只能作为初筛信号。

### 5.5 让子元素覆盖父容器背景

主题背景经常依赖继承。给所有段落强制白底，会破坏引用块、提示块和其他带背景的容器。

### 5.6 修改默认配置但忽略持久化主题版本

工作台主题配置保存在数据库的不可变版本中。修改 `DEFAULT_CONFIG` 不会覆盖已有主题版本。

需要确认：

- 当前页面实际选择的 `themeVersionId`。
- 数据库当前主题版本的配置。
- 文章布局是否仍指向旧主题版本。
- 页面刷新后是否加载了新版本。

## 6. 自动化测试建议

每个主题至少增加以下测试：

### 6.1 HTML 结构测试

```text
- 独立图片不被 p 包裹。
- 引用块内段落背景透明。
- 列表项使用 li > section 结构。
- strong 和后续文字处于同一 section。
- 二级标题包含预期的内部 span。
- 三级标题使用独立左边线。
```

### 6.2 样式测试

```text
- 正文字号、行高、字距和颜色。
- 列表容器字号与列表项内部文字字号。
- 引用块边框和背景。
- 二级、三级标题的颜色和间距。
- 图注样式。
```

### 6.3 微信粘贴回归

单元测试不能模拟微信全部重写行为。每次新增主题或修改核心节点结构后，应进行真实微信回归：

1. 复制工作台富文本。
2. 粘贴到测试草稿。
3. 读取最终 DOM。
4. 与 mdnice 基准草稿比较。
5. 保存截图和差异报告。

## 7. 新主题复刻检查清单

### 输入准备

- [ ] 使用固定基准 Markdown。
- [ ] mdnice 和工作台输入完全一致。
- [ ] 图片数量、位置和替代文字一致。
- [ ] 使用同一微信账号和编辑器环境。

### DOM 检查

- [ ] 标题级别一致。
- [ ] 列表节点层级一致。
- [ ] 引用块内部结构一致。
- [ ] 图片没有产生空段落。
- [ ] 没有微信新增的意外块级节点。
- [ ] 加粗、代码和链接没有被拆分。

### 样式检查

- [ ] 根字体完全一致。
- [ ] 正文字号、行高、字距和颜色一致。
- [ ] 普通段落背景一致。
- [ ] 引用块背景连续。
- [ ] 二级标题结构和装饰一致。
- [ ] 三级标题结构和装饰一致。
- [ ] 列表缩进、符号、字号、颜色和间距一致。
- [ ] 图片和图注间距一致。

### 发布检查

- [ ] `text/html` 和 `text/plain` 都写入剪贴板。
- [ ] 微信粘贴后没有新增异常换行。
- [ ] 长标题和长列表在移动端不溢出。
- [ ] 发布快照绑定准确的主题版本。
- [ ] 历史快照不会被后续主题更新修改。

### 回归检查

- [ ] 渲染器单元测试通过。
- [ ] 发布服务测试通过。
- [ ] Ruff 检查通过。
- [ ] 微信真实粘贴回归通过。
- [ ] 基准截图已更新。

## 8. 建议的主题配置模型

后续主题应避免使用少量颜色字段控制全部元素。建议至少支持：

```json
{
  "fontFamily": "Optima, PingFangSC-regular, serif",
  "fontSize": 16,
  "bodyFontSize": 15,
  "bodyLineHeight": 1.8,
  "bodyLetterSpacing": "0.02em",
  "textColor": "#5a5a5a",
  "rootBackground": "#fbfbfb",
  "paragraphBackground": "#ffffff",
  "headingBackground": "#212122",
  "headingTextColor": "#ffffff",
  "subheadingTextColor": "rgba(0,0,0,0.85)",
  "subheadingBorderColor": "#f44336",
  "blockquoteBackground": "#fbf9fd",
  "blockquoteBorderColor": "#9654b5",
  "blockquoteTextColor": "#000000",
  "strongColor": "#000000",
  "inlineCodeBackground": "rgba(27,31,35,0.05)",
  "inlineCodeColor": "#9654b5"
}
```

结构规则和视觉配置应分开：

- 结构规则由渲染器保证微信兼容性。
- 视觉配置由主题版本提供颜色、字号和间距。
- 不允许主题配置任意改变安全的 DOM 骨架。

## 9. 最终原则

复刻 mdnice 主题时，优先级应为：

```text
相同输入
  -> 相同语义结构
  -> 微信粘贴后相同 DOM
  -> 相同计算样式
  -> 相同视觉效果
```

不要反过来从截图开始连续试色和试间距。截图负责发现问题，DOM 负责解释问题，测试负责防止问题再次出现。
