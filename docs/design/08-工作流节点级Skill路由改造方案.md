# 工作流节点级 Skill 路由改造方案

## 1. 改造目标

将当前“按功能场景一次加载全部 Skill”的方式，改造为“场景限定功能范围、节点绑定实际使用时机”的精确路由。每个 AI 请求只接收当前节点需要的 Skill，并在执行轨迹中记录实际发送给模型的 Skill 快照。

本次不新增额外文本 AI 审校调用，不改变课程生成次数和版本提交边界。纯代码节点继续由确定性代码执行，不把 Skill 绑定展示冒充为 Skill 已执行。

## 2. 当前问题

1. `course_content_generation` 场景会一次加载 3 个系统 Skill 和 4 个场景 Skill，共约 14,101 字符。
2. 原稿的五个章节请求收到相同的全量 Skill，没有按章节职责筛选。
3. 公众号分段请求将系统提示词直接截断到 8,000 字符，场景 Skill 位于 11,000 字符以后，实际无法进入模型请求。
4. 图片生成只使用代码内置视觉后缀，没有解析 Skill 管理中的图片规则。
5. 执行轨迹只展示整次任务的 Skill 集合，无法说明某个节点实际使用了哪些 Skill。
6. Skill 内容、内置写作规则和代码校验存在重复，但当前无法区分“模型指导规则”和“确定性执行规则”。

## 3. 设计原则

- 场景表示功能：首版保留 `course_content_generation`。
- 节点表示使用时机：一个 Skill 可以绑定多个节点，一个节点可以绑定多个 Skill。
- Skill 不复制：节点关系使用独立绑定表保存。
- 只在 AI 节点解析 Skill：数据库查询、版本保存、尺寸校验、占位符替换等纯代码节点不解析提示词。
- 不静默截断：节点提示词按需组装，超过预算时明确失败并给出诊断，不允许截掉后半部分 Skill。
- 快照可追溯：每次请求记录 Skill ID、名称、范围、版本、节点、节点内顺序和内容 Hash。
- 系统 Skill 仍只读，但由内置节点绑定决定适用范围，不再无条件发送到所有请求。

## 4. 节点目录

| 节点键 | 名称 | 模型类型 | 说明 |
|---|---|---|---|
| `draft_opening` | 原稿：开场与目标 | 文本 AI | 建立具体场景、承接上一课、明确本课目标 |
| `draft_core` | 原稿：核心原理 | 文本 AI | 解释概念、术语、公式与边界 |
| `draft_example` | 原稿：案例与推导 | 文本 AI | 生成例子、计算、推导和正文插图提示词 |
| `draft_summary` | 原稿：本课小结 | 文本 AI | 收束当前课程，不引入新知识 |
| `draft_preview` | 原稿：下节课预告 | 文本 AI | 按路线预告下一课，不提前展开 |
| `wechat_conversion` | 公众号等量转换 | 文本 AI | 分段转换时每一段使用相同逻辑节点键 |
| `image_cover` | 课程封面生成 | 图片 AI | 独立封面提示词、2400x1024 |
| `image_inline` | 正文插图生成 | 图片 AI | 全部正文插图、2048x1152 |

`draft_section:opening`、`wechat_chunk:1` 等继续作为运行实例键保存；Skill 路由使用上表稳定的逻辑节点键，避免动态分段编号污染配置。

## 5. 默认 Skill 绑定

| Skill | 默认节点 |
|---|---|
| 成文坊规则理解 | 五个原稿节点、公众号转换 |
| 课程文章审校 | 五个原稿节点、公众号转换 |
| 图片生成与检查 | 封面生成、正文插图生成 |
| 课程策划与原稿生成 | 五个原稿节点 |
| 公众号文章转换 | 公众号转换 |
| 配图规划 | 原稿案例与推导、封面生成、正文插图生成 |
| 完稿规范 | 原稿小结、原稿预告、公众号转换 |

系统 Skill 的绑定由迁移写入且前端只读。场景 Skill 可以在新增和编辑弹窗中多选节点，并配置节点内顺序。

## 6. 数据模型

新增表 `skill_node_bindings`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string(36) | 主键 |
| `skill_id` | FK | 关联 Skill，删除时级联 |
| `workflow_type` | string(64) | `course_content_generation` |
| `node_key` | string(80) | 稳定逻辑节点键 |
| `priority` | integer | 当前节点内执行顺序 |
| `enabled` | boolean | 节点绑定是否启用 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 修改时间 |

唯一约束：`skill_id + workflow_type + node_key`。

保留 `skills.scene` 和 `skills.priority` 作为兼容字段。新运行时以绑定表为准，`skills.priority` 只作为创建绑定时的默认顺序和旧客户端兼容值。

## 7. 后端接口

Skill 读写结构增加：

```json
{
  "nodeBindings": [
    {
      "workflowType": "course_content_generation",
      "nodeKey": "draft_core",
      "priority": 10,
      "enabled": true
    }
  ]
}
```

新增节点目录接口：

`GET /api/settings/skills/workflow-nodes`

返回工作流、节点键、中文名称、模型类型和是否可配置。

Skill 创建和修改与节点绑定在同一数据库事务中完成，版本快照同时保存完整绑定信息。

## 8. 运行时解析

新增：

```python
resolve_node_prompt(
    workflow_type="course_content_generation",
    node_key="draft_core",
)
```

解析步骤：

1. 查询当前节点启用的绑定。
2. 过滤已删除或已停用 Skill。
3. 校验场景 Skill 的场景与工作流一致。
4. 按绑定优先级和 Skill 创建时间排序。
5. 拼接当前节点提示词。
6. 查询最新 Skill 版本号并生成快照。
7. 计算 Skill 内容 Hash 和完整节点提示词字符数。

文本节点将基础作者规则、课程上下文和节点 Skill 拼接后发送模型。图片节点将节点 Skill 拼入当前图片提示词。公众号阶段移除 `[:8000]` 静默截断。

## 9. 执行轨迹

每个 AI 子节点的输入摘要增加：

- `skillCount`
- `skills`
- `skillPromptChars`
- `skillPromptHash`

整次任务仍展示 Skill 汇总，但汇总来源改为本工作流所有有效节点绑定。后续前端可以在技术节点中精确展开本节点 Skill。

## 10. 前端交互

Skill 列表增加“适用节点”列，以简洁标签显示，过多时显示“等 N 个节点”。

新增和编辑弹窗增加节点多选区：

- 按“课程原稿、公众号、图片”分组。
- 点击节点胶囊切换选中状态。
- 至少选择一个节点才能保存场景 Skill。
- 系统 Skill 可以查看节点绑定，但不可修改。
- 执行顺序继续使用现有数字字段，保存时应用到该 Skill 的所有节点绑定。

## 11. 迁移策略

新增 Alembic `0017_skill_node_bindings`：

1. 创建绑定表和索引。
2. 按默认绑定矩阵写入 7 个内置 Skill。
3. 对用户已有场景 Skill：默认绑定五个原稿节点和公众号转换，保证升级后仍参与文本生成。
4. 不删除 `scene`、`priority`，避免破坏旧数据和历史快照。

## 12. 失败与边界处理

- 场景 Skill 没有节点绑定：创建或更新返回 422。
- 未知节点键：API 返回 422。
- 节点没有绑定 Skill：允许执行，只使用基础系统规则。
- Skill 全部停用：节点继续执行基础提示词。
- 节点提示词超过 12,000 字符：返回明确的 `SKILL_PROMPT_TOO_LARGE`，列出节点和字符数，不静默截断。
- 旧执行记录没有节点 Skill 快照：前端继续显示“旧任务未保存节点 Skill”。

## 13. 验收标准

1. 数据库迁移后 7 个内置 Skill 均具有预期节点绑定。
2. 新增、编辑、查询、删除 Skill 可正确维护节点绑定和版本快照。
3. `draft_core` 不包含公众号和图片 Skill。
4. `wechat_conversion` 不包含课程策划与原稿生成、图片生成 Skill。
5. `image_cover` 和 `image_inline` 实际将图片 Skill 内容发送给图片模型。
6. 公众号提示词不再使用固定 8,000 字符截断。
7. 每个文本 AI 节点的工作流记录保存实际 Skill 快照。
8. 后端单元测试、迁移测试、Ruff、Mypy、前端构建通过。
9. 浏览器验收 Skill 列表、节点展示、新增弹窗、编辑弹窗和系统 Skill 只读状态。
