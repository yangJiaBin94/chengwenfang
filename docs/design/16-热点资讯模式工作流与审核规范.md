# 热点资讯模式工作流与审核规范

## 1. 工作流名称

```text
热点资讯采集与文章生产
```

归属：

```text
模式：热点资讯模式
主题：AI 热点前沿
```

工作流节点继续使用现有 Skill 绑定机制，不做模式级 Skill 绑定。

## 2. 采集工作流

### 节点顺序

1. 读取主题来源配置。
2. 创建采集运行记录。
3. 并行执行来源适配器。
4. 标准化标题、时间、作者、链接和摘要。
5. 规范化 URL 并计算内容 Hash。
6. 与历史条目去重。
7. 聚合同一事件。
8. 计算热度、写作价值和可信度。
9. 生成热点摘要和候选角度。
10. 写入候选选题池。
11. 汇总每个来源的最终状态。
12. 发送采集完成通知。

### 失败处理

- 单个来源失败：记录失败并继续。
- 网络超时：按来源策略重试，默认最多 2 次。
- 鉴权失败：立即停止该来源并提示更新凭据。
- 内容结构变化：标记适配器异常，不使用猜测字段。
- 全部来源失败：任务进入失败终态并发送通知。

## 3. 选题工作流

### 第一阶段：候选分析

系统自动生成：

- 事件摘要
- 相关来源列表
- 热度分和写作价值分
- 可信度等级
- 可能的读者价值
- 推荐文章类型
- 2～4 个写作角度

### 第二阶段：人工确认

用户必须选择：

- 确认写作
- 暂不处理
- 忽略
- 合并到其他热点

确认写作时可以修改：

- 标题
- 文章角度
- 目标读者
- 作者观点方向
- 需要重点核验的事实

## 4. 事实核验工作流

文章生成前必须先建立证据清单：

```text
陈述 → 来源 → 来源类型 → 支持程度 → 当前状态
```

事实状态：

- 已确认：至少一个可靠一手来源支持。
- 多源支持：多个独立来源支持。
- 待确认：只有二手来源或来源信息不完整。
- 存在冲突：不同来源表述不一致。
- 观点：不应作为客观事实表达。

阻断规则：

- 关键数字没有来源，阻断文章生成。
- 发布时间无法确认，必须使用模糊时间表达或补证。
- 只有社交平台传言，不能写成确定事实。
- 官方来源与媒体说法冲突时，必须在简报中提示用户。
- 产品名称、模型版本、公司名称无法确认时，禁止自动纠正成猜测值。

## 5. 文章生成工作流

1. 读取已确认热点和选题简报。
2. 锁定本次使用的来源快照。
3. 生成文章结构。
4. 人工确认结构和观点方向。
5. 分章节生成原稿。
6. 检查事实、引用、日期、数字和名称。
7. 检查作者观点是否与事实混淆。
8. 转换微信公众号文章。
9. 规划封面和正文插图。
10. 生成图片或预留截图位置。
11. 执行最终审核。
12. 保存文章版本和来源关联。

## 6. 作者观点规范

允许作者观点，但要满足：

- 观点有事实或来源背景支撑。
- 不把推测写成已经发生的事实。
- 不使用“必然”“一定会”“彻底改变”等无依据绝对化表达。
- 文章中明确区分“事实”“来源观点”“作者判断”。
- 对争议事件至少说明主要分歧，不只保留单一立场。

建议提示词中要求模型生成三个独立区块：

```text
已确认事实
来源观点
作者分析与判断
```

最终文章可以自然融合，但审核数据中必须保留这三类信息。

## 7. 公众号审核清单

### 来源与事实

- [ ] 关键事实都有来源。
- [ ] 数字、日期、版本号和产品名准确。
- [ ] 引用来源与正文陈述对应。
- [ ] 未将传言写成事实。
- [ ] 已处理来源之间的冲突。

### 内容价值

- [ ] 不只是重复新闻标题。
- [ ] 解释了为什么值得关注。
- [ ] 对开发者、创业者或从业者至少有一类实际价值。
- [ ] 作者观点清晰但不过度武断。
- [ ] 没有明显标题党表达。

### 时效性

- [ ] 说明事件发生时间。
- [ ] 识别已经过时的信息。
- [ ] 文章中没有把旧版本写成当前版本。
- [ ] 必要时说明信息截至日期。

### 公众号格式

- [ ] 标题适合公众号传播，但不夸大。
- [ ] 摘要单独换行，包含本次热点和读者收益。
- [ ] 正文段落长度适合移动端阅读。
- [ ] 图片提示词与正文分离。
- [ ] 封面图独立，不计入正文配图数量。

## 8. 版本与回溯

每篇热点文章至少保留：

- 原始热点快照
- 选题简报版本
- 人工确认记录
- 文章原稿版本
- 公众号版本
- 来源快照列表
- 审核报告
- 图片资产
- 工作流运行记录

当来源页面更新时，不修改已生成文章所引用的历史快照，只在后续任务中生成新的来源版本。
