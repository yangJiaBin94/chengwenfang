# 热点公众号文章分步生成工作流设计方案

## 1. 目标

将热点文章生产改造成与课程教学模式一致的可观测分步工作流：每个步骤有明确节点、输入输出、Skill 快照、进度、日志、耗时、失败原因和可复用中间产物。

事实可信度、来源评分和冲突识别在素材池阶段完成。文章生成只消费已经确定可用的事实结论，不在成品中展示可信度、评分、冲突状态或核验过程。

## 2. 复用边界

复用课程模式已有的工作流基础设施：

- `WorkflowRun`、`WorkflowNodeRun`、`WorkflowArtifact`；
- 节点开始、完成、失败、耗时和重试记录；
- Prompt 版本、Skill 快照和 SSE 进度；
- 失败恢复、任务取消和文章版本保存。

热点独立维护：

- 选题简报和资料池上下文；
- 热点文章定位和大纲；
- 分段生成；
- 来源引用整理；
- 热点文章成品检查。

不引入课程专属元素：课程目标、前后课衔接、课程小结、学习路线和课程图片数量规则。

## 4. Skill 路由

热点文章使用独立 Skill 快照：

1. 热点上下文理解；
2. 科技资讯文章结构；
3. 公众号叙事与表达；
4. 热点影响分析；
5. 来源引用规范；
6. 成品文章检查。

素材可信度 Skill 只在素材池和资料分析阶段使用，不作为文章写作阶段的摇摆式判断指令。

每个生成节点记录 Skill 名称、版本、内容哈希和整体快照哈希。当前 Skill 系统没有专属热点 Skill 时，先使用热点文章专用 Prompt 快照，后续可平滑迁移到数据库 Skill 目录。

## 5. 节点输入输出

### 5.1 上下文节点

输入：`briefId`、`topicId`、简报版本。

输出：确认简报、来源快照、资料池条目数量、素材快照哈希。

日志示例：`已读取确认简报、8 条来源和 14 条文章素材`。

### 5.2 定位节点

输出包含：目标读者、文章类型、核心问题、主角度、必须回答的问题、结论方向。

不得输出“推荐写作角度”作为成品文章内容。

### 5.3 大纲节点

推荐结构：导语、事件背景、产品或项目解释、实际影响、边界与限制、作者判断、结论、来源附录。

大纲只作为内部产物，不直接保存为文章正文。

### 5.4 分段节点

每一段携带段落目的、可用素材 ID、上一段摘要、下一段目标和字数范围。单段失败只重试当前段。

### 5.5 整合节点

只允许重排、去重、衔接和语言统一，不允许新增素材中不存在的事实。

### 5.6 来源节点

来源只在文末作为引用附录展示来源名称、标题和 URL，不展示评分、可信度和冲突状态。

## 6. 日志和产物

每个节点记录：

- 节点状态、尝试次数、开始时间、结束时间和耗时；
- 输入哈希、输出哈希、输入摘要和输出摘要；
- Prompt 版本、Skill 快照哈希；
- 使用素材数量、输出字数和引用数量；
- 错误码、用户可见错误和内部重试信息。

节点产物必须支持恢复：上下文、定位、大纲、分段、整合稿和引用附录均可从成功产物复用。

## 7. 失败策略

- 上下文读取失败：任务失败；
- Skill 快照失败：任务失败；
- 定位或大纲失败：重试当前节点；
- 单段生成或检查失败：只重试当前段；
- 整合失败：复用已完成分段重新整合；
- 事实一致性失败：阻断保存，并记录后台检查结果；
- 保存失败：保留完整生成产物，允许重新保存。

## 8. 成品约束

文章不得出现：可信度评分、证据分数、来源等级、待核验、冲突证据、素材池、AI 分析、推荐写作角度、建议继续补充资料等内部工作语言。

文章必须具备自然开场、完整叙事、实际影响、明确结论和来源附录；事实复检只在后台记录，不将内部判断标签写入正文。

## 9. 验收标准

1. 生成记录至少出现上述 12 个节点；
2. 每个成功节点都有日志和产物摘要；
3. 分段节点失败时可单独重试；
4. 页面能显示当前节点、进度、耗时和失败原因；
5. 正文不包含内部素材判断语言；
6. 正文关键数字、日期和实体可追溯到来源；
7. 文章版本与简报版本、素材快照和 Skill 快照绑定；
8. 热点专项测试、迁移测试、Ruff 和前端构建通过。
