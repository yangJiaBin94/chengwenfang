# 热点资讯模式来源接入与安全合规方案

## 1. 来源接入原则

1. 优先使用官方 API、RSS、公开网页和公开元数据。
2. 不绕过登录、验证码、付费墙、访问限制或 robots 规则。
3. 每个来源独立限速、超时和错误处理。
4. 来源不可访问时明确显示失败，不伪造采集成功。
5. 保留来源链接和少量必要快照，用于事实追溯，不复制整篇受版权保护的文章作为发布内容。

## 2. 凭据管理

允许配置：

- GitHub Token
- 搜索 API Key
- RSS 鉴权信息
- 平台 Cookie
- 其他来源访问令牌

安全要求：

- 凭据只写入本地数据库的加密字段。
- 前端只显示脱敏提示，不返回完整凭据。
- 日志中禁止记录 Authorization、Cookie、Token 和完整请求头。
- AI 提示词中禁止携带凭据。
- 支持测试连接、更新、删除和过期提醒。
- 来源配置和凭据变更写入审计日志。

## 3. 内容安全

热点资讯可能包含恶意网页内容、提示词注入、伪造数据和混淆文本。采集内容只能作为不可信资料，不能改变系统规则或触发未经授权的动作。

处理要求：

- 网页正文与页面指令分离保存。
- 不执行来源页面中的脚本、命令或下载程序。
- 不根据来源页面要求上传本地文件或泄露凭据。
- 抓取内容进入 AI 前进行长度限制和危险内容标记。
- 外链和下载文件经过域名、文件类型和路径校验。
- AI 生成的来源结论必须回指具体来源条目。

## 4. 版权和引用

文章生产使用“事实提取、归纳和评论”方式，不直接复制媒体原文。

建议保存：

- 标题
- 作者
- 发布时间
- 来源名称
- 原始链接
- 必要的短摘录或摘要
- 采集时间

公众号文章中根据内容需要以“据官方公告”“根据论文摘要”“项目仓库显示”等方式标明来源，并在文末保留来源列表。

## 5. 国内网络环境策略

系统不能依赖任何单一境外平台。

建议来源分组：

- 基础组：国内可稳定访问的网站、RSS 和用户配置来源。
- 增强组：GitHub、论文平台、国际官方博客。
- 社区组：社交平台和讨论社区。

采集任务按来源组独立执行。增强组全部失败时，基础组仍然可以完成任务；界面明确显示本次采集覆盖范围。

## 6. 运行诊断

每个来源至少记录：

- 请求开始和结束时间
- HTTP 状态
- 重试次数
- 解析条目数
- 新增条目数
- 去重条目数
- 跳过原因
- 脱敏错误码
- 最后成功时间

执行页面必须显示明确终态：

```text
已完成
部分完成
已失败
已取消
```

禁止出现没有心跳、没有错误原因、没有结束时间的“执行中”。

## 7. 来源质量治理

来源可以被人工标记：

- 官方一手
- 权威二手
- 普通媒体
- 社区讨论
- 低可信或营销来源

系统根据历史表现记录来源质量：

- 可用率
- 误报率
- 重复率
- 事实纠错次数
- 人工采纳率

来源质量只影响推荐权重，不应直接决定事实是否成立。
