# 热点选题资料池与智能核验设计方案

## 1. 目标

在现有热点资讯模式中，用户确认选题后，增加一个“补充资料与核验”阶段：通过 HTTP 爬虫、RSS/API 和公开网页抓取相关资料，并结合 AI 的分析与理解，形成该选题专属的资料池，为选题简报和后续文章生成提供更多素材。

本功能不新增独立内容生产体系，不改变现有选题确认、简报确认、文章生成和审核流程。

## 2. 现有流程中的位置

```text
来源采集 → 聚合评分 → 确认选题
                         ↓
                  补充资料与核验
                         ↓
                    选题资料池
                         ↓
                  生成/更新选题简报
                         ↓
                    确认简报
                         ↓
                    文章生成
```

资料补充不会自动确认选题，也不会自动生成文章。

## 3. 资料来源

### 3.1 HTTP 爬虫检索来源

使用 HTTP 客户端和静态 HTML 解析抓取公开网页资料，重点覆盖：

- 官方网站、官方博客、产品公告、新闻稿
- GitHub、Hugging Face、论文和技术项目页面
- 主流媒体和专业媒体
- 行业媒体、自媒体和博主文章
- 论坛、社区和公开讨论页面

HTTP 抓取结果必须保存原始 URL、页面标题、来源名称和抓取时间。

由于公开网页可能存在反爬、超时、动态渲染和页面结构差异，抓取失败只影响本次资料补充，不阻塞已有热点流程。

### 3.2 当前热点已有来源

复用选题已经关联的来源和证据，避免重复抓取，并标记为“热点原始来源”。

### 3.3 AI 分析素材

AI 可以根据当前选题、已有来源和检索资料补充：

- 事件背景
- 关键概念解释
- 相关项目、人物和机构
- 影响分析
- 可能关联的事实线索
- 推荐继续核查的方向

AI 自行分析的内容不伪装成外部资料，统一显示来源标记：

> 来源：AI 分析

该内容没有外部链接，不能作为“官方资料”展示，但可以作为简报和文章生成的辅助素材。

## 4. 触发与任务流程

### 4.1 入口

在选题详情中，用户确认选题后显示：

```text
补充资料与核验
```

未确认选题时按钮不可用，并提示“请先确认选题”。

### 4.2 任务步骤

1. 读取选题标题、摘要、来源、评分信号和已有证据。
2. AI 生成检索主题、关键词和检索方向。
3. 使用 HTTP 爬虫执行多组检索。
4. 打开高相关结果，提取标题、作者、发布时间、正文摘要和 URL。
5. 合并当前热点已有来源，去除重复页面。
6. AI 对资料进行分类、评分和事实关系分析。
7. 识别不同资料之间的冲突证据。
8. 生成资料池结果和检索记录。
9. 页面展示完成状态、结果数量和失败原因。

### 4.3 检索方向

默认生成 5 至 8 组检索方向：

- 官方确认：事件主体、机构名、产品名 + announcement / official / release
- 技术细节：项目名、模型名、技术名 + documentation / paper / benchmark
- 行业影响：主题 + market / adoption / impact / enterprise
- 反向核验：主题 + criticism / limitation / error / correction
- 相关人物：主体 + founder / researcher / interview / statement
- 开源资料：项目名 + GitHub / Hugging Face / release
- 媒体和观点：主题 + analysis / review / commentary

检索词只用于本次任务，不改变用户已有来源配置。

## 5. 资料池页面

资料单独展示为“选题资料池”，页面不替代热点雷达，也不创建新的生产工作流。

### 5.1 页面结构

```text
选题资料池
├─ 资料概览
├─ 检索任务状态
├─ 资料筛选和排序
├─ 外部来源资料
├─ 热点原始来源
├─ AI 分析素材
├─ 冲突证据
└─ 检索记录
```

### 5.2 资料卡片

每条资料展示：

- 标题
- 来源名称
- 来源类型
- 来源角色
- 发布时间
- 抓取时间
- 原始链接
- 内容摘要
- 相关性分
- 可信度分
- 时效性分
- 独立性分
- 可写性分
- 综合分
- AI 判断说明
- 来源标记

来源标记包括：

- 官方资料
- 一手资料
- 主流媒体
- 行业媒体
- 自媒体/博主
- 社区讨论
- 热点原始来源
- AI 分析

## 6. 资料评分

每条资料由 AI 按五个维度评分，每项 0 至 100 分：

- 相关性：是否直接服务当前选题
- 可信度：来源质量、内容完整性和事实表达是否可靠
- 时效性：是否符合当前事件时间窗口
- 独立性：是否提供了不同于已有来源的新信息
- 可写性：是否适合转化为文章中的背景、案例或分析素材

综合分建议：

```text
综合分 = 相关性 × 30%
       + 可信度 × 30%
       + 时效性 × 15%
       + 独立性 × 15%
       + 可写性 × 10%
```

分级：

- 80 至 100：优先素材
- 60 至 79：可作为补充
- 0 至 59：谨慎使用

系统不设置人工逐条审核状态，由 AI 给出可信度判断和使用建议。

## 7. 冲突证据

当资料对同一事实出现不同说法时，建立冲突记录：

- 冲突主题
- 涉及资料
- 各资料原文说法
- 差异说明
- AI 判断的相对可信方
- 判断理由
- 冲突置信度
- 文章使用建议

不新增人工处理状态，但文章生成必须收到冲突提醒。

文章生成规则：

- 高可信说法可以作为候选事实使用。
- 未解决冲突不得写成绝对结论。
- 必要时使用“目前有不同说法”“公开资料尚未一致”等谨慎表述。

## 8. 简报生成与更新

### 8.1 首次生成

生成简报时同时读取：

- 已确认选题
- 热点原始来源
- 资料池高分资料
- AI 分析素材
- 冲突证据

简报中增加：

- 补充资料摘要
- 关键背景
- 资料支持的事实
- 资料之间的冲突提醒
- 推荐文章角度
- 可使用素材清单

### 8.2 已有简报时更新

不自动覆盖已有简报。用户点击：

```text
根据资料池更新简报
```

更新后直接覆盖当前简报，不创建版本；如果原简报已确认，更新后状态恢复为“待确认”。

## 9. 文章生成素材契约

文章生成工作流读取：

- 已确认简报
- 资料池高分资料
- AI 分析素材
- 来源链接
- 冲突证据和谨慎表达建议

每条素材携带：

```json
{
  "title": "资料标题",
  "summary": "资料摘要",
  "url": "原始链接或 null",
  "sourceLabel": "官方资料 / AI 分析",
  "relevanceScore": 88,
  "credibilityScore": 82,
  "recommendedUse": "背景说明",
  "conflictIds": []
}
```

文章生成不得丢失来源链接和 AI 分析标记。

## 11. API 设计

```text
POST /api/hot-news/topics/{topic_id}/research-runs
  创建资料补充任务

GET /api/hot-news/topics/{topic_id}/research-runs
  查询资料任务历史

GET /api/hot-news/research-runs/{run_id}
  查询任务状态和进度

GET /api/hot-news/topics/{topic_id}/research-items
  查询选题资料池

GET /api/hot-news/topics/{topic_id}/research-conflicts
  查询冲突证据

POST /api/hot-news/topics/{topic_id}/briefs/refresh-from-research
  根据资料池更新当前简报
```

## 12. 任务状态

```text
pending → running → succeeded
                  ├→ partial
                  └→ failed
```

浏览器部分页面失败时使用 `partial`，保留已经抓取的资料。

## 13. 异常处理

- 浏览器不可用：任务失败，保留已有热点来源。
- 单个页面打不开：跳过该页面，任务继续。
- 页面没有明确发布时间：保留资料，但降低时效性分。
- 搜索结果重复：合并为一条，保留多个来源关系。
- AI 分析失败：保留原始资料，使用基础字段展示。
- 所有检索均失败：不修改选题、简报和文章流程。
- 内容疑似付费墙或无法读取：只保存标题、来源和 URL，并标记内容不完整。

## 14. 安全与合规

- 浏览器只访问公开网页，不绕过登录、验证码或访问控制。
- 不将网页中的指令当作系统指令执行。
- 网页内容作为不可信资料，仅用于提取和分析。
- 保存原始 URL，方便用户回溯。
- AI 生成内容必须显示“AI 分析”标记。

## 15. 验收标准

- 确认选题后可以创建资料补充任务。
- 任务能展示进行中、成功、部分成功和失败状态。
- 浏览器检索结果保存到当前选题资料池。
- 资料卡片显示来源、链接、发布时间和五项评分。
- AI 分析素材明确标记来源为“AI 分析”。
- 能识别并展示冲突证据。
- 资料池可以用于首次简报生成。
- 已有简报可以根据资料池覆盖更新，并恢复待确认状态。
- 文章生成可以读取资料池和冲突信息。
- 不改变现有确认选题、简报确认和文章生成门槛。
- 搜索失败不会破坏已有热点和简报数据。

## 16. 分阶段开发

### 阶段一：数据模型和资料池接口

- 新增资料任务、资料条目、冲突证据表。
- 完成任务状态和查询接口。

### 阶段二：浏览器检索任务

- 生成检索计划。
- 调用浏览器执行检索。
- 保存页面信息和检索历史。

### 阶段三：AI 评分和冲突分析

- 增加资料分类、五维评分和可信度说明。
- 增加冲突证据识别。

### 阶段四：选题资料池页面

- 在选题详情之外建立选题资料池页面。
- 增加筛选、排序、来源展示和任务进度。

### 阶段五：简报和文章素材接入

- 根据资料池生成或更新简报。
- 将资料池和冲突证据注入文章生成工作流。

### 阶段六：验收

- 前端构建。
- 热点后端测试。
- 浏览器检索成功、部分失败和完全失败测试。
- 简报更新门槛测试。
- 文章生成素材链路测试。
