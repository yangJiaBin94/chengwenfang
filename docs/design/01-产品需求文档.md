# 工作台产品需求文档

## 1. 文档状态

- 文档版本：2.0
- 更新日期：2026-07-10
- 项目目录：`D:\work\personal\writer\product\workbench`
- 当前阶段：已完成 React 前端原型和部分本地能力，准备把后端重构为 Python 服务
- 本轮范围：更新产品和技术设计，不实施代码重构

## 2. 产品定位

工作台是一个本地运行的个人内容生产系统。项目不以某个具体学习主题命名，首个业务模块是“自学课程及自媒体内容生成”，首批主题是“0 基础 AI 自学”。

当前知识库项目只作为首批内容的一次性来源。工作台运行时使用自己的内容副本、数据库、配置、任务记录、审核记录和版本历史，不依赖原知识库路径。

工作台要跑通的主链路是：

素材与学习路线 → 课程原稿 → 公众号文章 → 配套图片 → mdnice 排版 → 自动审核 → AI 修复 → 人工审核。

## 3. 用户和使用方式

首版仅供作者本人使用：

- 无登录和权限系统。
- 本地网页访问。
- 数据保存在本机。
- AI 供应商通过 API Key 配置。
- 不做云端同步和多人协作。

## 4. 当前已实现能力

以下能力已经在现有 React 原型中出现，重构后应保留交互和视觉表现：

### 4.1 内容浏览

- 展示学习主题、课程系列和课程列表。
- 展示课程状态、进度、摘要、字数和图片数量。
- 阅读课程原稿和公众号文章全文。
- Markdown 标题、列表、引用、表格、代码和图片渲染。
- 兼容标准 Markdown 图片和 Obsidian 图片语法。

### 4.2 内容编辑

- 课程原稿和公众号文章支持预览、编辑和恢复导入版本。
- 编辑后的内容可在页面中重新渲染。
- 当前编辑内容仍有浏览器本地保存逻辑，后端重构后应迁入数据库。

### 4.3 图片和 mdnice

- 展示文章和课程关联的图片资产。
- 生成 mdnice 可用的 Markdown。
- 支持复制 Markdown 和打开 mdnice。
- mdnice 自动粘贴、主题选择和截图仍属于目标能力，尚未形成完整后端任务。

### 4.4 AI 配置

- 独立配置文本 AI 和图片 AI。
- 配置字段包括供应商名称、模型名称、请求 URL、API Key 和上游协议。
- 文本 AI 支持 OpenAI Chat Completions 和 OpenAI Responses API。
- 图片 AI 按 Codex imagegen CLI 模式调用 OpenAI Image API，固定模型 `gpt-image-2`。
- 图片接口为 `{baseUrl}/images/generations`。
- 配置已写入本地 SQLite，目标架构继续沿用数据库持久化。
- 文本和图片连接测试都是真实上游请求。

### 4.5 自动审核和人工审核

- 展示确定性审核结果、分数、失败项和警告项。
- 审核项区分“文本 AI 可修复”和“需要流程或资产处理”。
- 支持填写人工审核意见、通过、退回和撤销决定。
- 支持文本 AI 自动修复。
- 修复流程要求先备份原文，再替换内容并重新审核。
- 当前版本历史仍有浏览器存储逻辑，重构后必须迁入数据库。

## 5. 重构目标

### 5.1 目标架构

- 前端继续使用 React、Vite 和现有 CSS。
- 页面结构和视觉样式保持不变。
- 后端独立为 Python FastAPI 服务。
- SQLAlchemy 负责数据库访问，Alembic 负责数据库迁移。
- LangChain 负责文本模型、提示词和结构化输出。
- LangGraph 负责生成、修复、复检等多步骤工作流。
- 图片生成直接使用 OpenAI Python SDK Image API，不经过 LangChain Agent。
- 后台任务使用数据库任务表和本地单 worker。
- 前端通过 SSE 接收任务进度。

### 5.2 重构原则

- AI 不直接决定数据库写入和版本保存。
- 确定性规则用普通 Python 实现，不交给模型判断。
- AI 调用不能放在数据库事务中。
- AI 返回有效内容后，数据库事务才保存版本并替换正文。
- 所有任务必须可追踪、可重试、可恢复。
- 上游 HTML、API Key 和后端堆栈不得返回前端。

## 6. 功能范围

### 6.1 总览与课程路线

- 展示课程数量、已审核数量、待处理数量和图片资产数量。
- 按课程系列分组。
- 展示每节课的生产状态。
- 支持选择课程并查看详情。

课程状态统一为：

- `material_ready`
- `draft_generated`
- `article_generated`
- `images_generated`
- `formatted`
- `ai_checked`
- `human_rejected`
- `human_approved`

前端继续显示对应中文状态。

### 6.2 课程原稿

输入：学习路线、课程目标、素材、写作规范、历史样例。

输出：完整课程 Markdown、摘要、插图建议和版本记录。

要求：

- 面向零基础读者。
- 不默认读者掌握技术背景。
- 保留课程完整性。
- 本课小结在下节课预告之前。
- 每次人工编辑、AI 生成或恢复版本都写入数据库版本表。

### 6.3 公众号文章

输入：课程原稿、公众号规范、文章样例。

输出：完整公众号 Markdown、封面提示词和正文插图提示词。

要求：

- 不压缩原稿核心内容。
- 不改变具体含义。
- 标题适配公众号阅读。
- 表格按规范转为列表。
- 不使用 triple-backtick code fence。
- 规范检查忽略 URL 中合法的 `https://`。

### 6.4 图片生成

- 封面图 1 张。
- 正文插图 3 至 5 张。
- 图片 AI 固定使用 `gpt-image-2`。
- 协议为 OpenAI Image API。
- 调用 `/images/generations`。
- 默认参数：`n=1`、`quality=medium`、`output_format=png`。
- 测试连接会真实生成测试图，可能产生费用。
- 图片文件保存后写入 `generated_images`，不得只保留 Base64。

### 6.5 mdnice 自动化

- 使用 Python Playwright。
- 打开 mdnice。
- 粘贴最终 Markdown。
- 选择“我的”标签页下唯一可用主题。
- 等待预览完成。
- 截图并保存路径。
- 失败时保存错误截图和日志。

### 6.6 自动审核

审核分两层：

#### 确定性审核

- 文章是否存在。
- 摘要结构是否完整。
- 禁用符号是否出现，链接目标中的 URL 不参与匹配。
- 是否存在代码围栏。
- 小结和预告顺序。
- 图片引用和图片文件是否存在。
- 图片元数据是否完整。
- mdnice 发布稿和截图是否存在。

#### AI 语义审核

- 事实是否前后矛盾。
- 是否改变课程原稿含义。
- 是否有明显删减、重复或逻辑断裂。
- 是否适合目标读者。
- 标题、摘要和正文是否一致。

AI 审核必须返回结构化结果，不接受无法解析的自由文本。

### 6.7 AI 自动修复

固定流程：

1. 读取当前文章。
2. 执行自动审核。
3. 只提取文本 AI 可修复项。
4. 生成修复提示词。
5. 调用文本 AI。
6. 校验返回的是完整、有效且有变化的 Markdown。
7. 保存修复前版本。
8. 替换文章正文。
9. 保存修复后版本。
10. 重新执行确定性审核和 AI 语义审核。
11. 保存修复前后对比。
12. 返回最新文章和审核报告。

如果 AI 调用失败、内容为空、内容未变化或输出被截断，不得替换原文。

### 6.8 人工审核

- 查看当前文章、图片、mdnice 截图、自动审核报告和版本历史。
- 填写审核意见。
- 审核通过。
- 退回修改。
- 撤销人工决定。
- 恢复历史版本。
- 恢复版本后重新审核。

首轮重构中，人工审核采用普通数据库状态流转；LangGraph 人工中断能力预留到后续阶段。

### 6.9 AI 设置

文本 AI：

- OpenAI Chat Completions。
- OpenAI Responses API。
- 可配置模型、Base URL、API Key、超时和重试次数。

图片 AI：

- OpenAI Image API。
- 固定 `gpt-image-2`。
- 可配置 Base URL、API Key、超时和质量。

配置保存在本地 SQLite。首版允许明文存储 API Key，不上传远程服务。

## 7. 任务和进度

耗时操作都必须创建后台任务：

- 课程原稿生成。
- 公众号文章生成。
- AI 审核。
- AI 修复。
- 图片生成。
- mdnice 自动化。

任务状态：

- `pending`
- `running`
- `waiting_human`
- `succeeded`
- `failed`
- `cancelled`

前端通过 SSE 接收任务进度，不轮询大文本结果。

## 8. 非功能要求

### 8.1 数据安全

- API Key 不写入日志。
- API Key 不返回给非设置接口。
- 日志中的请求头必须脱敏。
- 上游 HTML 页面不得直接显示。
- 文件路径必须限制在工作台目录内。

### 8.2 可靠性

- 文本请求默认 30 秒，可配置。
- 图片请求默认 180 秒。
- 429、502、503 和连接重置可自动重试。
- AI 修复失败不能覆盖原文。
- 服务重启后可恢复未完成任务。

### 8.3 可维护性

- 提示词有版本号。
- 数据库迁移由 Alembic 管理。
- 工作流节点有独立测试。
- 审核规则有固定测试样例。
- LangChain 和 LangGraph 版本必须锁定。

## 9. 暂不实现

- 多用户和权限系统。
- 云端同步。
- 移动端优先适配。
- 发布后阅读量、点赞和收藏分析。
- Redis、Celery 和多 worker 集群。
- 默认启用 LangSmith。
- 通用自主 Agent。

## 10. 验收标准

- 前端视觉与重构前一致。
- 前端不再直接访问 SQLite 或调用上游 AI。
- AI 配置可在服务重启后恢复。
- 图片测试通过 OpenAI Image API 真实生成图片。
- AI 修复失败时原文不变。
- AI 修复成功时数据库存在修复前后版本。
- 修复成功后自动生成新的审核报告。
- 版本恢复后文章和审核结果同步更新。
- 任务进度可通过 SSE 查看。
- Cloudflare HTML、API Key 和 Python堆栈不会出现在页面。
