# 热点雷达日报化适配设计方案

## 1. 适配原则

参考本地 `ai-news-daily-zh` 的日报组织方法，但不直接安装、调用或复制该 skill。热点资讯模式继续使用自己的来源管理、采集任务、聚合评分、证据简报和文章工作区。

吸收的是产品方法，不是运行时协议：

- 按目标日期组织情报，而不是只展示一组持续累积的热点。
- 从较大的候选池中精选少量重点，降低阅读负担。
- 每条情报固定为事实速览和编辑洞察两层。
- 保留来源、发布时间、来源数量和证据状态，保证可追溯。
- 多来源覆盖作为可信度依据，但不把搜索引擎结果数量伪装成全网热度。

## 2. 不直接采用的内容

- 不依赖 SearXNG、Tavily 或 OpenClaw 专有工具。
- 不要求额外 API Key 才能使用热点雷达。
- 不直接复制外部 skill 的系统 Prompt、搜索语句和日报 Markdown 协议。
- 不把飞书卡片作为本地成文坊的输出前提。
- 不把日报精选替换现有 Top20 雷达，精选只是上层阅读视图。

## 3. 适配后的数据来源

日报精选复用现有热点主题：

1. 当前主题当日采集结果。
2. 现有来源健康度和采集覆盖率。
3. 去重后的主题聚合结果。
4. 速度、新鲜度、证据、可信度和写作价值评分。
5. 来源证据和已确认简报。

日报日期以 Asia/Shanghai 为准。没有明确发布时间的来源只能参与候选池，不应单独作为高优先级精选依据。

## 4. 精选规则

第一版采用确定性规则：

- 候选范围：当日 Top20 热点。
- 精选数量：默认 7 条，允许 5 至 9 条的产品配置扩展。
- 排序：写作价值、速度、新鲜度、证据完整度、可信度依次参与排序。
- 去重：沿用现有主题聚合，不重复展示相同事件。
- 分类：政策监管、模型发布、开源技术、商业资本、行业应用。
- 缺少战略级情报时不强行补足，明确显示“今日精选不足”。

## 5. 单条展示结构

每条精选统一展示：

- 序号和中文标题。
- 分类、来源数量、新鲜度。
- 速览：只描述已采集事实。
- 洞察：解释速度、证据或写作价值带来的行动建议。
- 写作价值和证据/简报入口。

洞察不是 AI 编造的行业结论。第一版由评分信号生成可解释提示，后续在确认选题后再结合简报生成更深入洞察。

## 6. 与现有流程的关系

```text
来源采集 → 去重聚合 → Top20 评分雷达
                         ├→ 今日情报精选 7 条
                         └→ 人工确认 → 事实简报 → 独立文章工作区
```

日报精选不绕过确认选题、事实简报、事实复检和人工审核，也不直接生成文章。

## 7. 后续增强

- 增加日期选择和历史日报查看。
- 增加来源组覆盖和缺口提示。
- 将精选卡片保存为日报快照，支持复盘。
- 在确认简报后把事实速览替换为经过来源约束的编辑洞察。
- 未来如接入外部搜索引擎，只作为来源渠道适配器，不改变本地主题、评分和审核模型。
