## 2. 改造目标

将现有课程相关功能从成文坊全局区域中独立出来，纳入固定的“课程体系教学模式”。

当前已有的“0 基础 AI 自学”调整为该模式下的一个主题。课程系列、课程路线、课程、文章及其生成过程均属于该主题，不再视为全局唯一内容。

本次改造需要满足：

1. 模式作为业务功能的一级边界。
2. 主题作为课程内容的二级边界。
3. 当前模式固定为“课程体系教学模式”，不提供模式管理页面。
4. 当前主题固定为“0 基础 AI 自学”，需要展示主题卡片，但暂不提供新增、编辑或删除入口。
5. 首页、设置、通知和 Skill 管理仍属于全局功能。
6. Skill 仍只在工作流节点上绑定，不新增模式级或主题级绑定。
7. 工作流归属于“课程体系教学模式”，暂时隐藏新增工作流按钮。
8. 现有课程和运行历史完整迁移到当前模式及主题，不丢失版本和关联关系。

## 3. 核心概念

### 3.1 模式

模式代表一套独立的内容生产与管理场景。

当前系统只存在一个固定模式：

```text
名称：课程体系教学模式
编码：course_system
状态：启用
```

本阶段模式直接写入系统初始化数据和左侧菜单，不建设模式列表、模式创建、模式编辑、模式停用等管理功能。

### 3.2 主题

主题是课程体系教学模式下的一套独立教学内容集合。

当前主题：

```text
名称：0 基础 AI 自学
编码：ai_self_study_zero
所属模式：课程体系教学模式
状态：启用
```

主题包含：

- 课程系列
- 课程路线
- 课程及课程安排
- 课程原稿
- 公众号文章
- 插图与图片资源
- 文章审核与修复记录
- 课程生成任务及执行记录

本阶段只展示主题卡片，不提供新增、编辑、复制、停用或删除主题的入口。

### 3.3 内容层级

```text
课程体系教学模式
└── 0 基础 AI 自学
    ├── 课程系列
    │   └── 课程
    ├── 课程路线
    ├── 课程原稿
    ├── 公众号文章
    ├── 插图
    ├── 审核与修复记录
    └── 生成任务与执行记录
```

## 4. 信息架构

### 4.1 全局功能

以下功能不属于任何模式或主题，其配置和数据全局生效：

- 首页
- Skill
- 设置
- 通知中心
- 全局运行状态

切换或进入模式不会改变全局设置，也不会复制全局配置。

### 4.2 模式内功能

以下功能归属于课程体系教学模式：

- 模式总览
- 主题展示
- 课程路线
- 课程系列与课程
- 课程内容与文章
- 工作流

课程类页面还必须限定到当前主题“0 基础 AI 自学”。工作流只限定到模式，不限定到主题。

### 4.3 左侧导航

建议导航结构：

```text
首页

课程体系教学模式
  模式总览
  课程路线
  课程内容
  工作流

Skill
设置
```

“课程体系教学模式”作为固定分组直接显示在左侧菜单栏，不提供模式管理入口。

模式分组应具备明确的视觉层级，避免用户误认为“课程体系教学模式”是普通页面。

## 5. 页面设计

### 5.1 首页

首页仍是全局首页，不归属于课程体系教学模式。

首页需要展示模式入口卡片：

```text
课程体系教学模式
围绕主题组织课程系列、课程路线和内容生成

当前主题：0 基础 AI 自学
```

点击卡片进入模式总览。

首页不提供：

- 新增模式
- 编辑模式
- 新增主题
- 编辑主题

### 5.2 模式总览

模式总览顶部显示：

```text
课程体系教学模式
围绕主题规划、生成和维护系列课程内容
```

页面必须展示主题区域，即使当前只有一个主题。

主题卡片建议内容：

```text
0 基础 AI 自学
面向零基础学习者的系统化 AI 自学课程

课程系列：实际数量
课程数量：实际数量
生成进度：按现有课程状态计算
```

主题卡片点击后进入该主题的课程内容或主题概览。卡片上不出现新增、编辑和删除按钮。

### 5.3 课程路线

页面标题继续使用：

```text
课程路线
```

标题上方或紧邻标题的位置显示只读上下文：

```text
课程体系教学模式 / 0 基础 AI 自学
```

课程路线中的所有系列、课程排序和课程安排均属于当前主题。

页面不再使用“当前模块”“主题：0 基础 AI 自学”等容易混淆层级的旧表达。

### 5.4 课程内容与文章

课程列表、课程详情、课程原稿、公众号文章、审核、修复和配图页面均显示相同上下文：

```text
课程体系教学模式 / 0 基础 AI 自学
```

内容查询必须由当前主题约束，不能仅按课程 ID 或系列名称推断归属。

### 5.5 工作流

工作流归属于“课程体系教学模式”，当前可固定此归属。

工作流页面顶部显示：

```text
课程体系教学模式 / 工作流
```

本阶段：

- 隐藏“新增工作流”按钮。
- 隐藏新增工作流弹窗的所有入口。
- 保留已有工作流的查看、编辑、发布、启停、版本、测试、运行记录和指标功能。
- 保留后端创建能力，不删除创建接口和数据模型。
- 不增加主题级工作流归属。

工作流的场景字段继续用于区分具体用途，例如课程内容生成、文章审核修复和插图生成。

## 6. Skill 设计

### 6.1 绑定原则

Skill 仍只允许在工作流节点上绑定。

本次不增加：

- 模式级 Skill 绑定
- 主题级 Skill 绑定
- 主题默认 Skill
- 自动绑定作者风格 Skill

### 6.2 Skill 列表中的应用范围

Skill 页面属于全局页面，但需要展示每个 Skill 的实际应用位置。

建议展示格式：

```text
应用位置
课程体系教学模式 / 课程内容生成工作流 / 原稿生成节点
```

同一个 Skill 绑定到多个节点时，展示全部实际绑定：

```text
课程体系教学模式
· 课程内容生成工作流 / 原稿生成
· 公众号转换工作流 / 文章审校
```

如果 Skill 未绑定任何节点，显示：

```text
未应用
```

系统级只读 Skill 也应显示其实际注入的工作流和节点，不能仅显示“全局”。

### 6.3 数据来源

Skill 的应用位置必须从已发布工作流版本和节点绑定关系中计算，不单独维护一份容易失真的应用范围文本。

草稿绑定可以在 Skill 详情中标记为“待发布”，但不计入正式生效范围。

## 7. 数据模型设计

### 7.1 模式表

建议新增 `content_modes`：

| 字段 | 说明 |
|---|---|
| id | 稳定主键 |
| code | 唯一编码，当前为 `course_system` |
| name | 课程体系教学模式 |
| description | 模式说明 |
| status | enabled / disabled |
| sort_order | 排序 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

虽然当前模式写死，仍建议落库，以便业务数据建立稳定外键，并为后续新增模式保留结构。

### 7.2 主题表

建议新增 `content_themes`：

| 字段 | 说明 |
|---|---|
| id | 稳定主键 |
| mode_id | 所属模式 |
| code | 唯一编码，当前为 `ai_self_study_zero` |
| name | 0 基础 AI 自学 |
| description | 主题说明 |
| status | enabled / disabled |
| sort_order | 排序 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

本阶段不提供主题写接口，只提供内部初始化和只读查询。

### 7.3 业务数据归属

建议直接增加 `theme_id` 的核心数据：

- 课程系列
- 课程
- 课程路线或课程排序配置

通过课程关系可可靠推导主题的数据，不重复保存 `theme_id`：

- 课程原稿
- 公众号文章
- 文章版本
- 审核与修复记录
- 图片资源
- 课程生成任务

如果当前任务表允许脱离课程运行，则需要同时增加 `mode_id` 和可空的 `theme_id`，避免仅靠元数据 JSON 判断。

### 7.4 工作流归属

工作流增加或固定以下归属：

```text
mode_id = 课程体系教学模式
scene = 具体工作流场景
```

当前不增加 `theme_id`。工作流可以被该模式下的主题复用，运行时由课程或任务上下文确定主题。

## 8. 路由设计

全局页面：

```text
/
/skills
/settings
/notifications
```

模式页面：

```text
/modes/course-system
/modes/course-system/workflows
/modes/course-system/workflows/:workflowId
```

主题页面：

```text
/modes/course-system/themes/ai-self-study-zero
/modes/course-system/themes/ai-self-study-zero/route
/modes/course-system/themes/ai-self-study-zero/courses
/modes/course-system/themes/ai-self-study-zero/courses/:courseId
```

即使当前模式和主题固定，URL 仍显式携带上下文，便于以后扩展多个主题或模式。

旧地址应提供兼容跳转，不能让用户保存的课程链接直接失效。

## 9. API 设计原则

### 9.1 只读模式和主题接口

本阶段仅需要：

```text
GET /api/modes
GET /api/modes/{mode_id}
GET /api/modes/{mode_id}/themes
GET /api/themes/{theme_id}
```

不提供模式或主题的 POST、PUT、PATCH、DELETE 接口。

### 9.2 主题内内容查询

课程路线和课程列表需要显式传入或从路径获得主题：

```text
GET /api/themes/{theme_id}/courses
GET /api/themes/{theme_id}/route
GET /api/themes/{theme_id}/series
```

单项详情接口仍应在后端验证资源是否属于当前主题，防止跨主题访问。

### 9.3 Skill 应用位置

Skill 返回结果建议增加从工作流绑定关系计算出的应用信息：

```json
{
  "applications": [
    {
      "modeId": "course-system",
      "modeName": "课程体系教学模式",
      "workflowId": "course-content-generation",
      "workflowName": "课程内容生成",
      "nodeKey": "draft-generation",
      "nodeName": "原稿生成",
      "bindingState": "published"
    }
  ]
}
```

## 10. 历史数据迁移

### 10.1 迁移目标

当前全部课程相关历史数据迁移到：

```text
模式：课程体系教学模式
主题：0 基础 AI 自学
```

当前全部工作流迁移到：

```text
模式：课程体系教学模式
```

### 10.2 迁移范围

必须覆盖：

- 课程系列
- 课程及课程顺序
- 课程安排和推荐配置
- 课程原稿及全部版本
- 公众号文章及全部版本
- 审核记录和审核问题
- AI 修复记录
- 插图、封面和图片元数据
- 课程生成任务
- 工作流运行记录
- 通知记录中的课程关联
- 工作流及其版本、草稿、节点和 Skill 绑定

### 10.3 迁移要求

1. 使用数据库迁移脚本完成，不依赖前端首次打开页面补数据。
2. 先创建固定模式和固定主题，再回填现有数据。
3. 不修改原有课程、文章、任务和版本主键。
4. 不重建文章版本，不改变版本号和内容 Hash。
5. 不删除无法立即归类的数据，应记录迁移异常并停止迁移。
6. 迁移完成后再为必要字段增加非空约束。
7. 重复执行迁移不得创建重复模式或主题。
8. 迁移前后课程、文章、图片、任务和工作流数量必须一致。

### 10.4 数据校验

迁移完成后至少校验：

```text
原课程系列数 = 新主题下课程系列数
原课程数 = 新主题下课程数
原文章数 = 可通过新主题课程关联得到的文章数
原文章版本数 = 迁移后文章版本数
原图片数 = 迁移后图片数
原工作流数 = 新模式下工作流数
原工作流版本数 = 迁移后工作流版本数
```

同时抽查：

- 课程路线顺序未变化
- 当前文章版本未变化
- 图片仍能显示
- 审核记录仍可查看
- 旧生成任务仍可进入执行详情
- Skill 的工作流节点绑定未变化

## 11. 状态与上下文规则

1. 当前模式固定为“课程体系教学模式”。
2. 当前主题固定为“0 基础 AI 自学”。
3. 模式内课程页面必须同时获得有效的模式和主题上下文。
4. 工作流页面只要求模式上下文。
5. 首页、Skill、设置和通知不得依赖当前主题才能打开。
6. 页面刷新后根据 URL 恢复上下文，不依赖临时前端状态。
7. 访问旧课程地址时自动跳转到包含模式和主题的新地址。
8. 如果上下文与资源真实归属不一致，显示资源不存在或无权访问，不静默切换主题。

## 13. 验收标准

### 13.1 导航与页面

- 左侧菜单明确显示“课程体系教学模式”。
- 不存在模式管理入口。
- 首页展示课程体系教学模式入口。
- 模式总览始终展示“0 基础 AI 自学”主题卡片。
- 不存在新增主题按钮。
- 课程路线页面标题仍为“课程路线”。
- 课程路线顶部显示“课程体系教学模式 / 0 基础 AI 自学”。
- 课程和文章页面显示相同上下文。

### 13.2 工作流

- 工作流页面显示“课程体系教学模式 / 工作流”。
- “新增工作流”按钮和弹窗入口不可见。
- 已有工作流仍可正常查看、编辑、发布、测试和运行。
- 工作流场景仍能区分具体用途。

### 13.3 Skill

- Skill 仍只能在工作流节点配置。
- Skill 列表能展示实际应用的模式、工作流和节点。
- 未绑定的 Skill 显示“未应用”。
- 不出现模式级或主题级 Skill 绑定控件。

### 13.4 数据

- 所有历史课程数据归属于“0 基础 AI 自学”。
- 所有已有工作流归属于“课程体系教学模式”。
- 迁移前后核心数据数量一致。
- 课程路线顺序、文章当前版本、历史版本、图片、审核、任务记录均未丢失。
- 全局设置不因进入模式或主题而改变。

### 13.5 回归

- 课程生成能读取当前主题的课程安排。
- 字数和插图数量推荐仍与当前课程对应。
- 文章审核、AI 修复和图片生成正常运行。
- 通知能够跳转到迁移后的课程或任务页面。
- 旧链接能够兼容跳转到新地址。

## 14. 推荐实施顺序

1. 新增模式、主题数据结构和初始化数据。
2. 编写并验证历史数据迁移。
3. 调整后端查询边界和资源归属校验。
4. 调整前端路由与左侧菜单。
5. 增加模式总览和主题卡片。
6. 为课程页面增加模式与主题上下文。
7. 为工作流增加模式归属并隐藏新增入口。
8. 在 Skill 页面展示工作流节点应用位置。
9. 完成旧路由兼容和全流程回归测试。

实施时应优先保证数据迁移和查询隔离，再调整页面展示，避免出现界面已分主题但底层数据仍全局混用的中间状态。
