# 热点资讯模式开发实施与验收计划

## 1. 开发边界

本阶段只新增“热点资讯模式 / AI 热点前沿”的产品和技术能力，不修改课程体系教学模式的课程内容、文章、版本和历史任务。

复用现有能力：

- 模式与主题模型
- 工作流定义和节点 Skill 绑定
- 后台任务、SSE、重试和执行轨迹
- 文章、文章版本和审核
- 图片生成和图片资产
- 公众号原生排版
- 站内通知

新增能力：

- 来源配置和凭据
- 手动采集任务
- 来源适配器
- 原始条目标准化
- 热点聚合
- 热度与写作价值评分
- 选题确认
- 选题简报
- 来源与文章关联
- 事实证据和时效性审核

## 2. 阶段计划

### 阶段 1：模式和主题骨架

- 新增固定模式和主题。
- 左侧新增热点资讯模式入口。
- 新增主题总览和热点雷达空状态。
- 建立主题上下文和权限边界。

验收：课程模式页面和历史课程数据无回归；热点模式可以独立进入。

### 阶段 2：来源管理

- 来源渠道表和配置界面。
- RSS、网页和 GitHub 三类适配器。
- 凭据保存、脱敏、测试和删除。
- 来源启停、优先级、可信等级和关键词配置。

验收：每个来源可以单独测试；凭据不出现在页面、日志和 API 响应中。

### 阶段 3：手动采集

- 开始采集按钮。
- 来源并行执行。
- 子任务进度和错误。
- 采集结果持久化。
- 成功、部分成功和失败通知。

验收：一个来源失败不会阻塞其他来源；刷新页面后可以继续查看任务终态。

### 阶段 4：热点聚合与评分

- URL 和内容去重。
- 相似事件聚合。
- 热度、写作价值和可信度评分。
- 候选选题列表。
- 忽略、暂缓、合并和人工修正。

验收：相同事件不重复展示；评分有理由；人工修改可追溯。

### 阶段 5：选题简报与确认

- 事件时间线。
- 事实、观点、传言分类。
- 证据来源。
- 推荐写作角度。
- 作者观点输入。
- 简报确认阻断。

验收：未确认简报不能进入文章生成；关键事实缺证时明确阻断。

### 阶段 6：公众号文章生成

- 复用分步文本生成工作流。
- 支持文章类型、字数和正文配图设置。
- 事实、来源和作者观点检查。
- 公众号转换、配图和排版。
- 文章版本、来源快照和执行轨迹。

验收：文章可以回溯到热点、简报、来源和工作流节点；生成失败进入明确终态。

### 阶段 7：质量与运营反馈

- 热点过期识别。
- 来源质量统计。
- 选题采纳率。
- 文章审核退回原因。
- 每日人工查看摘要。

本阶段暂不自动调节评分权重，只先采集反馈数据。

## 3. 测试计划

### 后端测试

- 模式主题初始化和历史数据隔离。
- 来源配置字段校验。
- 凭据脱敏和日志过滤。
- URL 规范化和内容 Hash 去重。
- 同一事件聚合。
- 评分边界和理由生成。
- 部分来源失败的任务终态。
- 任务租约、超时和重试。
- 选题确认阻断。
- 来源快照与文章版本关联。
- 事实冲突阻断。

### 前端测试

- 模式导航和主题上下文。
- 手动采集确认弹窗。
- 来源状态、进度和错误展示。
- 热点筛选、排序和详情。
- 选题确认、忽略和暂缓。
- 简报确认阻断。
- 文章生成状态和通知跳转。
- 桌面端和 390px 窄屏无溢出。

### 真实验收

至少准备以下场景：

1. 三个来源成功并聚合为一个热点。
2. 一个来源超时，其他来源仍完成。
3. 同一热点重复采集后不产生重复候选。
4. 只有二手来源时被标记为待核验。
5. 关键事实冲突时阻止文章生成。
6. 人工确认选题和简报后生成公众号文章。
7. 文章生成失败后通知用户并支持查看原因。

## 4. 待确认的后续产品选项

以下不影响文档进入开发准备，但开发前需要确定：

1. 第一批具体来源名单和每个来源的优先级。
2. 热点雷达默认展示最近 24 小时、3 天还是 7 天。
3. 是否允许手动粘贴一个链接作为热点来源。
4. 作者观点是在简报阶段填写，还是在文章生成前填写。
5. 公众号文章是否需要显示完整来源列表，还是只保留文末引用。
6. 采集任务是否允许用户选择来源，还是默认采集全部已启用来源。
7. 是否需要支持热点合并后的人工改标题。

## 5. 推荐的第一版默认值

如果没有额外调整，建议采用：

```text
首批来源：官方 RSS/博客 + GitHub + 论文元数据 + 2 个国内资讯来源
采集范围：最近 72 小时
触发方式：用户手动点击
选题确认：必须人工确认
简报确认：必须人工确认
文章平台：微信公众号
文章风格：事实清晰 + 有依据的作者分析
失败策略：允许部分成功，禁止无限等待
```
