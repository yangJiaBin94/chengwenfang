# 热点资讯模式文章生产工作区与工作流设计方案

## 1. 设计结论

课程模式与热点模式是同一套内容生产系统的两个入口。课程从既定课程安排进入，热点从热点雷达完成选题、资料深挖和简报确认后进入。

进入文章生产后，两种模式共用页面框架、生成配置、任务状态、编辑器、版本、审核、排版和执行轨迹。两种模式分别提供生成上下文、Skill、节点实现、节点职责和业务审核规则。

开发不得继续在 HotNewsArticleWorkspace 中平行复制课程详情功能。应抽取课程详情页通用能力，通过模式适配器接入课程和热点。

## 2. 范围

### 2.1 本期实现

- 热点原稿、公众号文章、配套图片、公众号排版、审核、版本和执行记录。
- 完整生成、重新生成原稿、重新生成公众号文章、重新生成配图和重新审核。
- 正文字数、正文插图数量及推荐配置。
- 热点专属 Skill、工作流节点、自动审核和失败恢复。
- 兼容现有热点文章、版本、审核和发布快照。

### 2.2 本期不做

- 公众号真实发布，只保留富文本、HTML 和不可变排版快照。
- 新增外部搜索能力、独立日报模块和操作截图。
- 课程路线、课次、上下节课、教学目标和课程预告。
- 在公众号正文中展示事实可信度、证据评分、冲突状态或内部判断过程。

## 3. 完整业务流程

热点雷达采集与评分 -> 选择热点 -> 资料深挖与资料池 -> AI 处理来源、冲突和可用边界 -> 生成并确认选题简报 -> 创建文章草稿壳 -> 配置字数和插图 -> 生成热点原稿 -> 自动审核原稿 -> 生成公众号文章 -> 自动审核公众号文章 -> 规划并生成配图 -> 自动审核图片 -> 最终检查 -> 保存 AI 版本 -> 人工审核 -> 公众号排版 -> 生成快照或导出。

简报确认是文章生产入口门禁，不等于文章已经生成。事实选择在资料池和简报阶段完成；文章生成只检查产物是否忠实使用已确定材料。

## 4. 共享与差异边界

| 能力 | 课程模式 | 热点模式 | 处理方式 |
| --- | --- | --- | --- |
| 内容入口 | 固定课程安排 | 热点雷达确认选题 | 各自实现 |
| 生成上下文 | 课程路线、课次目标、课程资料 | 简报、资料池、来源快照、文章角度 | 适配器输出统一快照 |
| 页面与交互 | 内容详情工作区 | 同一内容详情工作区 | 直接复用 |
| 生成配置 | 字数、插图数量 | 字数、插图数量 | 直接复用 |
| 任务基础设施 | Job、进度、取消、重试、恢复 | 同一基础设施 | 直接复用 |
| 生产阶段 | 原稿、公众号、配图、审核、排版、版本 | 相同 | 统一阶段协议 |
| Skill | 教学策划、课程写作 | 热点理解、资讯写作 | 各自绑定 |
| 节点职责与审核 | 教学准确性和可学性 | 事实保真和资讯价值 | 各自实现 |

## 5. 页面设计

### 5.1 路由和入口

- /modes/hot-news/topics/:topicId/articles/:articleId：热点文章详情页。
- /modes/hot-news/articles/:articleId/execution：热点文章执行记录页。

首次生成由已确认简报创建文章草稿壳和任务，随后进入文章详情页。详情 Tab 使用页面状态或查询参数，不复制多套页面。

### 5.2 顶部和主 Tab

顶部展示热点标题、摘要、状态、评分、来源数、简报版本、生命周期、生成按钮、字数/插图配置和任务进度。不展示课程课次和课程路线。

主 Tab 顺序：

1. 热点原稿
2. 公众号文章
3. 配套图片
4. 公众号排版
5. 审核
6. 版本

热点资料池、来源、冲突证据和简报通过顶部“热点资料”入口或辅助面板访问。

### 5.3 内容工作区

- 左侧：生成记录、来源快照、自动审核、人工审核、候选稿和版本摘要。
- 中间：当前原稿或公众号文章的 Markdown 编辑器。
- 右侧：当前内容渲染预览；排版 Tab 使用 mdnice 主题预览。
- 有未保存修改时，禁用依赖已保存内容 hash 的审核、配图和排版。

## 6. 领域模型与兼容迁移

### 6.1 文章与双内容

HotNewsArticle 作为文章聚合根，承载选题、简报、状态和当前版本。新增 hot_news_article_contents：

- article_id
- content_type：draft 或 wechat
- content
- content_hash
- word_count
- updated_at

兼容期内，原 HotNewsArticle.content 映射为当前 wechat 内容。旧文章迁移时把旧 content 写入 wechat，但不伪造 AI 原稿。原稿 Tab 显示“历史文章无原稿记录”，用户可选择以当前公众号文章初始化原稿。

### 6.2 生成配置

热点生成偏好与课程使用相同枚举：

- word_count_option
- image_count_option
- recommended_word_count_option
- recommended_image_count_option
- recommendation_reason

配置保存到文章草稿壳；任务启动时冻结到 Job 和版本快照。

### 6.3 完整版本快照

一个正式版本代表一次完整文章状态，保存原稿、公众号文章、两者 hash、图片清单、简报/资料/来源版本、生成配置、Skill/工作流/模型快照、workflow_run_id、版本原因和创建时间。

手工保存也创建文章版本，并标记变更来源和受影响内容类型。

## 7. 统一阶段协议

| 阶段 | 含义 |
| --- | --- |
| prepare | 冻结上下文并加载 Skill |
| draft | 策划并生成原稿 |
| draft_review | 自动审核原稿 |
| wechat | 生成公众号文章 |
| wechat_review | 自动审核公众号文章 |
| images | 规划并生成图片 |
| images_review | 自动审核图片和引用 |
| final | 最终完整性检查 |
| persist | 原子保存正式版本并完成任务 |

课程和热点节点通过 stage_key 映射到统一阶段。页面展示统一阶段，同时展示真实模式的节点名称、职责、Skill 和审核结果。

## 8. 热点专属 Skill

| Skill | 作用 | 主要节点 |
| --- | --- | --- |
| 热点上下文理解 | 理解主体、时间、产品或技术对象和简报边界 | 上下文、事实包 |
| 热点文章策划 | 确定新闻价值、读者问题、文章类型和角度 | 定位、结构 |
| 热点资讯原稿生成 | 基于事实包生成完整原稿 | 原稿生成 |
| 热点文章审校 | 检查事实、主体、时间线、归因和边界 | 两次文本审核 |
| 热点公众号转换 | 将已审校原稿转换为移动端成品 | 公众号生成 |
| 热点配图规划 | 选择需要可视化的内容和插图位置 | 配图规划 |
| 图片生成与检查 | 生成并检查文件、裁切、引用和匹配 | 图片节点 |
| 热点完稿规范 | 检查标题、结构、来源、格式和完整性 | 最终检查 |

课程专属 Skill 不绑定热点节点。通用 Markdown、作者风格、mdnice 排版和文件检查 Skill 可以共用。

## 9. 热点工作流节点

| 顺序 | 节点 | 阶段 | 职责与门禁 |
| --- | --- | --- | --- |
| 1 | hot_news_load_context | prepare | 冻结确认简报、资料池、来源和配置；简报未确认或来源为空则阻断 |
| 2 | hot_news_load_skills | prepare | 固定 Skill、提示词、模型和工作流版本；必需 Skill 不可用则阻断 |
| 3 | hot_news_prepare_facts | prepare | 整理事实、时间线、归因、数字和边界；冲突无采用结论则阻断 |
| 4 | hot_news_define_positioning | draft | 确定读者价值、核心问题、角度和主要判断 |
| 5 | hot_news_plan_draft | draft | 规划导语、事件、变化、影响、限制、判断、结论和插图位置 |
| 6 | hot_news_generate_draft | draft | 生成完整热点原稿，不输出提纲、建议或内部提示 |
| 7 | hot_news_review_draft | draft_review | 检查原稿事实、归因、时间线、材料覆盖和结构 |
| 8 | hot_news_generate_wechat | wechat | 仅基于已审校原稿生成公众号成品，不新增事实 |
| 9 | hot_news_review_wechat | wechat_review | 检查原稿保真、标题导语、移动端表达和内部内容清理 |
| 10 | hot_news_plan_images | images | 按配置规划封面和正文图的位置、目标、提示词和替代文本 |
| 11 | hot_news_generate_images | images | 生成封面和指定数量正文图，单图失败独立重试 |
| 12 | hot_news_validate_images | images_review | 检查数量、重复、连续图片、裁切、上下文和路径 |
| 13 | hot_news_final_validation | final | 检查审核、产物、配置、来源和 hash 关联 |
| 14 | hot_news_commit_version | persist | 条件写入完整版本并更新任务终态，只能作为终点 |

历史节点保留别名映射。新任务不得用同一个 hot_news_generate_sections 产物同时充当原稿和公众号文章。

## 10. 自动审核规范

### 10.1 原稿审核

- 是完整文章，不是提纲、写作建议或内部分析报告。
- 与确认选题、文章角度、事实包和来源快照一致。
- 事件、主体、产品、数字、时间线和因果关系准确。
- 官方表述、媒体报道、作者判断和 AI 分析归因清楚。
- 使用简报已确定的冲突结论，不重新摇摆。
- 能回答发生了什么、为何重要、对谁有影响。
- 关键材料有合理承载，章节不重复。
- 不出现可信度分数、审核规则、工作流术语、模型说明或插图提示词。

事实错误、主体混淆、时间线错误、无依据数字、关键材料遗漏和非完整文章均为阻断项。

### 10.2 公众号文章审核

- 标题准确、简短、可理解，不夸大、不标题党。
- 导语能快速说明是什么、做什么和为何重要。
- 与原稿的事实、数字、归因、边界和结论一致。
- 是可直接排版的成品，不是写作建议或半成品。
- 段落、小标题、列表和重点适合移动端阅读。
- 来源可追溯但不堆砌证据报告，不引入原稿外事实。
- 无事实分数、审核说明、Skill 名称、提示词或操作截图说明。
- Markdown 有效，字数处于目标区间，无重复内容。

事实漂移、标题误导、内部内容泄露、结构无效和字数严重偏离均为阻断项。

### 10.3 图片审核

- 封面与正文图分开计数，正文图数量等于配置。
- 图片符合文章上下文，不强制包含文字。
- 不使用无关图、重复图或为凑数量生成的图。
- 不允许连续两个图片块，中间必须有相关正文。
- 关键主体和图形不被裁切。
- 文件可访问，数据库关联与 Markdown 路径一致。
- 公众号正文不保留图片提示词。

## 11. 自动审核、版本、人工审核与排版顺序

生成工作流内的自动审核针对节点临时产物。全部自动审核和最终检查通过后，节点 14 才保存新的 AI 正式版本。

人工审核针对已保存版本：

- 自动审核通过且内容 hash 与报告一致，才允许人工通过。
- 退回必须填写意见，可创建热点修订任务或手工编辑。
- 内容修改后，原自动审核和人工审核失效。
- 人工通过锁定当前公众号内容 hash，之后才允许进入公众号排版。
- 切换主题或生成排版快照不改变文章内容版本。

正式顺序是：自动审核 -> 保存 AI 版本 -> 人工审核 -> 公众号排版。

## 12. 生成操作、重试与恢复

| 用户操作 | 执行范围 | 前置条件 |
| --- | --- | --- |
| 生成完整内容 | 节点 1-14 | 简报已确认 |
| 重新生成热点原稿 | 节点 3-7，保存原稿候选或版本 | 已有文章草稿壳 |
| 重新生成公众号文章 | 节点 8-9，相关终检后保存版本 | 原稿已保存且审核通过 |
| 重新生成配图 | 节点 10-12，相关终检后保存版本 | 公众号文章已保存且审核通过 |
| 重新自动审核 | 节点 7、9、12、13 | 对应产物已保存 |

- 单步任务记录跳过节点，不伪造成功状态。
- 失败从失败热点节点恢复，不从热点采集或课程原稿重新开始。
- 每个节点记录输入 hash、输出摘要、attempt、耗时、Skill 快照和错误。
- 上游 hash 变化时，下游审核、图片和人工审核失效。
- 图片按单图记录，成功图片可复用，失败图片独立重试。
- 同一文章同一任务类型只允许一个活动任务。
- 服务重启依据租约和检查点恢复；版本节点条件写入，避免重复版本。

## 13. 状态与交互门禁

- 简报未确认：不能创建文章草稿壳或启动生成。
- 原稿未保存或未通过自动审核：不能生成公众号文章。
- 公众号文章未保存或未通过自动审核：不能生成配图或提交人工审核。
- 图片未通过：完整任务不能完成，但可查看正文和失败原因。
- 有未保存修改：禁用审核、配图和排版。
- 人工审核未通过或已失效：不能进入公众号排版。
- 任务执行中：展示当前节点、进度、下一步和轨迹入口，禁止重复提交同类任务。

## 14. API 设计

### 14.1 首次生成

首次生成时没有 articleId，由简报接口创建文章草稿壳和 Job：

- POST /api/hot-news/briefs/:briefId/articles
- 请求包含字数和插图配置。
- 响应包含 articleId 和 jobId。
- 使用幂等键防止重复点击创建多篇文章。

### 14.2 文章详情与单步任务

- GET /api/hot-news/articles/:id/detail
- PATCH /api/hot-news/articles/:id/contents/:contentType
- GET/PATCH /api/hot-news/articles/:id/generation-settings
- POST /api/hot-news/articles/:id/generation-runs，请求参数 scope 为 full、draft、wechat、images 或 audit
- GET /api/hot-news/articles/:id/execution

所有生成接口返回统一 Job，沿用 SSE/轮询、取消、重试和租约恢复。旧简报生成接口在兼容期转调首次生成接口。

## 15. 组件复用

直接复用生成配置、任务状态、Markdown 编辑预览、mdnice 排版、版本列表、审核动作、执行记录和错误提示。

抽象通用组件：ContentDetailWorkspace、GenerationHeader、GenerationOptions、GenerationStatus、ContentTabs、PublishingPreview、WorkflowNodeTimeline、GenerationWorkflowContract 和 ContentGenerationContextAdapter。

热点独立保留资料池、来源快照、冲突证据、简报摘要、热点 Skill、节点执行器和自动审核规则。

## 16. 实施顺序

### 阶段 A：后端契约与兼容迁移

- 建立文章草稿壳、双内容、生成配置和完整版本快照。
- 迁移旧文章并保留旧 API 兼容。
- 定义统一阶段、热点节点、Job scope 和幂等规则。

### 阶段 B：热点工作流闭环

- 实现原稿、公众号、配图、三类自动审核、最终检查和条件版本写入。
- 实现单步任务、失败检查点、状态失效和重启恢复。
- 在工作流与 Skill 管理中注册完整热点节点。

### 阶段 C：共享页面与热点适配

- 从课程详情页抽取通用工作区组件。
- 课程模式回接通用组件并确保原功能不变。
- 热点模式接入同一组件和热点资料适配器。

### 阶段 D：人工审核、排版与执行记录

- 接入热点人工审核、mdnice 排版和发布快照。
- 补齐生成记录、双层轨迹、失败原因、取消和重试。

### 阶段 E：验收

- 后端迁移、API、工作流、审核、重试和并发测试。
- TypeScript 检查、前端构建和课程模式回归。
- 新旧热点全链路桌面和移动页面验收。

## 17. 验收标准

- 热点与课程使用同一个详情页框架，视觉和交互一致。
- 页面具备原稿、公众号文章、配套图片、公众号排版、审核和版本。
- 字数和插图配置真实进入 Job、工作流和最终检查。
- 工作流管理页可查看 14 个热点节点、连接、Skill 和真实状态。
- 原稿、公众号文章和图片具有独立产物与自动审核报告。
- 单步重试从正确热点节点开始，不触发课程节点或重新采集。
- 自动审核、版本保存、人工审核、排版的先后关系正确。
- 旧热点文章不丢失，历史无原稿时不伪造 AI 原稿。
- 公众号正文不包含事实评分、证据状态、写作建议、提示词或内部审核内容。
- 配图数量、上下文、位置、文件和引用均通过检查。
- 服务重启和重复点击不会产生重复正式版本。

## 18. 最终决策

当前无待确认阻断项。后续开发以本文件为唯一设计依据，按“后端契约 -> 热点工作流 -> 共享页面 -> 人工审核与排版 -> 验收”的顺序实施。
