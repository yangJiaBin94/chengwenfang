## 1. 目标与非目标

### 1.1 目标

- **单实例多用户**：同一部署内多个账号协作/分用，**不是**多租户 SaaS。
- **RBAC**：User + Role + Permission。
- **数据隔离**：用户级（`owner_user_id`），普通用户只看见自己的资源；`ADMIN` 可绕过。
- **登录**：账号密码；会话由 **Sa-Token + Redis** 承担；**无总开关，登录与 owner 隔离始终生效**。

### 1.2 非目标（明确不做）

| 项 | 说明 |
|----|------|
| 多租户 / `tenant_id` / 组织 Membership | 无租户概念 |
| Spring Security / Authorization Server / OAuth / OIDC | 本期不需要 |
| 独立 API 网关 | 单体足够；入口 = LB/反向代理 → `chengwenfang-app` |
| 本期改业务表 / 写拦截器实现 | 本文只定设计；实现分期见 §8 |

## 2. 框架选型

### 2.1 结论：Sa-Token，不用 Spring Security

| 能力 | 落点 |
|------|------|
| 登录 / Token / 登出 / 踢人 | Sa-Token（Boot 3 starter + Redis） |
| 角色 / 权限校验 | Sa-Token（`@SaCheckRole` / `@SaCheckPermission` 或等价路由规则） |
| 密码存储 | 自管哈希（Hutool BCrypt 或等价），与会话框架分离 |
| 按用户过滤数据 | 业务 Facade / 条件查询，**不是**鉴权框架的职责 |

**为何不用 Spring Security**：本形态下用不上 OAuth2 Resource Server、复杂 Filter 链与标准授权服务器；硬上会与 Sa-Token 职责重叠、配置膨胀。若未来要上企业 SSO/OIDC，再单独评估 Authorization Server，不在此预埋。

**为何 Sa-Token 合适**：与「会话登录 + RBAC + 已有 Redis」一一对应；注解鉴权贴合 `adapter.web` 薄壳；无租户 claim、无网关验签硬需求。

### 2.2 与现有密钥的边界

- `CHENGWENFANG_SECRET_KEY` / `SecretCipher`：**仅** at-rest 加密 AI/渠道等密钥列。
- **禁止**把该密钥兼作登录会话密钥或 Token 签名材料；Sa-Token / Redis 会话使用独立配置。

## 3. 总体架构

```text
WebClient
  │ POST /api/auth/login
  ▼
AuthController → AuthFacade → users/roles/permissions
                    │
                    └→ Sa-Token login → Redis session
  │
  │ Authorization: Bearer <token>
  ▼
SaInterceptor → adapter.web.* → *Facade → owner_user_id 条件
```

- 横切：现有 `TraceIdFilter` 保留；Sa-Token 拦截器与之协调顺序。
- 失败响应：继续走 `ApiResult` + `BusinessException`；新增错误码见 §6.3。

## 4. 身份模型（RBAC）

### 4.1 实体

| 概念 | 说明 |
|------|------|
| **User** | 账号（username/email 唯一）、密码哈希、启用/禁用 |
| **Role** | 闭集枚举优先，放 `facade.enums`（如 `ADMIN` / `EDITOR` / `VIEWER`） |
| **Permission** | 开集常量，放 `facade.constant`（如 `settings:write`、`work:write`）；由角色绑定 |

**无** Tenant、Membership、`switch-tenant`。

### 4.2 数据范围 vs 接口权限

| 层 | 含义 | 机制 |
|----|------|------|
| 权限 | 能否调用某类 API | Sa-Token 角色/权限 |
| 数据范围 | 能看见哪些行 | `owner_user_id`；`ADMIN` 可绕过 |

普通用户：只读写 `owner_user_id = 自己` 的资源。  
`ADMIN`：可管理用户与角色；列表/详情默认可跨用户（运维视角）。

## 5. 会话与 API

### 5.1 会话

- Sa-Token 签发 token，会话落 **Redis**（便于多实例）。
- 前端：`Authorization: Bearer <token>`（或与 Sa-Token 配置一致的 Token 头名）。
- 登出 / 踢下线走 Sa-Token API。

### 5.2 一期 HTTP 面（最小）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/login` | 账号密码登录 |
| POST | `/api/auth/logout` | 登出 |
| POST | `/api/auth/register` | 可配置关闭；亦可改为仅 ADMIN 创建用户 |
| POST | `/api/auth/change-password` | 本人改密；成功后踢掉该用户全部会话 |
| GET | `/api/me` | 当前用户与角色/权限摘要 |
| * | 用户/角色管理 | 仅 `ADMIN`（尚未实现） |

放行（白名单）：登录/注册、`/api/auth/status`、健康与就绪探针；Swagger 仅非 `prod`。  
其余 `/api/**` 必须登录。

### 5.3 错误码（实现时写入错误码常量）

| code | 场景 |
|------|------|
| `UNAUTHORIZED` | 未登录或 token 无效 |
| `FORBIDDEN` | 已登录但角色/权限不足 |
| `OWNER_MISMATCH` | 访问他人资源且非 ADMIN |

响应信封不变：`ApiResult(code, msg, data)`，`msg` 中文。

## 6. COLA 模块落点

### 6.1 新建 `chengwenfang-identity`（平台层）

```text
chengwenfang-identity
  facade/          AuthFacade, UserFacade
  facade/dto|enums|constant
  application/     登录、用户角色权限、CurrentUser 查询
  domain/          User / Role / Permission 规则
  infrastructure/  mapper、assembler
```

依赖方向：`app → identity → common|infra`。  
同层平台模块互不反向依赖业务域。

### 6.2 `chengwenfang-app`

- `adapter.web.identity`：登录、me、用户管理 Controller（无业务规则）。
- Sa-Token 配置与拦截器注册（与 `TraceIdFilter` 顺序协调）。

### 6.3 边界硬规则

- 业务域 **只依赖** `identity.facade` 获取当前用户 / 做权限语义判断。
- **禁止**业务 Facade / domain 直接散落 `StpUtil`；Sa-Token 调用收敛在 app 适配层或 identity 内部，对外暴露如 `CurrentUserView`。
- 实现时同步更新：父 POM、`ModuleArchitectureTest`、[`代码结构与注释规范.md`](./代码结构与注释规范.md)、COLA skill 模块表、[`类命名词典.md`](./类命名词典.md)。

## 7. 数据隔离（用户级）

**没有 `tenant_id`。** 隔离列统一为 **`owner_user_id`**（BIGINT → `users.id`）。

现网约 90 张表：**约 30 张用户资源根表加列**；其余全局共享或经父表归属。

### 7.1 A. 必须加 `owner_user_id`

写入填当前用户；查询默认 `owner_user_id = 当前用户`；`ADMIN` 可绕过。

| 域 | 表 |
|----|-----|
| 平台 | `stored_files`、`jobs`、`ai_provider_configs`、`model_calls`、`notifications` |
| 提示词/工作流 | `skills`（prompt pack）、`workflow_definitions`、`workflow_drafts`、`workflow_runs`、`workflow_alerts` |
| 内容 | `themes`、`works`、`media_assets` |
| 知识库 | `knowledge_documents`、`knowledge_chat_sessions`、`knowledge_memories`、`knowledge_index_state`、`knowledge_retrieval_traces`、`knowledge_graph_edge_overrides`、`knowledge_answer_feedback` |
| 信源 | `source_channels`、`source_items`、`source_fetch_runs`、`source_query_site_blocks`、`video_transcripts` |
| 课程 | `course_curricula`、`course_series` |
| 热点 | `hotnews_radar_batches`、`hotnews_topics`、`hotnews_briefs`、`hotnews_works`、`hotnews_research_runs`、`hotnews_article_skeletons` |
| 质量 | `audit_runs`、`human_reviews`、`repair_runs` |
| 发布 | `layout_themes`、`channel_accounts`、`publications` |

说明：`channel_accounts` 历史上可为「公众号单例」；多用户后改为**每用户**自己的渠道配置。

### 7.2 B. 不加 owner（全局共享）

全站一份数据；登录用户可读；**写入一般仅 ADMIN**。

- `content_modes`、`channels`、`output_formats`、`channel_formats`
- `source_channel_catalog`
- `workflow_templates`（平台种子模板）
- `skill_default_bindings`（实例默认绑定）

**工作流口径（避免误解）：**

| 对象 | 用户隔离 | A 改了是否影响 B |
|------|----------|------------------|
| `workflow_definitions` / `drafts` / `runs` | 是（A 类） | 否 |
| `workflow_templates` | 否（平台模板） | 会 → **禁止普通用户改模板** |
| 从模板复制出的定义 | 属创建者 | 各改各的 |

「不加 owner」≠「所有工作流不隔离」，仅字典/平台模板共享。

### 7.3 C. 不加 owner（经父表隔离）

访问须先校验父资源归属；禁止对子表主键裸查跨用户数据。

| 父（有 owner） | 子表示例 |
|----------------|----------|
| `jobs` | `job_events` |
| `themes` | `theme_profiles`、`theme_profile_items`、`theme_scoring_rubrics`、`theme_scoring_rubric_dimensions` |
| `works` | `work_generation_settings`、`work_outputs`、`work_output_versions`、`media_generations`、`output_layouts`、`render_snapshots` |
| `skills` / 工作流定义 | `workflow_versions`、`workflow_version_skill_bindings`、`workflow_node_runs`、`workflow_run_executed_nodes`、`workflow_artifacts` |
| `knowledge_documents` | `knowledge_chunks` |
| `knowledge_chat_sessions` | `knowledge_chat_messages` |
| `source_channels` | `source_channel_values` |
| `source_fetch_runs` | `source_fetch_channel_runs` |
| `source_query_site_blocks` | `source_query_site_block_samples` |
| `course_curricula` / `course_series` | `course_curriculum_draft_*`、`course_lessons`、`course_lesson_outcomes`、`course_output_sources` |
| `hotnews_*` 根 | `hotnews_topic_score_*`、`hotnews_topic_sources`、各类 `*_items` / `*_sources`、`hotnews_research_items` 等 |
| `audit_runs` / `repair_runs` | `audit_issues`、`audit_issue_refs`、`repair_run_codes`、`repair_candidates`、`repair_candidate_issues` |
| `layout_themes` / `publications` | `layout_theme_versions`、`publication_metric_snapshots` |

例外：若 API **按子表主键直查且不经父表**，该子表补 `owner_user_id`，或强制先加载父资源再鉴权。

### 7.4 库外存储

- **Qdrant**：point payload 带 `owner_user_id`，或检索前先按文档归属过滤。
- **Neo4j**（若开启）：节点属性带 `owner_user_id`。

### 7.5 运行时强制

- Facade 列表/详情必须带 owner 条件（或统一 OwnerScope 助手）；**禁止只靠前端藏按钮**。
- Job / SSE：入队快照 `owner_user_id`；worker 按快照用户恢复上下文再执行。
- 先鉴权（Sa-Token），再数据范围（owner）。

## 9. 配置（约定）

```yaml
chengwenfang:
  auth:
    register-enabled: false   # 自助注册；登录与隔离始终开启
```

- Sa-Token 拦截 + owner 过滤始终生效；仅 `register-enabled` 可关。

## 10. 风险与约束

- **漏加 owner 的根表**会导致串数据；新表若属用户资源，必须进 A 类。
- **子表裸查 API** 是常见漏洞点；新增按子表 ID 访问的接口必须过父归属或补列。
- **全局模板被误开放写权限**会影响全站；`workflow_templates` / 字典写接口必须锁 `ADMIN`。
- 向量库若只按 chunk id 检索而不带用户维度，会绕过 MySQL 隔离——U3 必须对齐。
