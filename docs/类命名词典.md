# Workbench 类命名词典

> **版本**：1.1（v2 模块名词补齐）  
> **适用范围**：`D:\work\personal\writer\product\workbench` 后端 Java 代码  
> **优先级**：本词典 > 通用 Java 规范；与 `.cursor/skills/workbench-cola-architecture/`、`docs/代码结构与注释规范.md` 冲突时，以本仓 COLA + 本词典为准。  
> **目的**：给人和 AI 同一套「后缀词典」，避免 `View` / `Dto` / `Ref` / `Service` / `Util` / `FacadeImpl` 混用。

---

## 0. 总原则（MUST）

1. 类名 **UpperCamelCase**，英文，体现**业务含义**；禁止拼音、中英混拼、无语境名（`Data`、`Temp`、`Manager`、`Processor`、`Helper1`）。
2. **一个文件一个顶级 public 类型**，文件名 = 类型名。
3. **跨模块只暴露 Facade 面**：他域只能依赖 `*.facade`（含 `dto` / `enums` / `constant` / `spi`），不得依赖 `*FacadeImpl`、他域 `domain.entity`、`infrastructure.mapper`。
4. 新增类型前先查本表：能归入已有后缀就不要发明新后缀。
5. 标识符英文；注释中文（与现有仓规一致）。

## 0.1 v2 业务名词（语义，非后缀）

| 名词 | 含义 | 典型落点 |
|------|------|----------|
| Work / 作品 | 统一内容身份（原课程 ID / 热点文章 ID） | `works`、`WorkEntity`、`*WorkStore` |
| WorkOutput / 产出 | 渠道×格式的正文容器（原 document） | `work_outputs`、`WorkOutputEntity` |

| Quality / 质量 | 审核、修复、修复候选 | `workbench-quality`、`RepairCandidateStore` |
| Publishing / 发布 | 排版、渲染、渠道推送 | `workbench-publishing` |
| Notification / 通知 | 站内通知与跳转目标解析 | `workbench-notification` |

## 1. 允许后缀表（按层）

| 后缀 / 形态 | 放置位置 | 含义 | 示例 | 备注 |
|-------------|----------|------|------|------|
| `*Facade` | `*.facade` 根包 | 跨模块门面**接口** | `ContentFacade`、`JobFacade`、`HotNewsFacade` | 根包只放接口 |
| `WorkContentStore` | `content.facade` | 正文读写契约（无 `Facade` 后缀的例外） | `WorkContentStore` / `WorkContentStoreImpl` | 实现仍在 `application` |
| `*FacadeImpl` | `*.application` | 门面默认实现 | `ContentFacadeImpl` | 实现类名 = 接口名 + `Impl`；多接口实现见 §3 |
| `*Service` | `*.application` | **模块内**应用协作类（不对外） | `HumanReviewService`、`TopicQueryService` | 禁止被他模块直接依赖 |
| `*Pipeline` | 域 `application.generation` 等 | 长任务步骤编排 | `HotNewsArticlePipeline`、`ArticleRepairPipeline` | 由 app Worker 薄壳调用 |
| `*Orchestrator` | 域 `application` | 跨多步用例编排 | `ThemeCurriculumOrchestrator` | 与 Pipeline 二选一，偏「业务编排」 |
| `*Store` | `*.application` | 模块内聚合读写/持久化协作 | `HotNewsWorkStore`、`RepairCandidateStore` | 不对外；跨域正文用 `WorkContentStore` |
| `*Assembler` | `*.infrastructure.assembler` 或 `application` | Entity⇄View / 领域组装 | `ArticleViewAssembler`、`ThemeProfileAssembler` | 一个聚合一个 Assembler |
| `*Definition` | `facade.spi` 接口 + 域实现 | 模式扩展点 | `ModeDefinition`、`CourseModeDefinition` | |
| `*Publisher` | `facade.spi` + publishing 实现 | 渠道发布扩展点 | `ChannelPublisher`、`WechatMpChannelPublisher` | |
| `*Renderer` | `facade.spi` + publishing 实现 | 产出格式渲染 | `OutputRenderer`、`ArticleHtmlRenderer` | |
| `*Resolver` | `facade.spi` 或 `application` | 按键解析策略 | `NotificationTargetResolver`、`VideoParseOwnerStrategyResolver` | SPI 放 `facade.spi` |
| `*Handler` | `app.adapter.worker` 或 `application.node` | Job 入口 / 工作流节点 | `HotNewsFetchHandler`、`*NodeHandler` | Worker 不写厚业务 |
| `*Controller` | `app.adapter.web.<域>` | HTTP 入口 | `ArticleController`、`HotNewsTopicController` | 资源名一般用**单数** |
| `*Entity` | `*.domain.entity` | 表映射实体 | `WorkEntity`、`WorkOutputEntity` | 不对外返回 |
| `*Mapper` | `*.infrastructure.mapper` | MyBatis-Plus Mapper | `WorkMapper` | |
| `*ViewMapper` | `*.application` | Entity/领域 → View（MapStruct） | `StoredFileViewMapper`、`NotificationViewMapper` | 与 Assembler 并存时优先语义更清者 |
| `*Request` | `*.facade.dto.request` | 创建或完整提交入参 | `ArticleUpdateRequest` | |
| `*Patch` | `*.facade.dto.request` | **局部更新**入参 | `ProviderConfigPatch` | 少用；与 Request 分工见 §2 |
| `*View` | `*.facade.dto.view` | 对外只读视图 / API data | `ArticleView`、`HotNewsArticleView` | **默认首选** |
| `*Result` | `*.facade.dto.view` 或 `dto.job` | 一次操作的结果快照 | `FetchResult`、`TextCompleteResult`、`OkJobOutput` | 偏「动作结果」；Job 出参放 `dto.job` |
| `*JobInput` / 任务入参类 | `*.facade.dto.job` | 任务创建载荷类型 | 各 `*JobInput` / 场景入参类 | JSON 键名与历史 Map 一致 |
| `*Engine` / `*Runtime` | `*.domain.engine` / `runtime` | 纯规则 / 运行时 | `HotArticleReviewEngine` | 无 Spring Web 依赖 |
| `*Provider` | `facade` 接口 + `infrastructure` 实现 | 可替换技术适配 | `StorageProvider` / `LocalStorageProvider` | 实现可用技术名 |
| `*Config` / `*Properties` / `*AutoConfiguration` | `config` / `infra` | 配置 | `OpenApiConfig` | |
| `*Exception` | `common` | 异常 | `BusinessException` | |
| `*Prompts` | `*.application.prompt` | 提示词常量与拼装 | `CoursePrompts`、`HotNewsPrompts` | 整段文本不改字 |
| 枚举（无强制后缀） | `*.facade.enums` | 闭集词表 | `JobStatus`、`NotificationLevel` | 名用业务名词；需 `getValue`/`from` |
| 常量类（无强制后缀） | `*.facade.constant` | 开集常量 | `JobTypes`、`ModelCallScenes`、`HotNewsWorkflowKeys` | |

## 2. 入参 / 出参细分规则

### 2.1 Request vs Patch（MUST）

| 场景 | 用 | 不要用 |
|------|----|--------|
| 创建、整单提交、语义完整的更新 | `*Request` | |
| 明确的局部字段修补（JSON Merge/Patch 语义） | `*Patch` | 不要再叫 `*UpdateRequest` 却只改 1～2 字段而不说明 |
| 查询条件 | `*Query`（若引入）或复用 `PageQuery` + 显式参数 | 不要用 `*Request` 表示纯查询（已有大量历史除外，新增遵守） |

### 2.2 View vs Result vs 其它（MUST）

| 形态 | 何时用 |
|------|--------|
| `*View` | 资源/聚合的对外投影（列表项、详情）——**默认** |
| `*Result` | 「跑完一次动作」的返回：连通性测试、生成、拉取、校验引擎输出等 |
| `*Entry` | **仅**批量导入/迁移条目等「行项目」，且不单独作为主 API 资源 |
| 禁止新增 | `*Dto`、`*VO`、`*BO`、`*DO` 作为对外类型（持久化用 `*Entity`，对外用 `*View`） |

### 2.3 历史异类后缀（冻结，仅改不增）

下列名字允许暂时保留，但**禁止新代码再发明同类后缀**；改造见《重命名清单》：

- `*Ref`（如 `ChannelRef`）→ 应改为 `*View` 或嵌在父 View 内的静态字段对象并改名
- `*Hit` / `*Item`（如 `SearchHit`、`FetchedItem`）→ 对外 API 倾向 `*View`；若仅爬虫内部可留，但应迁出 `facade.dto.view` 或改名
- `*Stats` / `*Data` / `*Binding` / `*Position` / `*Event` → 能改 `*View`/`*Result` 则改；事件确需 `*Event` 时放清包路径并写进 CR 说明

## 3. Facade / 实现命名（MUST）

| 规则 | 说明 |
|------|------|
| 一对一 | `FooFacade` ↔ `FooFacadeImpl` |
| 一对多接口、一个实现 | 实现类名不得叫不存在的 `XxxFacadeImpl`；应叫 `DefaultFooBarFacade` 或按技术名 `OpenAiAiFacade`，并在类 Javadoc 写明实现了哪些接口 |
| 技术名实现 | 允许：`DuckDuckGoHtmlSearch implements SearchFacade`（接口业务名 + 实现技术名） |
| 禁止 | `IContentFacade`；`ContentFacadeService`；他模块依赖 `*FacadeImpl` |

---

## 4. Service / Util / Support / Pipeline / Store（MUST）

| 名字 | 用途 | 禁止 |
|------|------|------|
| `*Service` | 模块内有状态或需注入的应用协作（可 `@Service`） | 当跨模块 API；名字用 `And` 拼接两件无关事 |
| `*Pipeline` | 按任务类型的长流程步骤编排（可注入多 Facade） | 放在 `workbench-app` 写厚业务；跨模式互调 |
| `*Store` | 模块内围绕一张/一组表的读写协作 | 替代跨模块 Facade；跨域正文用 `WorkContentStore` |
| `*Util` | **无状态**静态工具，`private` 构造；纯函数 | 放 Spring Bean；塞领域生命周期；当「常量类」 |
| 常量 / ID 工厂 | 优先 `Ids`、`TraceIds`、`ErrorCodes`、`IdsUtil`（历史名可保留） | 不要新造与 Hutool 重复的 blank 工具 |
| `*Support` | 可选，表示「同模块辅助协作」；与 Util 二选一，新代码优先语义更清的名字 | 与 Util 成对重复 |

`StorageService`（infra）这类基础设施协作可保留 `*Service`，但不要放到业务 `facade`。

## 5. Controller 命名（SHOULD）

- 默认：**单数**资源 + `Controller`：`ArticleController`、`JobController`。
- 已存在的 `JobsController` 视为历史；新增不要再复数，除非规范修订明确「集合入口用复数」。
- 按域分包：`adapter.web.content|course|hotnews|quality|publishing|sourcing|workflow|notification|...`，禁止重新出现巨型 `DomainController`。
- HTTP 视图若仅该 Controller 使用，可暂放同包；**优先**放到对应域 `facade.dto.view`，避免 `adapter.web` 下 View 扩散。

---

## 6. 禁止清单（AVOID）

- 新的 `*Dto` / `*VO` / `*BO` / `*DO`（对外或 application 对外映射）
- `I*` 接口前缀
- Facade 入参/出参使用 Java `record`（本仓硬性规定；内部 private 辅助可讨论，门面 DTO 禁止）
- 公开 API 使用裸 `Map<String, Object>`（开放载荷用 `FlexiblePayload`）
- `Manager`、`Processor`、`CommonUtil`、`BaseService` 等空洞名
- 把业务类塞进 `util` 包
- 新模块名沿用已废弃的 `hot-news` / `publishing-audit`（用 `mode-hotnews` / `publishing` / `quality` / `sourcing` / `notification`）

## 7. 给 AI 的一句话约束（可复制）

```text
新增或重命名 Java 类型时必须遵守 docs/类命名词典.md：
跨模块只用 *Facade（及 WorkContentStore / facade.spi）；实现为 *FacadeImpl（或技术名）；
对外模型用 *View/*Result/*Request/*Patch；任务载荷放 facade.dto.job；禁止新 *Dto；
模块内协作用 *Service/*Pipeline/*Store；组装用 *Assembler；无状态用 *Util；
SPI 用 *Definition/*Publisher/*Renderer/*Resolver。先搜仓库同类命名再写。
```
