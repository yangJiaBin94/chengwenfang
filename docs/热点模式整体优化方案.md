# 热点模式整体优化方案

## 1. 文档目的

本文用于优化热点雷达到公众号成品文章的完整链路，目标是让用户能够清楚知道：

1. 当前热点是什么，为什么值得关注。
2. 资料来自哪里，哪些是来源事实，哪些是 AI 分析，哪些是作者推演。
3. 当前任务正在执行哪一步，是否需要等待，失败后从哪里恢复。
4. 生成结果是否已经是可编辑、可审核、可排版的公众号文章成品。
5. 哪些内容可以直接使用，哪些内容只能作为观点或素材参考。

本方案不新增日报模块，不改变课程体系模式的既有流程，也不引入微信公众号官方发布能力。

## 2. 当前目标流程

```text
来源管理
  -> 热点采集
  -> 热点聚合与评分
  -> 选择热点
  -> 生成或更新事实简报
  -> 确认选题
  -> 深挖资料池
  -> 确认简报
  -> 生成热点原稿
  -> 审校原稿
  -> 生成公众号成品文章
  -> 审校公众号文章
  -> 生成封面与正文配图
  -> 图片与引用检查
  -> 最终检查
  -> 保存版本
  -> 本地排版、人工审核、复制或下载
```

### 2.1 用户可见的简化阶段

技术节点可以保留，但用户界面建议只突出五个业务阶段：

| 阶段 | 用户要做什么 | 系统负责什么 |
|---|---|---|
| 发现热点 | 查看来源、概要、评分和影响面 | 采集、去重、翻译、聚合、评分 |
| 研究选题 | 确认选题并查看资料池 | 抓取来源、AI 分析、整理冲突证据 |
| 生成文章 | 选择字数和配图数量后启动 | 生成原稿、公众号文章、图片并逐步校验 |
| 审核排版 | 修改正文、运行检查、选择主题 | 保存内容、执行检查、生成排版预览 |
| 输出使用 | 复制或下载成品 | 生成稳定的 HTML 和 Markdown 输出 |

## 3. 现状判断

### 3.1 已有能力

- 热点来源、采集、聚合、评分和解释已经有独立数据链路。
- 选题简报、确认选题、资料池和冲突证据已经接入文章生成。
- 热点文章已经有原稿、公众号文章、配图、排版、审核和版本页面。
- 热点文章工作流已经有节点记录、Skill 快照、任务事件、失败和重试能力。
- 热点作者风格 Skill 已绑定到定位、提纲、原稿和公众号转换相关文本节点。
- 已使用 PostgreSQL 保存运行数据，任务表和工作流记录是事实来源。
- 图片结果已经支持 AI 生成图片的尺寸校验和文章引用校验。

### 3.2 当前主要问题

1. 执行轨迹可能同时使用任务 `currentStep` 和节点 `status`，导致出现“内容已完成但右侧仍显示执行中”。
2. 页面刷新后状态能够恢复，但实时更新与完整节点列表之间仍存在短暂不一致风险。
3. “AI 生成图片”和“资料池来源图片、网页卡片、远程图片”在用户界面上没有始终明确区分。
4. 资料来源信息有时只出现在正文或图片中，素材池和文章预览未必能直接看到完整来源地址。
5. 采集、资料研究、文章生成都是长任务，用户需要更明确的当前阶段、已完成阶段、等待原因和预计剩余工作。
6. 失败重试需要继续强化“从失败节点恢复”，避免用户误以为会从头生成并重复消耗模型调用。
7. 热点作者风格允许推演，但事实边界、推演边界和来源事实在生成前后的展示规则需要固定。
8. 资料池中来源质量、抓取失败、403、超时和内容过短需要统一呈现，而不是只显示一个笼统失败状态。

## 4. 核心设计原则

### 4.1 一个状态事实源

任务状态、工作流状态和节点状态必须遵循以下优先级：

1. 节点终态 `succeeded`、`failed`、`cancelled` 优先于旧的当前节点标记。
2. `currentStep` 只用于标识当前正在执行的节点，不能覆盖已结束节点。
3. 任务进入 `succeeded` 或 `failed` 后，前端必须重新获取任务、节点和事件的完整快照。
4. 任务终态后禁止继续显示转圈动画。
5. 前端实时事件只做增量更新，定时或终态时必须做完整同步。

### 4.2 事实、观点、推演分层

系统内部保留三类信息：

| 类型 | 例子 | 文章中的表现 |
|---|---|---|
| 来源事实 | 官方公告、项目仓库、论文摘要、公开产品信息 | 可以直接陈述，并保留来源链接 |
| AI 分析 | 对多个来源的归纳、结构化总结 | 作为分析结果，不伪装成原始来源 |
| 作者推演 | 对行业、职业、商业和趋势的个人判断 | 使用“可能”“我倾向于”“值得观察”等限定表达 |

文章成品不展示内部评分、可信度标签、待核实清单和审核术语，但禁止把推演写成已经发生的事实。

### 4.3 成品优先

“生成公众号文章”输出必须是可直接编辑的文章正文，不得输出：

- 写作建议
- 提示词
- 文章结构草案
- 内部节点名称
- 事实可信度说明
- “这里可以插图”的提示文字
- 未处理的图片占位符

技术日志可以保留在执行记录页面，但不能混入文章正文。

## 5. 功能优化方案

### 5.1 热点雷达页

每条热点统一展示：

- 中文短标题
- 一句话速览
- 这条资讯具体是什么
- 为什么现在值得关注
- 来源数量和来源类型
- 热度、时效性、影响力、证据覆盖等评分
- 评分依据展开入口
- 主要影响行业和可能影响对象
- 来源链接和采集时间

评分依据使用明确的可展开按钮，显示“展开评分依据”或“收起评分依据”，同时使用箭头图标和 `aria-expanded`，避免用户误以为只是普通文本。

### 5.2 来源与采集

来源状态统一为：

- 可用
- 采集中
- 部分成功
- 访问受限
- 内容过短
- 超时
- 已停用

来源失败必须保存：HTTP 状态码、最终 URL、失败时间、失败阶段和是否影响本批次结果。单个来源失败不能让整个批次永久停留在执行中。

建议增加来源健康摘要：最近成功时间、最近失败时间、连续失败次数、最近一次失败原因。连续达到阈值后提示用户停用来源，但不自动删除历史资料。

### 5.3 资料池

每条资料显示：

- 资料标题
- 简短概要
- 来源类型，例如官方、GitHub、论文、媒体、博客、AI 分析
- 来源名称和完整链接
- 采集时间
- 关联热点
- AI 分析摘要
- 影响领域
- 是否包含冲突证据

来源图片和网页卡片必须显示“来源图片”标记；图片模型生成的图片显示“AI 生成图”标记。两者不能混用。

资料池顶部增加一句固定业务说明：

> 这里是当前选题的资料素材池，供简报、原稿和公众号文章生成使用。

不增加人工事实确认状态，AI 只输出分析分数和说明；但来源事实、AI 分析和作者推演仍在内部数据结构中分开保存。

### 5.4 生成前设置

生成按钮旁固定展示：

- 文章目标字数
- 正文插图数量，不含封面
- 是否生成封面
- 当前确认简报版本
- 当前资料数量和来源数量
- 预计执行阶段

启动前确认弹窗只做一次，明确：

- 将生成热点原稿和公众号成品文章
- 将生成封面和正文配图
- 预计会调用文本 AI 和图片 AI
- 失败时可以从失败节点重试

### 5.5 执行轨迹

页面采用课程体系模式的结构：左侧生成记录，中间执行流程，右侧或下方展示节点详情。

每个步骤必须有四种互斥显示：

- 待执行：灰色圆点，无转圈
- 执行中：橙色状态、转圈、当前动作说明
- 已完成：绿色对勾、完成摘要、结束时间
- 失败：红色警告、失败原因、重试入口

完成节点不得显示转圈；当前节点不得使用“该阶段已完成”作为执行中描述。执行中描述必须是动作句，例如“正在分段生成热点原稿”。

### 5.6 失败和重试

重试策略：

1. 默认从失败节点重新执行。
2. 前置成功节点按输入哈希复用产物。
3. 只有输入、Skill、配置或来源发生变化时，才允许从更早节点重新生成。
4. 重试前显示“将从第 X 步开始，前 X-1 步复用已有结果”。
5. 重试后创建新的执行批次，旧批次只读保留。
6. 失败任务终态必须关闭所有仍显示运行中的节点。

### 5.7 文章工作区

工作区继续复用课程体系模式的通用结构：

- 热点原稿
- 公众号文章
- 配套图片
- 公众号排版
- 审核
- 版本

热点模式保留自身内容：热点概要、资料池、来源、影响分析和热点作者风格。删除重复入口和“候选稿”一类不再使用的功能，避免用户在多个入口之间判断哪个才是正式结果。

公众号文章页的首屏应优先显示：标题、摘要、正文、封面和文章状态。Skill、来源和技术日志进入执行记录或折叠详情，不挤占正文阅读区域。

### 5.8 图片资产

图片资产统一保存以下字段：

```text
type: ai_generated | source_image | webpage_card | uploaded
sourceUrl: 来源地址，可为空
sourceName: 来源名称，可为空
model: 生成模型，可为空
prompt: 生成提示词，可为空
width / height
articleId
position
```

校验规则：

- 封面固定 `2400 x 1024`。
- 正文图固定 `2048 x 1152`。
- 图片数量必须符合设置。
- 每张图片在正文中最多引用一次。
- 图片之间不得连续出现，除非文章明确要求图片组。
- 公众号正文不得残留提示词、插图标题或占位说明。
- 来源图片必须保留来源 URL，AI 生成图必须保留生成模型和节点记录。

## 6. 技术改造优先级

### P0：先修复一致性和可用性

1. 统一任务终态和节点终态渲染逻辑。
2. 任务终态强制刷新完整节点、事件和文章状态。
3. 修复节点状态与阶段描述不一致问题。
4. 失败重试明确恢复起点，并防止旧协程覆盖新终态。
5. 所有长任务补充超时、失败收口和异常兜底。

### P1：提升用户理解成本

1. 统一五阶段业务导航和当前阶段提示。
2. 资料池显示来源类型、来源 URL 和采集失败原因。
3. 图片资产显示 AI 生成图或来源图片标记。
4. 生成前确认弹窗展示输入快照和预计步骤。
5. 执行记录显示每个节点的输入摘要、输出摘要和耗时。

### P2：提升生成质量

1. 为热点作者风格增加可配置的语气强度和观点密度，但默认保持当前推荐值。
2. 对标题、开头、影响分析和结尾增加成品质量检查。
3. 增加观点与素材的关联摘要，确保每个主要推论有可追溯的观察依据。
4. 对来源图片和网页卡片增加正文上下文匹配检查。

### P3：运行效率和可观测性

1. 统计每个节点平均耗时、失败率和重试率。
2. 统计各来源成功率、403 比例和内容有效率。
3. 对文本、图片和采集调用分别设置并发与速率限制。
4. 只有监控证明有必要时，再引入更复杂的异步数据库会话或外部队列。

## 8. 成功标准

- 用户不需要猜测下一步该点什么。
- 任何运行中的任务都能看到当前动作和等待原因。
- 任何已完成步骤都不会显示执行中动画。
- 失败后用户知道失败在哪一步、为什么失败、重试从哪里开始。
- 文章正文是成品，不包含内部流程和提示词。
- 每张图片都能解释“它是怎么来的”。
- 热点模式与课程模式共用结构，但不把课程专属教学内容带入热点文章。
