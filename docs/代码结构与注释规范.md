# 代码结构与注释规范

## 1. 项目分层（Chengwenfang × COLA，v2）

后端为 Java 21 Maven 多模块单体（Spring Boot 3），前端为 React/Vite。  
架构约定见 `.cursor/skills/chengwenfang-cola-architecture/`（映射 [COLA](https://github.com/alibaba/COLA)）；模块依赖方向以 `docs/refactor-v2/03-代码架构设计.md` 与 `ModuleArchitectureTest` 为准。

```text
workbench/
├── chengwenfang-app/                 # 适配层：adapter.web / adapter.worker / bootstrap / config
├── chengwenfang-mode-course/         # 模式层：课程流水线与节点
├── chengwenfang-mode-hotnews/        # 模式层：雷达 / 选题 / 热点文章与节点
├── chengwenfang-content/             # 内容核心：主题 / 作品 / 产出 / WorkContentStore / ModeDefinition
├── chengwenfang-quality/             # 内容核心：审核 / 修复 / 修复候选
├── chengwenfang-publishing/          # 内容核心：排版 / 渲染 / 渠道发布（ChannelPublisher）
├── chengwenfang-sourcing/            # 内容核心：信源频道 / 抓取 / 视频转写表
├── chengwenfang-notification/        # 平台：站内通知 + NotificationTargetResolver
├── chengwenfang-skill-workflow/      # 平台：Skill / 工作流 / WorkflowNodeHandler 注册表
├── chengwenfang-file|job|ai|crawler/ # 平台：文件 / 任务 / AI / 抓取搜索
├── chengwenfang-common/              # 平台：ApiResult、异常、IdsUtil 等纯工具
├── chengwenfang-infra/               # 平台：配置属性、线程池、存储
├── src/                           # React 前端（app / shared / features）
│   ├── app/                       # 布局壳、routes、useRouter、legacyRedirects
│   ├── shared/                    # api / format / hooks / theme / components
│   └── features/                  # dashboard / course / hotnews / workflow / …
├── docs/ contracts/ scripts/
└── pom.xml
```

依赖只能**自上而下**：`app → 模式层 → 内容核心层 → 平台层`。  
同层仅允许：`quality → content`、`publishing → content`；模式层互不依赖。由 `ModuleArchitectureTest` 强制。

模块内包（统一）：

```text
com.chengwenfang.<module>
  facade/          # *Facade、dto/request|view、enums、constant、spi
  application/     # 用例、*FacadeImpl、pipeline、node、prompt
  domain/          # entity / model / rule（及 engine|runtime）
  infrastructure/  # mapper、assembler、client
```

`chengwenfang-app`：

```text
com.chengwenfang.app
  bootstrap/ config/
  adapter.web.<域>/     # Controller（content/course/hotnews/quality/…）
  adapter.worker/       # JobHandler 薄壳
```

依赖：`app.adapter → *.facade.. → …`；禁止 Controller→Mapper、app→`*FacadeImpl`、他域穿透 `application/domain/infrastructure`（已知暂免见 refactor-v2/06 决策 D-21～D-32）。  
**禁止**把数据库 Entity、Mapper、MyBatis-Plus `ServiceImpl` 按表合并成对外 CRUD 包；表操作由 FacadeImpl + Mapper 完成。

## 2. 公共依赖约定

- **Lombok**：父 POM 全模块引入。实体用 `@Data`/`@Builder`；注入用 `@RequiredArgsConstructor`；关键路径（Controller/Facade/Orchestrator/Job Handler/Worker）用 `@Slf4j`，入口与终态打 info/warn/error。
- **Hutool**：判空优先 `ObjectUtil`/`StrUtil`；JSON 序列化/反序列化优先 `JSONUtil`；类型转换优先 `Convert`；集合优先 `CollUtil`。**禁止**自写 `blank`/`nullToEmpty`/`firstNonBlank` 等与 Hutool 重复的私有工具方法。
- **MapStruct**：实体 ↔ 视图放 `*ViewMapper`；聚合组装优先 `infrastructure.assembler.*Assembler`。
- **Swagger（springdoc）**：Controller 类用 `@Tag`，方法用 `@Operation`；字段可用 `@Schema`。开发访问 `/swagger-ui.html`；`prod` 关闭。
- **统一响应**：HTTP 成功/失败体均为 `ApiResult`（`code`/`msg`/`data`）；成功 `code=ok`。Controller 方法显式返回 `ApiResult<T>`（文件下载/`SseEmitter` 除外），便于 Swagger 展示完整信封。
- **分页**：查询用 `PageQuery`，列表用 `PageResult<T>`。
- **禁止 Java `record`**：Facade 入参/出参、DTO、视图用普通类（Lombok），单独建类文件。
- **禁止公开 API 使用裸 `Map`**：Controller/Facade 入参出参用 View/Request；开放结构载荷用 `FlexiblePayload`。
- **类命名**：见 `docs/类命名词典.md`（`*View`/`*Result`/`*Request`/`*Patch`；禁止新 `*Dto`；一对多 Facade 实现用 `Default*`；SPI 用 `*Definition`/`*Publisher`/`*Renderer`/`*Resolver`）。
- **时间类型**：持久化实体与业务 DTO 统一使用 `LocalDateTime`（仅日期用 `LocalDate`）；禁止在项目代码中使用 `Instant` 作为字段或 API 类型。
- **Controller 分包**：按业务放在 `adapter.web.{content,course,hotnews,quality,publishing,sourcing,workflow,job,notification,settings,system,file}`，禁止再堆 DomainController。
- **Facade 分包**：根包仅 `*Facade`（及少量跨切面接口如 `WorkContentStore`）；请求在 `facade.dto.request`，视图在 `facade.dto.view`，任务载荷在 `facade.dto.job`，闭集 enum 在 `facade.enums`，开集常量在 `facade.constant`，扩展点在 `facade.spi`。
- **业务字面量**：闭集用 `enum`（`getValue`/`from`/`matches`），开集用常量类；放在 `facade.enums` / `facade.constant`。**禁止**业务逻辑里 `"hot_news_xxx".equals(typeKey)` 散落魔法字符串；同场景常量集中进同一常量类（如 `HotNewsWorkflowKeys`、`ModelCallScenes`、`JobTypes`）。
- **上游 JSON**：POJO + `JSONUtil.toJsonStr`/`toBean`，禁止 `createObj().set(...)`。
- **固定结构禁止裸 Map**：节点状态、行数据、请求体等固定结构用普通类；仅开放图定义/真正动态 JSON 可暂用 `Map`/`FlexiblePayload`，边界尽快收窄。
- **可扩展设计**：可预见分支用策略/多态（`ModeDefinition`、`WorkflowNodeHandler`、`ChannelPublisher`、`OutputRenderer`、`NotificationTargetResolver`、`JobHandler`），避免巨型 switch 写死流水线；遵守 DDD/COLA 分层。
- **日志与异常**：message 中文；code 英文；MDC `traceId`（请求头 `X-Trace-Id`）写入日志。
- **持久化**：Entity 在 `domain.entity`，Mapper 在 `infrastructure.mapper`；不引入按表 `IService`/`ServiceImpl` 当领域服务。正文经 `WorkContentStore`（UTF-8 原样读写，只追加版本）。

## 3. 注释规则

- 注释使用**中文**；标识符英文；命名须有含义，禁止无语境的单字母变量（如 `q`/`c`/`e`/`i`/`m`/`tmp`/`obj`/`data`/`v`/`p`/`a`）；查询包装器用 `query`，实体用业务名，异常用 `ignored`/`exception`，lambda 参数按元素类型命名。
- 每个 `public` 类型须有类级 JavaDoc；**类属性 / 实体字段**须有字段注释。
- Facade / FacadeImpl / Controller / Orchestrator / Job Handler 的 **public 与 private** 方法均须方法级 JavaDoc，且包含：
  - `@param`：每个入参是什么、起什么作用
  - `@return`：返回什么（void 可省略）
  - `@throws`：对外有意义的业务异常（可选但推荐）
- 方法体内：关键步骤、重要变量声明、非显而易见的方法调用须有中文行注释说明目的。
- 注释只写业务意图，不写「对齐原版 Python」等对照来源。
- Entity 对重要外键、状态、JSON 字段补充字段注释。
- Mapper / ViewMapper / Assembler 一行类注释即可。
- 参考样板：`chengwenfang-ai/.../DefaultAiFacade.java`。

## 4. 关键不变量

- 文章修改经版本或 workflow，不静默覆盖正文；正文存文件，业务表只存 `*_file_id`。
- AI 修复先存原文版本再写修复版并复检。
- 业务表只存 `file_id`；路径在 `stored_files`。
- API Key / 完整提示词 / 完整模型输出不进日志或公开响应。
- 长任务经 jobs + 租约 + SSE（SSE 事件体可不包 ApiResult）；任务入出参用 `facade.dto.job` 类型，键名与历史 JSON 一致。
- 正式生成失败必须报错，禁止用夹具正文或占位图顶替。
- 作品身份：`works.id`；产出身份：`work_outputs.id`（原 documentId）。
