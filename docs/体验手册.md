# 体验手册

从设置到第一篇成品的点击顺序。安装用仓库根目录的一键脚本，见 [README](../README.md)。本文不重复讲 JDK 和镜像加速。

开始前打开 **http://127.0.0.1:5173**，用种子管理员登录：**用户名 `admin`，密码 `admin123`**。登录后请立刻在右上角头像菜单改密。不要把 5173 或 8001 暴露到公网；安全边界见 [SECURITY.md](../SECURITY.md)。

**设置 → 系统就绪** 和 `GET /api/system/builtin-ready` 是同一份清单。默认档（课程 + 知识库）要看到「通过」，需要：内置提示词包和三条主工作流已导入、Qdrant 真连上、生成 Key、嵌入 Key、图像 Key 都已配置。热点 CLI 显示「未加装」、Graph / Agent 显示「默认关闭」，不会单独把默认档判失败。内存向量库不算 Qdrant 已就绪。嵌入 Key 没配时，知识库不会装成已经成功。

密钥只在设置里填。种子不会写入真实 Key。管理员可在 **设置 → 用户管理** 创建账号。

## 1. 课程成文

适合默认档。不需要 SearXNG、Lightpanda 或三条 Python CLI。

1. **设置 → AI 配置**。多模态供应商负责写作、审核和看图；图片供应商负责配图；嵌入供应商负责知识库。先填多模态和图像，点各自的「测试连接」，再保存。
2. **课程体系**。用已经导入的演示主题，或新建一个主题并确认课表。
3. 打开 **课程路线**，选一课。
4. **生成原稿**。这里用多模态 Key。
5. **公众号文**。同样用多模态 Key。
6. **配图**。这里用图像 Key。
7. **排版**。复制 Markdown，或按页面上的排版主题打开。
8. **审核与修复**。这是质量模块：规范检查、AI 修复、人工确认。它不走知识库检索。

缺 Key 时停在哪一步：

| 没配什么 | 会停在哪 |
|----------|----------|
| 多模态（生成）Key | 原稿、公众号文、审核修复都不会产出正文 |
| 图像 Key | 原稿可以有；配图和封面停住 |
| 嵌入 Key | 课程这条路径仍可写；知识库索引和问答不会成功，系统就绪也不通过 |

## 2. 热点雷达到成文

这是加装档。默认的「课程 + 知识库」不包含下面这些容器和 CLI。没装时，雷达本地搜索、JS 页正文、视频解析或佐证截图会缺，页面应显示未加装或明确的失败原因，而不是把课程安装说成坏了。

满血加装（`start-java.ps1 -AllDeps` 或 `./scripts/start.sh --all-deps`）会：

- `docker compose --profile all`：在 MySQL、Redis、Qdrant 之外拉起 SearXNG、Lightpanda，以及 Neo4j 容器
- 安装三条 CLI：`article-extract`（正文）、`video-transcript`（视频）、`page-screenshot`（截图，含 Chromium 与 PyMuPDF）

应用侧 Graph 开关保持关闭。Neo4j 容器起来不等于图检索打开。

点击顺序：

1. **热点资讯** 里打开主题（可用演示主题）。若提示先确认主要意图，回到设置把多模态 Key 配好，再在主题页确认。
2. **雷达采集**。本地聚合搜索依赖 SearXNG（默认 `http://127.0.0.1:8080`）。没有 SearXNG 时，这一路搜索没有结果，其它来源（例如 RSS）仍可按主题配置使用。
3. 在选题榜上进入 **选题与资料池**。网页正文抽取用 `article-extract`；JS 页打不开时才轮到 Lightpanda。视频解析用 `video-transcript` 和本机 ffmpeg。
4. **分步成文**。生成仍要多模态 Key；配图要图像 Key。
5. 成文里的 **佐证截图** 用 `page-screenshot`。网页必须对上定位文本才插图；对不上就跳过，不用首屏冒充那句话。PDF 只取首页。没装这条 CLI 时，文字出处还在，只是没有截图。

视觉理解（看截图、看关键帧）用的是设置里的多模态 Key，不是单独的第四个供应商。

## 3. 知识库

默认档就有。`docker compose up` 会起 Qdrant（6333 / 6334）。应用容器连的是服务名 `qdrant`，不是容器里的 `127.0.0.1`。

1. **设置** 里填写嵌入 Key 并测试连接。没配时，入库后的索引和「问一问」都不会成功。
2. 侧栏 **知识库**：上传文件、登记网页，或从作品同步。
3. 等索引完成。系统就绪里 Qdrant 必须是「通过」。若显示内存库或未连通，先看 Qdrant 是否在跑，不要继续问答。
4. 带着引用问一问。证据不够时会拒答，而不是编一段看起来像答案的话。
5. 问答在 **会话** 里。对一条回答可以提交 **反馈**。想让它记住跨会话的事实，在对话里写 **请记住：…**，之后在记忆列表里能看到。

写作规范审核在 **质量模块**（课程或热点文的审核与修复）。那条链路不检索知识库，也不因为知识库拒答而代替审核。

**Graph** 和 **Agent** 默认关闭。系统就绪里它们标成「默认关闭」。要图检索时，再打开 `chengwenfang.knowledge.graph.enabled` 并准备 Neo4j。不要把这两项当成开箱能力。

## 4. 工作流与提示词包

产品里这一层叫 **提示词包**，不叫 Skill。

1. 侧栏 **工作流**。可以看到三条主工作流图：课程生成、热点成文、雷达采集。
2. 点进一张图，看节点，以及节点上绑定的提示词包。
3. 同一页可以看近期执行。
4. **设置 → 提示词包** 里列出、编辑你自己的提示词包。已发布工作流上绑定的提示词包才会参与生成。

仓库 `.cursor/skills` 只给改代码的助手用，设置页里不会出现它。
