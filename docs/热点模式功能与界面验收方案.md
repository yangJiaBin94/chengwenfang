# 热点模式功能与界面验收方案

## 1. 验收目的

本文用于对热点模式进行一次端到端验收，覆盖真实服务、真实 AI 调用、页面操作、工作流状态、数据一致性、图片资产、排版和响应式布局。

验收结论分为：

- 通过：满足验收条件，未发现阻断问题。
- 有条件通过：主流程可用，但存在不影响核心使用的体验或环境问题。
- 不通过：存在数据丢失、任务无法收口、状态误导、文章不可用或严重布局问题。

## 2. 验收环境

### 2.1 必备环境

| 项目 | 要求 |
|---|---|
| Node.js | 24 或兼容项目版本 |
| Python | 使用 `backend/.venv` 的 Python 3.12 |
| PostgreSQL | 运行在 `5432`，迁移到最新版本 |
| API | `8001` 端口可访问 |
| 前端 | `5173` 端口可访问 |
| Worker | 至少一个可领取任务的 Worker；推荐单进程并发配置为 2 |
| AI 文本配置 | 已配置有效模型、Base URL 和 Key |
| AI 图片配置 | 已配置有效模型、Base URL 和 Key；如额度不足，图片项单独标记环境阻断 |
| 浏览器 | 能打开本地前端并支持开发者控制台；不要求 Chromium 参与资料采集 |

### 2.2 启动前检查

```powershell
Get-NetTCPConnection -LocalPort 5432,8001,5173 -State Listen
Invoke-RestMethod http://127.0.0.1:5173/api/health
```

若服务未启动，在项目根目录执行：

```powershell
npm run dev
```

确认 API、前端和 Worker 日志均已启动后再开始真实操作。

## 3. 测试数据准备

1. 准备至少一个已启用的公开热点来源。
2. 准备一个能够稳定访问的官方来源或 GitHub 来源。
3. 准备一个已确认的热点选题。
4. 选题至少拥有一条简报来源快照。
5. 若测试资料池，需要准备一个允许采集的公开 URL。
6. 若测试图片，需要确认图片服务额度、模型和尺寸接口可用。
7. 记录测试开始时间、数据库迁移版本和 AI 模型配置名称，不记录 API Key。

## 7. 执行轨迹专门验收

### 7.1 状态互斥规则

对每个步骤记录截图和接口数据，确认：

```text
pending  -> 只有待执行样式，无动画
running  -> 只有当前步骤有动画和执行中描述
succeeded -> 绿色完成，无动画
failed   -> 红色失败，无动画
```

禁止出现：

- 右侧显示执行中，节点摘要显示已完成。
- 第 N+1 步成功，但第 N 步仍执行中。
- 任务失败后所有步骤继续转圈。
- 刷新前后同一节点状态不同。
- 重试后历史批次节点被覆盖。

### 7.2 断线与刷新

1. 任务运行时刷新页面。
2. 关闭页面后重新进入执行记录。
3. 在任务完成瞬间刷新页面。
4. 在任务失败瞬间刷新页面。

预期是任务状态和节点状态最终一致，页面不依赖浏览器内存中的临时状态才能显示正确结果。

## 8. 响应式和视觉验收

至少检查以下视口：

- 桌面：`1440 x 900`
- 窄桌面：`1280 x 800`
- 移动端：`390 x 844`

每个页面检查：

1. 左侧生成记录宽度稳定，不挤压主内容。
2. 步骤文本不被截断或错误换行；必要时允许内容区域自然换行。
3. 当前节点动画位置、标题和状态在同一行或明确的响应式结构中。
4. 弹窗固定在当前视窗中央，不在页面底部出现。
5. 按钮文字、图标和加载状态不重叠。
6. 图片保持比例，不被顶部或容器裁切。
7. 文章正文、资料来源和技术详情不会互相覆盖。
8. 页面不存在横向滚动条，除非是明确设计的横向记录列表。
9. 浏览器控制台无未处理异常。

## 9. 自动化验收命令

```powershell
npx tsc --noEmit
npm run build
backend\.venv\Scripts\python.exe -m pytest backend\tests -q --basetemp=.pytest-tmp-hot-acceptance
backend\.venv\Scripts\python.exe -m ruff check backend\app backend\tests
git diff --check
```

专项测试失败时需要区分：

- 业务断言失败：必须修复或记录为不通过。
- 外部 AI 超时、403、额度不足：记录环境阻断，不得改写为业务通过。
- 测试框架临时目录权限问题：更换项目内 `--basetemp` 后重跑。

## 10. 真实 AI 验收边界

### 文本 AI

至少真实执行一次：

- 热点简报分析
- 资料池 AI 总结
- 热点原稿生成
- 公众号文章转换
- 文章审校

记录模型名称、任务 ID、节点、耗时、输出字符数和最终状态，不记录 Key 和完整私密请求内容。

### 图片 AI

至少真实执行一次封面或正文图，记录：

- 模型名称
- 请求尺寸
- 实际 PNG 尺寸
- 文件 Hash
- 文章引用位置
- 任务节点状态

如果上游返回超时、余额不足或 5xx，应判定图片真实验收为环境阻断，并继续用确定性夹具验证数量、尺寸、引用和布局规则，不能把夹具结果当成真实图片质量通过。

## 12. 通过门槛

### 必须全部满足

- 热点采集、选题、简报、资料池和文章生成主链路可完成或明确收口。
- 任务失败不会永久显示执行中。
- 节点状态与执行描述一致。
- 刷新和重新进入页面后状态一致。
- 文章正文是成品，不含内部提示词和流程文本。
- 图片数量、尺寸、引用和来源类型可验证。
- 公众号排版、审核、版本和快照不丢失内容。
- 课程模式未被热点模式改坏。

### 可以记录但不阻断

- 上游单个来源暂时 403，但失败隔离正确。
- 图片上游额度不足，但错误能正确收口且确定性校验通过。
- 非关键页面存在轻微间距差异。
- 构建存在 chunk size 警告但不影响运行。
