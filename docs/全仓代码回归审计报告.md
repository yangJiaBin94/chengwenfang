## 0. 已锁定决策

| 项 | 决策 |
|----|------|
| 本轮交付 | 只出报告（方案 1A） |
| 文章体系 | **统一模型 A**：远期 `content_document` + `content_document_version`；发布/微信/配图/审核挂 `document_id` |

| Skill 正文存放 | **代码不嵌、不保留**提示词正文；出厂副本**只**留在 `scripts/bootstrap`（如 `builtin-catalog.json`）；导入后**一律以库为准**；Java `Builtin*SkillSeeder` 内嵌 `SEEDS`/`systemInstructions` 为后续整改债 |

### 术语

| 词 | 含义 |
|----|------|
| **live** | 数据库 `skills`（等）表中的现行行；导入完成后的**唯一运行真相** |
| **出厂种子** | 仅初始化脚本中的完整 skill 正文，供首次/重装导入，**不是**运行时数据源 |
| **代码侧** | 只保留名称常量、scene/绑定键等结构元数据；禁止 Java 内嵌长文提示词 |

## 2. 业务架构与可替换方案

### 2.1 产品定位与评估原则

个人/小团队**本机**内容工作台（无登录、单用户、本地数据）。运维复杂度优先于「工业级平台完整度」。

**已用栈（摘要）：** Java 21 / Spring Boot 3 模块化单体 + React/Vite；MySQL + Redis（Redisson）；LangChain4j；Flyway；可选 SearXNG / Lightpanda；主机 Python CLI（Trafilatura / Whisper / yt-dlp 等）。

### 2.2 能力地图与决策

| 能力 | 现状 | 决策 | 市场替代评估 |
|------|------|------|----------------|
| 课程/主题生成 | Graph + Skill 节点 + `GenerationPipelines` | **保留并演进** | Temporal/Camunda：**过重**，丢 Skill 绑定 |
| 热点雷达/调研/成文 | 自研域 + 图；Facade 过大 | **保留域；拆结构** | Scrapy 不贴交互雷达；付费抓取已排除 |
| Skill + GraphRuntime | 域专用 DAG | **保留（产品 IP）** | BPMN/Conductor 税高 |
| 发布/微信/审核引擎 | 规则引擎 + AI 项 | **保留** | 无 OSS 可替编辑规则 |
| AI 调用 | LangChain4j + 自研图 HTTP | **保留 LC4j** | Spring AI 迁移收益低 |
| Job 租约 + SSE | MySQL `SKIP LOCKED` + 进程内 Worker | **保留** | Redis/Kafka/XXL-JOB 无必要 |
| 文件 | 本地 + `stored_files` | **保留** | MinIO 仅多机再加 |
| 爬虫/视频 | 策略注册 + 本地 CLI | **演进运维（纯本地）** | 不做 Firecrawl 等收费 |
| 前端 | 功能可用；`App.tsx` 过大 | **拆分演进** | 勿换 Next |
| 可观测性 | Actuator 弱用 | **后续补 Micrometer** | 勿上全套 APM |
| RAG / 鉴权 | 无 | **暂不加** | 超出当前产品范围 |

### 2.3 不应替换的领域 IP

1. Builtin/bootstrap 提示词与节点→skill 绑定语义（正文存放规则见第 0 节）
2. 三类工作流节点目录与 feature binding
3. 确定性审核 / 知识规则 / 热点复审与修复候选语义
4. 热点产品模型（频道、聚类评分、调研池、成文骨架）
5. 课程教学流水线（草稿→公众号→公式检查→版本提交）
6. 发布主题 HTML / 微信粘贴适配
7. Job 事件 + SSE 契约
8. 成文写作规则与字数门禁等

### 2.4 架构优化 backlog（Top 10，后续）

1. 拆 `HotNewsFacadeImpl`（雷达 / 调研 / 成文 / 信源）
2. 拆 `App.tsx`（课程 / 设置 / 首页）
3. **本地** Python/CLI 安装摩擦：一键脚本 + 「仅课程 / 满血热点」配置档与失败态说明
4. Micrometer：pending/running、租约回收、按 job type 耗时
5. 按 Job 类型并发槽位（防 Whisper/出图饿死短任务）
6. 拆 `WorkflowFacadeImpl`（持久化/设计器 vs `GraphRuntime`）
7. AI 统一重试/超时；基于 `model_calls` 的费用/用量汇总
8. 爬虫 skip-hosts / 探测 UX（不引入付费抓取）
9. 文档去 Python/LangGraph 误导，指向 Java COLA + cutover
10. FE「系统就绪」面板聚合 BuiltinConfig / CLI 健康检查

### 2.5 明确排除的替换

Temporal、Camunda、Flowable、Conductor、Kafka、XXL-JOB、PowerJob、Spring AI 整迁、Scrapy 重写爬虫、Firecrawl/Browserless 等**付费**路径、为个人台引入完整 RAG/向量库。

## 3. 表结构回归与目标重构

> 忽略数据迁移成本。来源：Flyway V1–V28、48 个 `@TableName` Entity、设计文档与 Python 原版对照。

### 3.1 总评

Schema 是 **Python 迭代模型的 parity 平移**，不是干净的 COLA 域重设计。Job/workflow/content/hot-news 主链路可用，但存在双文章体系、神 JSON、软引用、path/`file_id` 双存、孤儿表。

### 3.2 主要结构债

| 问题 | 证据 | 目标动作（已定或建议） |
|------|------|------------------------|
| 双文章体系 | `articles` ∥ `hot_news_articles` + 各自 versions | **已定 A**：统一 `content_document` + version |
| 主题神 JSON | `content_themes.briefing_json` / `curriculum_draft_json` / `defaults_json` | 拆 `content_theme_wizard_states` |
| 1:1 可合并 | `course_generation_preferences` | 并入 `courses` |
| 路径未割完 | `articles` / `generated_images` / `workflow_artifacts` 仍有 `file_path` | 只留 `stored_files` + `file_id` |
| 孤儿表 | `workspaces`（Java/TS 零业务引用） | **删除** |
| 悬挂字段 | `course_series.topic_id`（无 learning_topics） | 删除或重建 taxonomy |
| 雷达批次 | 仅 `radar_batch_id` 字符串 | 新表 `radar_batches` + FK |
| 视频解析重复 | `source_items` 与 `topic_research_items` 列堆叠 | 共享 `video_parse_runs` / media |
| 审核缺口 | 课程缺 audit 持久化；热点 `result_json` 大包 | 统一 `article_audit_runs` / `issues` / `decisions`（挂 document） |
| 双「主题」名 | `content_themes` vs `publishing_themes` | 后者概念改名 layout_themes |
| skill_versions | 读路径走 live，表半死 | **已定 B**：删/废表 |
| theme_id | 热点侧几乎无 FK | FK → `content_themes.id` |

### 3.3 已采纳：文章统一模型（方案 A）

**目标表：**

```text
content_document
  id, domain(course|hot_news), owner_id, kind, title, status,
  current_version_no, ...

content_document_version
  document_id, version_no, body_md, content_hash, source, reason, workflow_run_id, ...
```

- 课程：`owner_id = course_id`，`kind = course_draft | wechat_article`
- 热点：`owner_id = brief_id`（或 topic_id），`kind = draft | wechat`
- 下游一律 `document_id`：`publishing_snapshots`、`wechat_mp_*`、`generated_images`、审核三表

**未采纳的对照案（双轨清理 B）**仅作历史记录：保留两套文章表，只补 domain 判别与字段对齐——改动更小但永久双轨。

**建议分期（后续实施）：**

1. 先完成与合并无关的止血：`file_id`、FK、删 `workspaces`
2. 引入 `content_document` 并行写入 / 读切换
3. 下游改挂 `document_id`
4. 删旧双表

### 3.4 已采纳：Skill 无版本 + 正文只在 bootstrap（方案 B 加强）

**目标状态：**

1. 删除或停用 `skill_versions`
2. 运行时只读 live `skills`（与当前 `SkillFacade` 注释一致）
3. 出厂完整正文**仅** `scripts/bootstrap`（如 `builtin-catalog.json`）
4. Java 侧移除内嵌 `systemInstructions`；保留 `*SkillNames` / scene 常量即可
5. 导入完成后以库为准；回滚靠重灌 bootstrap 或（可选）workflow 发布时把提示词打进 `workflow_versions` 快照

**未采纳：** 库内 skill 多版本权威（方案 A）。

### 3.5 其它表结构切片（后续 backlog）

1. 删 `workspaces`；业务表去掉 `file_path` / `legacy_public_path`；`theme_id` 加 FK
2. 合并 `course_generation_preferences` → `courses`；拆 theme wizard；加 `radar_batches`
3. 视频解析抽共享表；瘦 `topic_clusters`（skeleton 外置；分数细节与物化分二选一为长期真相）
4. 统一审核表挂 `document_id`；`publishing_themes` → layout_themes（可延后）
5. 密钥列（`api_key` / `app_secret`）改为加密或 vault 引用（可延后）
6. ID 宽度统一（CHAR(36) vs VARCHAR(64)）

### 3.6 建议保留的稳定核

- `jobs` / `job_events`
- `workflow_definitions` / `versions` / `drafts` / bindings / `runs` / `node_runs`
- `stored_files`

- 信源 → topic → brief 脊柱（表名可保留，外键与媒体列清洗）
- `model_calls`、`notifications`

### 3.7 Python 原版对照信号（节选）

| Python 有、Java 弱/无 | 含义 |
|------------------------|------|

| 热点 rewrite/audit/human/decision 等 | 热点 QA 轨迹更薄 |

| Java 演进超出 Python | 含义 |

| 视频解析列、`source_query_site_blocks`、雷达 batch 字段 | 新产品面，需抽表/建批次实体 |

## 5. 本轮结论

1. **规范债**集中在 app / hot-news / skill-workflow；平台模块健康。
2. **架构**对单机工作台已 right-sized；优先拆 God 类与本地 CLI 运维，不换重型中间件；**不做收费抓取**。
